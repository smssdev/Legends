# Legends: خطة السبرنتات حتى النسخة الأولى (v1.0)

> المرجع للقرارات: `docs/PLAN.md`. هذا الملف يحوّلها إلى 27 سبرنتاً مرتبة، من إنشاء المشروع حتى إطلاق النسخة الأولى على الويب وAndroid وiOS.

## كيف تُقرأ هذه الخطة

- **السبرنت = أسبوع واحد** تقريباً، وينتهي عند تحقق "تعريف الانتهاء" وليس عند انتهاء الوقت.
- **ثلاثة مسارات تعمل بالتوازي** في كل سبرنت:
  - **B** الباك اند (Laravel API)
  - **W** الويب (Vue 3 SPA)
  - **M** الموبايل (Flutter لـ Android وiOS)
- قاعدة الترتيب: **B يسبق W وM** في نفس الميزة. عقد الـ API (المسارات وشكل الـ JSON) يُكتب أولاً في `docs/api/` ثم يبني عليه W وM بالتوازي.
- كل مهمة = فرع + PR. اسم الفرع: `sNN/b-وصف` أو `sNN/w-وصف` أو `sNN/m-وصف`.
- **بداية جلسة AI لأي مهمة:** "اقرأ CLAUDE.md وdocs/SPRINTS.md، ونفّذ مهمة [الرمز] من السبرنت [الرقم]، والتزم بتعريف الانتهاء."
- عند بداية كل سبرنت يُنشأ `docs/sprints/sprint-NN.md` لحالة المهام، ويُحدَّث عند نهايته.

**الهدف:** ثلاثة مشاريع تعمل وتتكلم مع بعض، وCI يحرس الجودة.

| الرمز | المهمة |
|---|---|

| B2 | معيار الـ API: البادئة `/api/v1`، شكل موحد للأخطاء برسائل عربية، `GET /api/v1/health`، حدث بث تجريبي |

| W1 | Vue 3 SPA في `web/`: Vite، Vue Router، Pinia، Tailwind، RTL، خطوط عربية، ألوان `brand/`، Echo، عميل API بالتوكن |
| M1 | Flutter في `mobile/`: Riverpod، go_router، dio، flutter_secure_storage، RTL عربي، ثيم من `brand/`، بيئتان (dev وprod)، أيقونة التطبيق وشاشة البداية من `brand/current/` |
| M2 | عميل Reverb (بروتوكول Pusher) في Flutter، واستقبال الحدث التجريبي |
| X1 | GitHub Actions: اختبارات PHP + Pint، بناء الويب، `flutter analyze` + `flutter test`. حماية `main` |

**تعريف الانتهاء:**
