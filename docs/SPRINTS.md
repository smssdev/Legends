# Legends: خطة السبرنتات حتى النسخة الأولى (v1.0)

> المرجع للقرارات: `docs/PLAN.md` (الأرقام بين قوسين مثل [2.7] تشير لأقسامه). هذا الملف يحوّلها إلى 33 سبرنتاً مرتبة، من إنشاء المشروع حتى إطلاق v1.0 على الويب وAndroid.
>
> **مجاني بالكامل:** كل ما في v1 يعتمد على خدمات مجانية. السيرفر جهاز منزلي برابط Tailscale Funnel [2.19].
>
> **واجهة واحدة:** تطبيق Vue يعمل في المتصفح، ويُغلَّف بـ Capacitor كتطبيق Android. فكل شاشة تُكتب مرة واحدة. **iOS بعد v1** (يحتاج حساب Apple مدفوعاً)، وCapacitor يدعمه بنفس الكود.

## كيف نعمل

- **مسار واحد:** سليمان وحمزة يعملان على نفس السبرنت حتى يتحقق تعريف انتهائه، ثم ينتقلان معاً للسبرنت التالي.
- **السبرنت حوالي أسبوع**، وينتهي عند تحقق "تعريف الانتهاء" وليس عند انتهاء الوقت.
- رموز المهام: **B** الباك اند، **W** الواجهة (Vue، تعمل في الويب وداخل التطبيق)، **A** طبقة Android الأصلية (Capacitor)، **D** التصميم والمحتوى والمواصفات، **X** مشتركة.
- **التصميم أولاً:** كل سبرنت فيه شاشات يبدأ بمهمة **D0**: تصميم شاشاته للويب والموبايل [2.23]، ويوافق عليها صاحب المشروع قبل مهام W.
- **العقد أولاً:** أي مهمة B تضيف أو تغيّر مساراً تحدّث `docs/api/openapi.yaml` في نفس الـ PR، والواجهة تولّد العميل منه.
- **قبل أن تبدأ Issue:** أسندها لنفسك على GitHub حتى لا يعمل الاثنان على نفس المهمة.
- فرع لكل Issue باسم `sNN/وصف-قصير`، وPR صغير يراجعه الآخر، وrebase على `main` قبل الدمج. التعارض يُحل وقته.
- **بداية جلسة AI لأي مهمة:** "اقرأ CLAUDE.md ثم مهمة [الرمز] من السبرنت [الرقم] في docs/SPRINTS.md وأقسام PLAN المذكورة فيه، ونفّذها والتزم بتعريف الانتهاء."
- عند بداية كل سبرنت يُنشأ `docs/sprints/sprint-NN.md` لحالة المهام، ويُحدَّث عند نهايته.

| B4 | أمر `composer dev`: serve + queue + reverb + schedule + vite |
| W1 | Vue 3 SPA في `web/`: Vite، Router، Pinia، Tailwind بألوان نظام التصميم، RTL، Echo، عميل TypeScript مولّد من OpenAPI، وهيكل التنقل للويب والموبايل |

| X1 | GitHub Actions: اختبارات PHP وPint، بناء الويب، بناء APK موقّع، فحص OpenAPI وأن العميل المولّد محدّث. بحساب الدقائق المجانية (2,000 شهرياً): اختبار ARM على `main` فقط، والمحاكاة الطويلة على الجهاز المنزلي |
