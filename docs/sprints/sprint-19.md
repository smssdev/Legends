## تعريف الانتهاء

- [x] الإعادة تطابق المباراة الحية حرفاً، حتى مع أوامر وصلت أثناء حساب دقيقة. اختبار `MatchOrdersTest`: أوامر تبديل وتكتيك وطريقة، وأمر متأخر يدخل الدقيقة التالية، ثم الإعادة تعطي نفس النتيجة ونفس الأحداث حدثاً بحدث. ومع قتل المشغّل وفقد الكاش تعاد الأوامر في دقائقها نفسها
- [x] 50 مباراة حية متزامنة بلا تأخير في الدقائق ولا أخطاء `SQLITE_BUSY`. **على حاوية التطوير** (4 أنوية Xeon 2.1GHz)، وتُعاد على الجهاز المنزلي بنفس الأمر:

| | بلا عمال أوامر* | 4 عمال أوامر |
|---|---|---|
| مباريات حية في وقت واحد | 50 | 50 |
| دقائق لُعبت | 4706 | 4702 |
| دقيقة صُنعت متأخرة (ms): p50 / p95 / الأقصى | 0 / 0 / 0 | 0 / 0 / 0 |
| خطوة المشغّل (ms): p50 / p95 / الأقصى | 16 / 65 / 1093 | 15 / 64 / 974 |
| أوامر المدربين | 3935 | 8018 |
| `SQLITE_BUSY` (المشغّل / الأوامر) | 0 / 0 | 0 / 0 |

\* التشغيل الأول كان بعاملين بسبب خطأ في عدّهم صُحح بعده. والخطوة الأطول (حوالي ثانية) هي بداية الخمسين معاً، وتُصنع الدقائق قبل موعدها بـ 1.2 ثانية فلا تتأخر.

## كيف يعمل

- **الأمر:** يُحفظ بالدقيقة التالية التي لم تُصنع (`target_tick`)، والمشغّل يأخذه عند صنعها ويسجّل `applied_tick`. والأمر الذي يصل أثناء صنع دقيقة يدخل التي بعدها، والإعادة تقرأ `applied_tick` فتطابق.
- **من يدير الفريق:** المدرب ما دامت شاشته على المباراة، والمساعد إذا غاب، والحاسوب للبوت. والمباراة الفورية بلا مشاهد: المساعد للمدرب والحاسوب للبوت. وأوامر الاثنين تُحفظ كأوامر المدرب.
- **الطريقة أثناء المباراة:** الأمر يحمل خانات الطريقة من `FormationBook` (أو طريقة المدرب الخاصة)، والمحرك يتحقق منها ويوزّع اللاعبين عليها. **المحرك 4:** أمر الطريقة يقبل الخانات، وتغيير الطريقة يمسح الخانات القديمة.
- **مشغّل واحد:** `matches:run` يحجز دوراً في الكاش يجدده كل خطوة، والثاني ينتظر ويأخذ الدور خلال 10 ثوانٍ إذا توقف الأول. ومشكلة مباراة واحدة تُسجَّل ولا توقف الباقي.
- **الإعادة:** نفس الإصدار تُعاد دقيقة بدقيقة بإطاراتها، والأقدم من أحداثه.
