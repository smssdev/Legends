## 0. الخلاصة في صفحة واحدة

| المحور | القرار |

| النوع | لعبة مدير كرة قدم أونلاين بالدور (مثل OSM)، منافسة في دوريات خاصة |
| التقنية | Laravel 12 API (Sanctum) + Vue 3 SPA، وتطبيق Android بـ Capacitor يغلّف نفس تطبيق Vue. SQLite (وضع WAL)، Reverb، Queues، Scheduler |

## 1. التقنيات

| الطبقة | الاختيار | السبب |
|---|---|---|
| الباك اند | Laravel 12 | الحسابات، الجدولة، المحاكاة، الـ API |
| الـ API | REST بالبادئة `/api/v1` + Sanctum (توكن Bearer) | API واحد يخدم الويب والموبايل، فلا يتكرر منطق |
| الويب | Vue 3 SPA + Vue Router + Pinia + Echo | الواجهة الوحيدة: تعمل في المتصفح وداخل تطبيق Android |
| الموبايل | **Capacitor** يغلّف تطبيق Vue في تطبيق Android، مع إضافات أصلية: الإشعارات (FCM)، Google Sign-In، الروابط العميقة، التخزين الآمن، استئناف التطبيق | الشاشات تُكتب مرة واحدة، فيقل عمل الواجهات للنصف تقريباً. Flutter خيار بعد v1 |
| التصميم | Tailwind CSS، اتجاه RTL، خط عربي (Cairo أو Tajawal) | |
| قاعدة البيانات | SQLite بوضع WAL، **ثلاثة ملفات منفصلة:** البيانات، والكاش، والطابور. المعاملات بوضع `IMMEDIATE` | فصل الكاش والطابور يمنع تزاحم الكتابة. والانتقال لـ MySQL أو Redis لاحقاً بدون تغيير الكود |
| اللحظي | Laravel Reverb + Echo | بث أحداث المباراة والإشعارات داخل اللعبة |
| المهام الخلفية | Queues (driver: database) + Scheduler كل دقيقة | المباريات، التدريب، الملعب، الغياب |
| الكاش | Cache (ملف SQLite مستقل) | حالة المباراة الجارية |
| عقد الـ API | OpenAPI في `docs/api/openapi.yaml` يُكتب قبل الشاشات، ومنه يُولَّد عميل TypeScript | لا ينجرف الباك اند عن الواجهة |
| إصدار التطبيق | `/api/v1/health` يعيد أدنى إصدار مدعوم، والتطبيق الأقدم يعرض شاشة "حدّث التطبيق" | تطبيقات الأصدقاء لا تتحدث وحدها |
| الرابط العام | Tailscale Funnel: رابط ثابت مجاني بـ HTTPS باسم الجهاز، بلا بطاقة ولا نطاق. البديل السريع: Cloudflare Quick Tunnel (رابطه يتغير مع كل تشغيل) | روابط الدعوة وصورة واتساب والتطبيق تحتاج عنواناً ثابتاً بـ HTTPS |
| الدخول | الويب: Sanctum بالكوكيز (لا توكن في localStorage). التطبيق: توكن Bearer له مدة انتهاء في التخزين الآمن. جوجل: Socialite في الويب، و`id_token` من التطبيق | |
| العرض 2D | PixiJS (WebGL، مجاني) للملعب المتحرك والمؤثرات، وHowler.js للصوت، وCapacitor Haptics للاهتزاز في التطبيق | |
| الإشعارات | Web Push للمتصفح + FCM لتطبيق Android + صندوق رسائل داخل اللعبة | |
| المراقبة | فحص صحة لكل خدمة دائمة كل دقيقة، وتنبيه فوري على الموبايل عبر ntfy (مجاني) | اللعبة تعتمد على عمليات دائمة، ولازم نعرف فوراً لو وقفت |

**التوقيت:** كل الأوقات تُخزن بـ UTC. **الجدولة** بالمنطقة `Africa/Cairo` بالاسم (وليس +2 ثابتة)، فيتعامل النظام مع التوقيت الصيفي تلقائياً. **العرض** بتوقيت جهاز كل مستخدم، فالصديق في بلد آخر يرى المواعيد بتوقيته.

**ساعة اللعبة (GameClock):** كل منطق اللعبة (المباريات، القفل، التدريب، الملعب، الغياب، المواسم) يسأل خدمة `GameClock` عن الوقت، ولا يستدعي `now()` مباشرة. أما أمور الإطار (انتهاء التوكنات، الكاش، حد معدل الطلبات) فتبقى على الوقت الحقيقي. `clock:travel` ممنوع في الإنتاج. في التطوير والاختبارات يمكن تقديم الوقت بأمر (`clock:travel +8h`)، وفي "دوري التطوير" تُلعب جولة كل دقيقة. بدونها لا يمكن اختبار القفل والحكم والتدريب والملعب والمواسم.

## 2. القرارات المحسومة بالتفصيل

### 2.1 الدوريات والانضمام

- دوريات خاصة فقط. أي مستخدم ينشئ دورياً ويصبح منشئه، ويحصل على كود مشاركة من **8 أحرف**، ومحاولات الانضمام بالكود عليها حد معدل.
- عند الإنشاء يُولد الدوري كاملاً بكل فرقه، وكلها تحت إدارة بوت. **الموسم يبدأ في الموعد الذي يحدده المنشئ** (فترة الإعداد تبدأ منه)، ويمشي بعدها على جدوله. في وضع التطوير يوجد زر "ابدأ الآن".
- **مسار الانضمام:**
  1. المستخدم يدخل كود الدوري ويرسل **طلب انضمام**.
  2. المنشئ يوافق على الطلب متى شاء.
  3. بعد الموافقة يرى المدرب كل فرق الدوري بكل بياناتها (اللاعبون، الميزانية، الترتيب، النتائج).
  4. يختار أي فريق بلا مدرب. الفرق المشغولة تظهر للعرض لكنها مقفلة.
  5. الاستلام بتحديث شرطي واحد (`UPDATE clubs SET user_id = ? WHERE id = ? AND user_id IS NULL`) وفحص عدد الصفوف المتأثرة. لو صفر، فقد سبقه أحد: رسالة "الفريق أُخذ" ويعود للقائمة. (`lockForUpdate` لا يعمل على SQLite.)
- الانضمام مسموح بعد بدء الموسم، ما عدا آخر 25% من جولات الدوري.
- **إشراف المنشئ:** يستطيع طرد مدرب بسبب مكتوب، والسبب يظهر لكل أعضاء الدوري. لا يتحكم في إكمال الفرق (البوتات دائماً).
- **عند مغادرة مدرب** (استقالة، غياب، طرد): عروضه المعلقة تُلغى، ومؤقتات التدريب والملعب تكمل كحالة للنادي.
- **حدود الحساب:** فريق واحد في كل دوري، وحتى 4 فرق نشطة في 4 دوريات مختلفة. من يغادر (استقالة أو طرد بالغياب) لا يعود لنفس الدوري في نفس الموسم، ويمكنه العودة في الموسم الجديد. يتحقق ذلك بقيد unique على `(user_id, league_id, season_id)`.
- التحذير المعروف: أي شخص يستطيع إنشاء حساب ثانٍ بإيميل آخر. الحماية العملية هي موافقة المنشئ على الطلبات، ومشاركة الكود مع أشخاص معروفين.

### 2.2 المدربون، الاستقالة، الغياب

| الحالة | القاعدة |
|---|---|
| الاستقالة اليدوية | مسموحة، **ما عدا** في فترة الإعداد (الانتقالات الصيفية) ويوم الانتقالات الشتوي، وفي آخر 25% من جولات الدوري |
| دخول مدرب جديد | ممنوع في آخر 25% من جولات الدوري |
| الطرد التلقائي | بعد 3 أيام متواصلة بلا نشاط في الدوري. **العداد يبدأ مع بداية الموسم** (لا قبله)، ويعمل بعدها في كل الأوقات |
| وضع الإجازة | المدرب يفعّله لحد 7 أيام، مرة واحدة في الموسم. خلالها لا يُحسب غياب، والمساعد يدير الفريق |
| طرد المنشئ | بسبب مكتوب يظهر للجميع، وبنفس آثار الطرد التلقائي |
| تحذير الغياب | إشعار عند 48 ساعة بلا نشاط |
| بعد المغادرة | الفريق يعود بوتاً بحالته كما هي (التشكيلة والميزانية والترتيب)، ومتاح لمدرب آخر |

- "النشاط" = أي دخول لصفحات الدوري أو الفريق أو تعديل (يُجدد `last_active_at` في عضوية الدوري، وليس في المستخدم).
- **صلاحيات البوت:** يغير التشكيلة والخطة والتكتيك، ويشتري لاعبين من مجموعة السوق. **لا يبيع بمبادرته أبداً**، لكنه يقبل البيع بالسعر الثابت عندما يشتري منه مدرب (2.7). ولا يدرب، ولا يطور الملعب.
- **البوت المساعد في المباراة:** لو المدرب غائب وقت المباراة، بوت بقواعد بسيطة يبدل المصاب والمرهق، ويهاجم أكثر لو متأخر في النتيجة.

### 2.3 إعدادات الدوري (يحددها المنشئ عند الإنشاء)

| الإعداد | الخيارات |
|---|---|
| اسم الدوري | نص حر. لو فارغ: اسم القالب + الكود، مثل "الدوري الإنجليزي #K7F2" |
| قالب الدوري | دوري حقيقي من البيانات (الإنجليزي مثلاً) |
| عدد الفرق | من 4 إلى 20، زوجي أو فردي، وبحد أقصى عدد أندية القالب. النظام يأخذ أقوى N فريق في القالب |
| الجولات يومياً | 1 أو 2، مع ساعة كل جولة بتوقيت القاهرة |
| مدة فترة الإعداد (الانتقالات الصيفية) | يوم أو 2 أو 3 |
| نهاية الموسم | موسم جديد في نفس الدوري، أو إنهاء الدوري |
| موعد البدء | تاريخ وساعة بداية فترة الإعداد (من الآن حتى 7 أيام) |
| الميزانية الابتدائية | من 1 إلى 10 ملايين، والافتراضي 3,000,000 من أموال النادي |
| دوري نزيه | نعم / لا. "نعم" يقفل صرف العملة المميزة داخل هذا الدوري |

- **كل الإعدادات تُقفل** (بما فيها الاسم) بمجرد بدء الدوري.
- ثوابت لا يتحكم فيها المنشئ: مدة المباراة، قاعدة الغياب، عدد التبديلات، حجم الكأس.

### 2.4 تقويم الموسم

- دوري ذهاب وإياب (round-robin بطريقة circle method).
- العدد الفردي: فريق يستريح في كل جولة، وكل فريق يستريح مرة في كل دور. الواجهة تعرض عمود "لعب" وعلامة "استراحة".
- **الانتقالات الصيفية:** هي فترة الإعداد في بداية الموسم (1 إلى 3 أيام).
- **الانتقالات الشتوية:** يوم واحد بعد منتصف الموسم، **بلا أي مباريات** (لا دوري ولا كأس).
- **منطقة القفل:** آخر 25% من جولات الدوري (في دوري 30 جولة تبدأ من الجولة 23 تقريباً).
- **السوق مفتوح طول الموسم** (مثل OSM)، ويُقفل في آخر 25% من الجولات. النافذتان الصيفية والشتوية هما موعدا **تجديد مجموعة السوق** فقط.
- **من أين يأتي اللاعبون طول الموسم؟** ثلاثة مصادر:
  1. **أندية الحاسوب:** كل بوت في الدوري يبيع أي لاعب بالسعر الثابت (125%)، ما دام فريقه يبقى 18 لاعباً وحارسين. في دوري 16 فريقاً فيه 4 مدربين حقيقيين، هذا حوالي 300 لاعب متاح في أي يوم.
  2. **قائمة الانتقالات:** ما يعرضه المدربون الحقيقيون من لاعبيهم.
  3. **مجموعة السوق:** حوالي 300 لاعب من خارج أندية الدوري، تتجدد في النافذتين الصيفية والشتوية. وأي لاعب يبيعه مدرب للمجموعة يصبح متاحاً فيها فوراً لغيره.

### 2.5 الكأس

- لقبان في كل موسم: الدوري والكأس.
- خروج مغلوب، مباراة واحدة. التعادل: وقت إضافي (شوطان × 15 دقيقة لعب) ثم ركلات ترجيح.
- الشجرة الرئيسية تبدأ من دور 16 كحد أقصى. الإعفاء للأقوى (حسب متوسط تقييم الفريق أول الموسم)، والقرعة عشوائية بين من يلعبون في نفس الدور.

**القاعدة العامة (تغطي كل الأعداد):** ليكن `n` عدد الفرق، و`S` أكبر قوة للعدد 2 لا تتجاوز `n` (بحد أقصى 16).
- إن كان `n = S`: الكأس يبدأ مباشرة من دور `S`.
- وإلا: أضعف `2 × (n − S)` فرق تلعب **دوراً تمهيدياً**، والباقون معفون، ثم يبدأ دور `S`.
- لو `n` أكبر من 16 يبقى `S = 16`.

| أمثلة | التمهيدي | ثم |
|---|---|---|
| 20 فريقاً | 4 مباريات بين أضعف 8، و12 معفاة | دور 16 |
| 16 | لا يوجد | دور 16 |
| 15 | 7 مباريات بين أضعف 14، وفريق معفى | ربع النهائي |
| 10 | مباراتان بين أضعف 4، و6 معفاة | ربع النهائي |
| 6 | مباراتان بين أضعف 4، وفريقان معفيان | نصف النهائي |
| 4 | لا يوجد | نصف النهائي |

- **أيام الكأس منفصلة تماماً:** كل دور في يوم وحده بلا جولة دوري، ومباراة واحدة لكل فريق حتى لو الدوري جولتين يومياً. الميعاد = أول ميعاد جولة في اليوم.
- الأدوار موزعة على فترات متباعدة. **النهائي داخل منطقة القفل وقبل آخر جولة دوري.** لو صادف يوم كأس يوم الراحة الشتوي، يُزاح لأقرب فاصل بعده.

**مثال توزيع (دوري 15 فريقاً، 30 جولة):**

| التوقيت | الحدث |
|---|---|
| بعد الجولة 6 | الكأس: الدور التمهيدي (7 مباريات، وفريق معفى) |
| بعد الجولة 12 | الكأس: ربع النهائي |
| بعد الجولة 15 | يوم راحة شتوي + انتقالات |
| بعد الجولة 18 | الكأس: نصف النهائي |
| بعد الجولة 26 | نهائي الكأس (داخل القفل من الجولة 23) |

طول الموسم تقريباً (15 فريقاً، إعداد يومان): 37 يوماً بجولة يومياً، و22 يوماً بجولتين يومياً.

### 2.6 البيانات

- **المصدر:** ملف EA FC 26 على Kaggle (ترخيص CC0)، باستخدام الملفين `ea_fc26_outfield.csv` و`ea_fc26_goalkeepers.csv`، وتجاهل الملف المدمج.
- **بيانات حقيقية كاملة** (أسماء الأندية واللاعبين) لأن اللعبة خاصة بالأصدقاء. يُصمم النظام بحيث يمكن تبديلها بحزمة خيالية بتغيير ملف الاستيراد فقط (عمود `source`: generated / custom / imported).
- **قوة الفريق** = متوسط تقييم أفضل 18 لاعباً (لا يوجد عمود قيمة سوقية في الملف).
- **خصائص اللاعبين تُستورد من البداية:** السرعة والتسديد والتمرير والمراوغة والدفاع والبدنية، وخصائص الحارس، وأعمدة الكرات الثابتة. المحرك يستخدمها في كل مرحلة (40% من القدرة) [2.24].
- **قيمة اللاعب بأموال النادي** = معادلة من التقييم والعمر والمركز (تُعاير بعد الاستيراد).
- **الاستيراد:** أمر واحد `php artisan data:import --version=2026`، ينظف البيانات ويرفض الأندية التي تقل عن 18 لاعباً أو بلا حارس.
- **النسخ:** `master_clubs` و`master_players` للقراءة فقط. عند إنشاء الدوري تُنسخ الأندية واللاعبون المختارون إلى `clubs` و`players` مرتبطة بالدوري. كل دوري يبقى على نسخة البيانات التي أُنشئ بها حتى لو نزلت نسخة أحدث.
- التحديث: إدخال يدوي مرة في السنة (لا سحب تلقائي).
- **الشعارات:** ملفات محلية على السيرفر، وبديل تلقائي (شارة بألوان الفريق وحروفه) لو الشعار غير موجود.

| البند | القرار |

| العملة 1: أموال النادي | تخص النادي في دوري واحد، تبدأ بـ 3 مليون، وتُصفّر مع الموسم الجديد. هي ميزانية الصفقات والرواتب والملعب |
| العملة 2: العملة المميزة | تخص **الحساب** (مثل Credits في OSM، أيقونتها `brand/current/coin-*.png`). في v1 تُكسب داخل اللعبة فقط (الدخول اليومي، الفوز، تحقيق الهدف، الألقاب)، وتُصرف مثل OSM (الإنهاء الفوري، التجسس، الأخصائيون، التدريب السري). لا تتحول أبداً إلى أموال نادي، ولها سقف صرف لكل مدرب في الموسم، ويقفلها إعداد "دوري نزيه" |
| التخزين | أرقام صحيحة (integers) فقط، وكل حركة في جدول `club_transactions` (النوع، المبلغ، الرصيد بعد العملية). سجل منفصل للعملة المميزة على مستوى الحساب (`wallet_transactions`) |
| الأمان | كل عملية مال داخل معاملة `IMMEDIATE` مع تحديث شرطي (مثل `UPDATE ... WHERE balance >= ?` وفحص عدد الصفوف)، و**مفتاح idempotency لكل عملية مال** حتى لا يتكرر الخصم بضغطة مزدوجة أو شبكة ضعيفة |
| مصدر اللاعبين | مجموعة سوق (حوالي 300 لاعب من خارج أندية الدوري، تتجدد كل نافذة) + **أندية الحاسوب** + تبادل بين المدربين الحقيقيين |
| الكشاف | مثل OSM: بتكلفة من أموال النادي، يستغرق يوماً (أو فوري بالعملة المميزة)، ويعيد 3 لاعبين حسب معاييرك (المركز، المستوى، الجنسية، العمر، الدوري) |
| قائمة الانتقالات | المدرب يعرض لاعبه بسعر يحدده، وأي مدرب يقدّم عرضاً |
| العرض المباشر | عرض على لاعب غير معروض للبيع، وصاحب النادي يقبل أو يرفض أو يفاوض |
| الشراء من أندية الحاسوب | **مسموح**، بشرط النزاهة: سعر ثابت 125% من القيمة بلا تفاوض ولا خصومات، نفس السعر لكل المدربين، والحاسوب لا يبيع لو هبط فريقه عن 18 لاعباً أو حارسين |
| التبادل بين الأندية البشرية | بالتفاوض، ولا يتم إلا بقبول مدير النادي الآخر. قيود ضد نقل المال بين حسابين: **السعر بين 50% و200% من القيمة**، و**اللاعب لا يُنقل بين نفس الناديين مرتين في الموسم**، و**سقف لصافي ما ينتقل من أموال بين أي ناديين في الموسم** (مبدئياً 25% من ميزانية البداية). العرض يُلغى تلقائياً لو بيع اللاعب لغيره |
| البيع للمجموعة | مسموح لتوفير السيولة. **المدرب يشتري من المجموعة بـ 100% من القيمة، ويبيع لها بـ 70% من القيمة الأصلية** (بدون أثر التدريب)، حتى لا تصبح دورة "اشترِ ودرّب وبِع للمجموعة" مصدر مال مضمون. ربح التدريب يتحقق بالبيع لمدرب آخر |
| الدخل | **رعاة لكل قطاع من الملعب** (مثل OSM: المدرب يختار عقد كل قطاع، ودخل ثابت لكل مباراة على الأرض) + التذاكر حسب السعة + مكافأة فوز أو تعادل + جوائز نهاية الموسم (الدوري والكأس) |
| المصاريف | رواتب كل جولة كنسبة صغيرة من قيمة التشكيلة + تطوير الملعب |
| الديون | الرصيد يمكن أن ينزل تحت الصفر بالرواتب. وهو سالب: **ممنوع أي صرف** (شراء، تدريب، ملعب، كشاف). لو بقي سالباً 3 جولات متتالية، **يُباع أغلى لاعب تلقائياً للمجموعة**، ويتكرر حتى يعود موجباً |
| استلام فريق من بوت | ميزانيته عند الاستلام **تُحصر بين 500,000 وميزانية البداية**: الأقل تُرفع هدية، والأعلى تُخفض. حتى لا يُضخ مال في بوت ثم يُستلم، ولا يرث المتأخر ميزانية تفوق الأوائل |
| أموال البوت | البوت يكسب دخله مثل أي نادٍ، ولا يصرف إلا على شراء لاعبين لسد النقص |
| العقود | بلا مدة في النسخة الأولى |

### 2.8 التدريب، اللياقة، الإصابات، البطاقات

**التدريب (بأموال النادي، مثل OSM):**
- 4 خانات: حارس، دفاع، وسط، هجوم. لاعب واحد من كل خط في نفس الوقت.
- كل 8 ساعات (مُعايرة حسب طول الموسم) يزيد شريط تقدم اللاعب بنسبة عشوائية، والسيرفر يحسبها حتى لو المدرب أوفلاين.
- عند 100%: القوة +1 (89 تصبح 90)، وتزيد الخصائص الست (وخصائص الحارس) بنفس البونص، والقيمة معها. الخانة تفرغ والمدرب يضيف لاعباً جديداً يدوياً.
- الصعوبة تزيد مع القوة (حوالي 6 جلسات من 65 إلى 66، وحوالي 25 جلسة من 89 إلى 90)، تُعاير بالمحاكاة.
- **الإمكانية (Potential)** مثل OSM: لكل لاعب سقف تطور حسب عمره (الشباب أعلى، وفوق 30 أقل)، والتدريب يتوقف عنده. السقف يُحسب عند الاستيراد ويظهر في بطاقة اللاعب.
- التكلفة: كل جلسة بأموال النادي، وإكمالها فوراً بالعملة المميزة.
- **هدف المعايرة:** اللاعب الذي يتدرب باستمرار طول الموسم يتحسن بين +3 و+5 في المتوسط.
- يُخزن كـ `training_bonus` على نسخة اللاعب في الدوري، والقوة الفعلية = الأصلية + البونص. التقدم رقم صحيح من 10000.
- افتراض: اللاعب المصاب يستطيع البقاء في التدريب.

**اللياقة:**
- تنزل حسب الدقائق والمجهود (الضغط والإيقاع والمشاركة في الصراعات تزيد النزول). بإعدادات محايدة ينهي اللاعب المباراة بحوالي 75%، وبضغط كامل بحوالي 60%، فيبدأ الأثر قرب الدقيقة 60 إلى 65 ويصبح التبديل قراراً حقيقياً.
- تتعافى فقط لو ارتاح اللاعب في مباراة الفريق التالية (لم يلعب أساسياً ولا بديلاً). لو لعب تنزل أكثر.
- **"المباراة التالية" = مباراة الفريق التالية في أي مسابقة** (دوري أو كأس). نفس القاعدة لعدّ الإصابة والإيقاف: البطاقة الحمراء في الدوري توقف اللاعب في مباراة الكأس التالية لو جاءت أولاً.
- اللياقة المنخفضة تضعف أداءه فعلياً في المحاكاة، ولو وصلت 0 يُصاب.

**الإصابات:** من الالتحامات، واحتمالها يرتفع مع خشونة "قطع الكرة" عند الخصم ومع الإرهاق. المدة بعدد المباريات.

**البطاقات:** تأتي **من خسارة الصراعات وأنت مدافع**، لا من اسم التكتيك: كلما تجاوزك المهاجم بفارق أكبر، ومع "قطع الكرة" الأخشن والإرهاق وصرامة الحكم، زاد احتمال الخطأ والبطاقة. الحمراء المباشرة لتعطيل فرصة محققة، وصفراء ثانية في نفس المباراة = حمراء. الحمراء: الفريق يكمل بعشرة، والخط يضعف وتزيد إرهاقه، والمدرب يعدل بنفسه في الدقيقة التالية، واللاعب يغيب مباراة واحدة. **الصفراء لا تتراكم بين المباريات (محسوم):** الإيقاف بالحمراء فقط. ركلة الجزاء من خطأ داخل المنطقة. التفاصيل في `docs/ENGINE.md` (6.1).

### 2.12 المباراة والمحاكاة

- **مدة العرض حوالي 5 دقائق:** 90 Tick (دقيقة لعب) × 3 ثوانٍ = 4.5 دقيقة + نصف دقيقة استراحة = 5 دقائق، ويضيف بدل الضائع حوالي 15 ثانية، فالمباراة بين 5 دقائق وأكثر قليلاً.
- **الحد الأقصى 120 دقيقة لعب + ركلات ترجيح** (في الكأس فقط): الوقت الإضافي (30 Tick) بثانيتين للـ Tick مع 10 ثوانٍ بين شوطيه، ثم الترجيح ركلة ركلة (حوالي 30 ثانية). أطول مباراة كأس حوالي 7 دقائق.
- **بدل الضائع (محسوم):** يحسبه المحرك عند الدقيقة 45 و90 من أحداث الشوط (الأهداف والتبديلات والإصابات والبطاقات) بعشوائية صغيرة من البذرة، ويُعلن كحدث. الشوط الأول 1 إلى 3، والثاني 2 إلى 6، والوقت الإضافي 0 إلى 2. البذرة برقم تسلسل الـ Tick لا الدقيقة المعروضة.
- **المحاكاة دقيقة بدقيقة:** المحرك دالة نقية حتمية `simulateTick(state, actions, rng)` لا تلمس قاعدة البيانات، والبذرة = بذرة المباراة + رقم تسلسل الـ Tick. أي أمر من المدرب أثناء جريان المباراة (تبديل، تغيير خطة اللعب أو أي تكتيك، تغيير الطريقة أو مراكز اللاعبين) يُطبق في بداية الدقيقة التالية (خلال 3 ثوانٍ على الأكثر)، والأحداث تُبث عبر Reverb فور حسابها. (فكرة "المقاطع" ألغيت.)
- **أرقام صحيحة داخل المحرك:** المحرك يستخدم أرقاماً صحيحة (fixed-point) وجداول بحث بدل `exp` و`pow`، لأن نتائج الدوال العشرية قد تختلف بين المعالجات (x86 على الجهاز وARM على السيرفر). اختبار في CI على المعماريتين.
- **حماية الأرقام الصحيحة:** تجاوز حد العدد الصحيح في PHP يتحول بصمت إلى float، فالمحرك يفحص قيمه ويرمي استثناء عند ظهور أي float، مع اختبار حدود.
- **الإعادة:** البذرة + الحالة الأولى + الأوامر المطبقة = نفس المباراة حرفياً. كل مباراة تُخزن `engine_version` و**لقطة من إعدادات المحرك** (`config_snapshot`) لحظة البدء، فتعديل `config/game.php` لا يغيّر مباراة جارية ولا إعادتها. المباريات من إصدار أقدم تُعرض من أحداثها المخزنة في `match_events` (لا نحتفظ بكود الإصدارات القديمة).
- **توقيت الأوامر:** كل أمر يُسجَّل برقم الدقيقة المستهدفة (الدقيقة التالية لحظة استلامه). المشغّل يطبق في بداية كل دقيقة الأوامر المستهدفة لها أو قبلها، فالترتيب ثابت في الإعادة.
- **النشر:** ممنوع النشر والمباريات جارية. النشر ينتظر حتى تنتهي كل المباريات الجارية.
- **بوت ضد بوت:** تُحاكى فوراً بلا بث لحظي عند موعدها، وتُنشر نتيجتها في موعد نهايتها الطبيعي.
- **مدرب بأكثر من مباراة في نفس الوقت** (من دوريات مختلفة): شاشة المباراة فيها مبدّل بين مبارياته الحية، والمساعد يدير التي لا يتابعها.
- **التعافي:** لو توقف المشغّل أو السيرفر في منتصف مباراة، تكمل من آخر دقيقة بعد الرجوع (الحالة تُعاد بناؤها من البذرة والأوامر). المباراة التي فات موعدها: إن كان التأخير 10 دقائق أو أقل تبدأ متأخرة، وإن زاد تُحاكى فوراً حتى النهاية وتُعرض كإعادة.
- **التخزين:** حالة المباراة الجارية في الـ Cache، وتُكتب في SQLite عند الاستراحة والنهاية فقط.
- **تحديد النتيجة (`docs/ENGINE.md`):** كل دقيقة: أوامر المدرب، ثم المبادرة (حوالي 0.58 هجمة في الدقيقة، أي حوالي 26 لكل فريق)، ثم مراحل الهجمة **بناء ← تقدم ← صناعة فرصة ← تسديدة ← هدف أو لا**، ثم الأخطاء والبطاقات والإصابات واللياقة. كل مرحلة مواجهة بين قدرة المهاجم والمدافع تتحول لاحتمال بجدول بحث صحيح، بأرضية 8% وسقف 92%.
- **قدرة اللاعب في كل مرحلة = 60% من `overall` + 40% من خصائصه المناسبة** (المهاجم السريع يفرق في الارتداد، وصانع اللعب في التمريرات)، ثم اللياقة والمركز وميزة الأرض.
- **العشوائية متوسطة:** فارق 18 نقطة (الأول ضد الأخير) يعطي الأقوى حوالي 67% فوزاً، بدون أي تعديل خاص.
- **وضع النتيجة والطرد:** المتأخر بعد الدقيقة 60 يهاجم أكثر والمتقدم يتراجع، فتظهر الأهداف المتأخرة. والطرد يضعف خط اللاعب ويرهق الفريق.
- **اللعب خارج المركز:** عقوبة بسيطة في نفس الخط، متوسطة في خط آخر، شبه كاملة لحارس خارج المرمى أو لاعب ملعب في المرمى.
- **التبديلات:** 3 لكل فريق (+1 في الوقت الإضافي بالكأس). تبديل المصاب يُحسب منها. تغيير التشكيلة والتكتيك أثناء المباراة لا يُحسب تبديلاً، ويُطبق في الدقيقة التالية.
- **العرض في النسخة الأولى: ملعب 2D متحرك بمؤثرات** [2.24]. المحرك ينتج بيانات هجمات (المراحل، ومن مرر لمن، والمنطقة، والتسديدة، والنتيجة) والعرض طبقة فوقها ترسمها حركياً، فيتطور لاحقاً إلى 3D بدون لمس المحرك.
- **شاشة استراحة الشوط** موجودة من الآن، ومكان الإعلان فارغ.

### 2.13 القفل، الحكم، الإشعارات

| التوقيت | ما يحدث |
|---|---|
| قبل المباراة بـ 30 دقيقة | تعيين الحكم وصرامته (متساهل، متوسط، صارم) عشوائياً في السيرفر وتخزينها، وإشعار للمدربين |
| قبل المباراة بـ 5 دقائق (القفل) | **تصحيح تلقائي:** أي مصاب أو موقوف في التشكيلة يُستبدل بأفضل بديل. ثم تجميد التشكيلة والتكتيكات الأولية معاً. يظهر للخصم: الـ 11 الأساسيون والطريقة + 4 تكتيكات فقط (قطع الكرة، الرقابة، خطة اللعب، مصيدة التسلل) |
| أثناء المباراة | التعديل مسموح ويُطبق في الدقيقة التالية. التكتيكات الأربعة المعروضة للخصم تتحدث لحظياً |

- **مخفي عن الخصم دائماً:** الضغط، الأسلوب، الإيقاع، التمركز، **والشكل الدفاعي المشتق منها**. ولا يظهر في أي استجابة API ولا في أي حدث بث يصل للخصم، ولا في القراءة الحية ولا تقرير ما بعد المباراة، ولا يُرسم خط دفاع الخصم منه على الملعب (اختبار إلزامي).
- **قنوات البث:** قناة المباراة خاصة بأعضاء الدوري (مصادق عليها)، وقناة خاصة لكل نادٍ. لا قنوات عامة، لأن الدوريات خاصة.
- Web Push يحتاج HTTPS وموافقة المستخدم، وعلى الآيفون يعمل فقط لو أُضيف الموقع للشاشة الرئيسية. لذلك يوجد أيضاً شريط تنبيه داخل اللعبة.

| الإعداد | الخيارات | الثمن |

| الرقابة | دفاع منطقة / رجل لرجل | المنطقة أقوى ضد مهاجمين كثر، ورجل لرجل ضد نجم واحد |

**التكتيك يغيّر السلوك لا القوة** (يحل محل "مقياس التناسق" الملغى): كل إعداد يغيّر احتمالات مراحل الهجمة وعدد الهجمات والأخطاء والإرهاق، والنتيجة تطلع من أسباب ظاهرة. التفاصيل لكل مقبض في `docs/ENGINE.md` (5).

- **الشكل الدفاعي** (عالٍ، متوسط، منخفض) يُشتق من الضغط والأسلوب والمصيدة وتمركز المدافعين، ومخفي عن الخصم.
- **مصفوفة المواجهة:** 5 خطط هجوم × 3 أشكال دفاع بنقاط تُضاف لمرحلة التقدم (مثلاً المرتد +3 ضد الدفاع العالي و−3 ضد المنخفض). مجموع كل صف وعمود صفر، فلا خطة أفضل في المتوسط.
- **ميزانية التكتيك:** أفضل تكتيك ضد أسوأ تكتيك ≈ 6 نقاط قوة. يقلب مباراة متقاربة، ولا يقلب فارقاً كبيراً.
- **النصائح** تبقى في صفحة التكتيك بصياغتنا، لكنها تشرح الآلية ("ضغط عالٍ + خشونة + حكم صارم = بطاقات متوقعة")، ولا تعدّل أي رقم.
- **منع "التكتيك الصحيح الوحيد":** `sim:matrix` يفشل لو فاز أي إعداد بأكثر من 58% في المتوسط بين فريقين متساويين.

> نصوص النصائح والأيقونات والشخصيات المرسومة تُكتب وتُرسم من عندنا، ولا تُنسخ من OSM.

### 2.17 الحسابات والدخول

- إيميل + باسورد (تسجيل، تأكيد إيميل، استرجاع باسورد) + حساب جوجل: Socialite في الويب، وGoogle Sign-In الأصلي في تطبيق Android يرسل `id_token` للسيرفر.
- نفس الحساب يعمل على الويب والتطبيق. الويب بكوكيز Sanctum، والتطبيق بتوكن له مدة انتهاء في التخزين الآمن.
- **ربط جوجل بحساب موجود** يتم فقط إذا كان الإيميل مؤكداً عند جوجل (`email_verified`) **ومؤكداً في حسابنا**. لو حساب الباسورد غير مؤكد: يُحذف أو تُصفَّر كلمة مروره وتوكناته قبل الربط. والتحقق من `aud` لكل Client ID (ويب وAndroid). يمنع اختطاف الحساب بتسجيل مسبق بإيميل الضحية.
- **حذف الحساب** من الإعدادات (مطلوب في المتاجر، وحق للمستخدم): فريقه يعود بوتاً ويُحذف كل ما يخصه.
- **الصلاحيات:** عمود `role` (user / admin)، ولوحة الإدارة للـ admin فقط مع تحقق بخطوتين.
- لا رقم هاتف.
- محلياً: البريد يُعرض في Mailpit أو في ملف اللوج. خدمة بريد بخطة مجانية تُختار وقت النشر.

### 2.18 الإعلانات والشراء الحقيقي

**القرار (v1):** العملة المميزة تُكسب **داخل اللعبة فقط** (الدخول اليومي، الفوز، تحقيق الهدف، الألقاب)، فالكل متساوٍ. وتُصرف مثل OSM. مع قيود نزاهة دائمة: لا تتحول أبداً إلى أموال نادي، وسقف صرف لكل مدرب في الموسم، وإعداد "دوري نزيه" يقفلها. الإعلانات والشراء الحقيقي في مرحلة ثانية بعد v1، بعد تبديل البيانات بحزمة خيالية والتأكد من بوابة الدفع. في المتاجر يلزم نظام الشراء داخل التطبيق الخاص بـ Apple وGoogle للعملات الرقمية.

لماذا التأجيل:

1. شبكات الإعلانات تمنع عرض الإعلانات بجانب محتوى محمي بلا ترخيص، والبيع الحقيقي يجعل الاستخدام تجارياً فيكبر الخطر القانوني للأسماء الحقيقية.
2. الشراء الحقيقي يعطي أفضلية بالمال، وهذا يتعارض مع شرط النزاهة بين المتنافسين.
3. بوابات الدفع لها قيود حسب بلد التاجر، ويجب التأكد من توفرها قبل البناء.

مكان الإعلان بين الشوطين محجوز في الواجهة من الآن.

### 2.19 الاستضافة

1. **السيرفر في v1 = جهاز منزلي** (جهاز التطوير أو أي جهاز قديم) بـ Laragon أو Herd على ويندوز. مجاني، ويدعم كل ما تحتاجه اللعبة: عمليات دائمة، WebSocket، ملفات SQLite. الاستضافات المجانية المعروفة لا تناسب: تنام بعد دقائق من عدم النشاط، أو تمنع العمليات الدائمة، أو تطلب بطاقة.
2. **الرابط العام:** Tailscale Funnel (مجاني، `اسم-الجهاز.tailnet.ts.net` بـ HTTPS). ميزة تجريبية لها حدود سرعة غير معلنة، وتكفي مجموعة أصدقاء.
3. **الشرط العملي:** الجهاز يكون شغالاً ومتصلاً وقت المباريات، فتُختار ساعات الجولات على هذا الأساس. كل الخدمات تبدأ وحدها مع تشغيل الجهاز، والمباراة التي فاتها موعدها تُحاكى عند الرجوع [2.12].
4. **لاحقاً عند توفر ميزانية:** VPS صغير ونطاق باسم اللعبة. النقل سهل لأن قاعدة البيانات ملفات SQLite.
5. **المتطلبات:** PHP حديث، قرص دائم لملفات SQLite، Scheduler كل دقيقة، Queue Worker دائم، Reverb دائم، المشغّل اللحظي دائم، HTTPS.
6. **التشغيل الدائم:** كل خدمة دائمة (الويب، Reverb، الطابور، `matches:run`، الـ Scheduler) خدمة ويندوز تبدأ مع الجهاز وتُعاد تلقائياً لو وقعت.
7. **المراقبة:** فحص صحة كل دقيقة، وتنبيه فوري على موبايلَي سليمان وحمزة عبر ntfy (مجاني) لو وقفت أي خدمة.
8. **النسخ الاحتياطي:** نسخ متواصل بـ Litestream إلى قرص ثانٍ (يفقد ثوانٍ لا يوماً)، ونسخة يومية بـ `VACUUM INTO` إلى Google Drive، مع تجربة استرجاع فعلية.

### 2.20 مزايا OSM الإضافية

القاعدة: تعمل **تماماً مثل OSM**. **أول مهمة في سبرنت كل ميزة: مواصفة من صفحة** في `docs/features/` (الآلية، الأرقام المبدئية، ما يراه اللاعب، والاختبارات)، يكتبها الفريق ويوافق عليها صاحب المشروع قبل الكود. الأرقام في `config/game.php`، وتُستبدل بأرقام OSM متى توفرت، وتُعاير في سبرنت المعايرة.

| الميزة | ما هو محسوم | ما ينتظر التوثيق من OSM |
|---|---|---|
| **هدف النادي** | في الدوري: مركز مطلوب حسب قوة النادي (لقب، مركز متقدم، بقاء)، يظهر عند اختيار الفريق، ويُقيَّم المدرب عليه آخر الموسم. في الكأس: الدور المطلوب الوصول إليه | معادلة الهدف وأثر النجاح أو الفشل |
| **معسكر التدريب** | مثل OSM | الآلية والأرقام |
| **التدريب السري** | مثل OSM | الآلية والأرقام |
| **التجسس على الخصم** | مثل OSM | ما الذي يُكشف، والتكلفة |
| **الأخصائيون** (الطبيب، المحامي، وغيرهم؛ جدول `staff_specialists`) | مثل OSM | القائمة الكاملة وأثر كل واحد وتكلفته |
| **الإنهاء الفوري بالعملة المميزة** | مثل OSM (التدريب، الكشاف، الملعب...) | جدول الأسعار |
| **المتجر** | مثل OSM | الحزم والأسعار |

### 2.21 التعليق الصوتي

- مكتبة مقاطع صوتية جاهزة **بلا أسماء** ("جووول!"، فرصة ضائعة، بطاقة حمراء، صافرة النهاية، هتافات الجمهور)، تُولَّد مرة واحدة بأداة صوت بالذكاء الاصطناعي، وتُشغَّل حسب نوع الحدث وسياقه (تعادل، هدف قاتل...).
- مؤثرات جمهور ترتفع مع الهجمة الخطيرة، وزر كتم.
- لاحقاً: نطق الأسماء بتوليد مسبق لأسماء لاعبي الأندية المستخدمة فقط (حوالي 500 اسم).
- الصوت مُولَّد أو مسجل لنا، ولا يُقتطع من بث تلفزيوني لمعلق حقيقي.
- التعليق النصي العربي طبقة عرض بعد المحرك من جدول قوالب، والمقطع الصوتي يُربط بنفس الحدث.
- **اللهجة:** فصحى بسيطة بأسلوب المعلقين العرب، في النص والصوت.
- تُجرَّب عينة صوت AI عربية مبكراً (مع شاشة المباراة)، قبل بناء المكتبة كاملة.

### 2.22 الحمل وقياس النجاح

- **تعريف الحمل:** "50 مباراة متزامنة" = 50 مباراة فيها مدرب بشري واحد على الأقل في نفس الدقيقة. مباريات بوت ضد بوت لا تُحسب لأنها تُحاكى فوراً بلا بث.

- سجل نشاط بسيط: لكل مستخدم يومياً عدد الدخول، والمباريات التي تابعها مباشرة، والأوامر التي أرسلها.
- معيار v1: نسبة الأصدقاء الذين يتابعون مبارياتهم ويعودون أسبوعياً، تُعرض في لوحة الإدارة.

### 2.23 التصميم

- **الاتجاه:** نفس بنية شاشات OSM وتنقلها، لأن اللاعبين يعرفونها، لكن بتصميم أكثر احترافية وبهوية Legends (`brand/`). لا تُنسخ رسوم OSM ولا أيقوناتها ولا نصوصها ولا شخصياتها.
- **نظام تصميم واحد** (السبرنت 1): الألوان من `brand/`، خط عربي للعناوين وآخر للنص، مسافات وزوايا وظلال موحدة، ومكونات (بطاقة لاعب، بطاقة نادٍ، جدول، شارات المراكز واللياقة، أزرار، أشرطة تقدم، عدادات تنازلية).
- **الويب:** شريط جانبي للتنقل، ولوحة رئيسية بالبطاقات، وجداول عريضة. **الموبايل (داخل التطبيق ومتصفح الموبايل):** شريط تنقل سفلي، وبطاقات بعرض الشاشة، وأزرار لمس 44px على الأقل. نفس كود Vue يتكيف مع العرض.
- **ما يميزنا عن OSM:** شاشة مباراة حية فيها ملعب وتعليق وصوت ولوحة مدرب، ووضع داكن افتراضي بألوان Legends، وحركات انتقال خفيفة، وأرقام واضحة (اللياقة والقوة والقيمة) بلون حسب المستوى.
- **العملية:** كل سبرنت فيه شاشات يبدأ بتصميمها (مهمة D0)، ويوافق عليها صاحب المشروع قبل كتابة الواجهة. لقطات OSM المرجعية في `docs/design/reference/`.

| ميزة الأرض | **أساسية لكل فريق على أرضه: +2.5%** من قدرته، وأرضية الملعب تضيف +1% إلى +3% فوقها [2.9] |
| بدل الضائع | **نعم**، يحسبه المحرك من أحداث الشوط ويُعلن كحدث، ويضيف حوالي 15 ثانية عرض [2.12] |
| خصائص اللاعبين | **من البداية** (السبرنت 3 و4): 60% من `overall` + 40% من الخصائص في كل مرحلة [2.6] |
| تراكم الصفراء | **لا تتراكم بين المباريات**، والإيقاف بالحمراء فقط [2.8] |
| القراءة التكتيكية الحية | **نعم**: ملاحظة قصيرة من المساعد على قناة النادي الخاصة كل حوالي 15 دقيقة لعب أو عند حدث مهم، تصف الأثر من الأحداث العلنية وبيانات فريقك فقط، ولا تكشف قيم الخصم المخفية |
| تقرير ما بعد المباراة | "لماذا فزت أو خسرت": أهم 3 أسباب بالأرقام (البناء المقطوع، الارتدادات، الإرهاق، البطاقات، الفرص مقابل الأهداف)، بنفس قاعدة الخصوصية |
| البوتات | 6 شخصيات (الكبار، المدافعون، الضاغطون، الخشنون، الأجنحة، المتكيف)، تتكيف مع الخصم مما يراه أي مدرب بشري فقط |
| مدة المباراة | حوالي 5 دقائق عرض (Tick = 3 ثوانٍ)، وحتى 120 دقيقة لعب + ركلات ترجيح في الكأس [2.12] |
| التحكم أثناء المباراة | التبديلات وتغيير خطة اللعب وكل التكتيكات والطريقة ومراكز اللاعبين أثناء جريان المباراة، تُطبق في الدقيقة التالية |

**العرض الحركي للمدرب (داخل v1):**

- **ملعب 2D متحرك** (PixiJS): لاعبون كنقاط بألوان الفريقين وأرقامهم في مواقع الطريقة، والكرة تتحرك عبر مراحل كل هجمة (بناء، تقدم، صناعة، تسديدة) داخل الـ 3 ثوانٍ، وخط الدفاع لفريقك يتحرك حسب تكتيكك.
- **مؤثرات بصرية:** هدف (وميض، اهتزاز الشبكة، تحريك النتيجة)، فرصة محققة (تقريب على المنطقة)، بطاقة (ظهور البطاقة على اللاعب)، تبديل وإصابة، وإعلان بدل الضائع.
- **صوت:** تعليق من مكتبة المقاطع [2.21]، وجمهور يرتفع مع الهجمة الخطيرة، وصافرات، واهتزاز للجهاز مع الهدف في التطبيق. زر كتم.
- **لوحة المدرب:** شريط الزخم (من يهاجم أكثر في آخر 10 دقائق)، إحصائيات حية، لياقة لاعبيك ملونة حسب المستوى، والقراءة التكتيكية الحية، وأزرار التبديل والتكتيك بلمسة واحدة.
- **الأداء والوصولية:** يعمل بسلاسة على موبايل متوسط، ويحترم إعداد "تقليل الحركة" في الجهاز، ويوجد وضع نصي خفيف.
- **الخصوصية في الرسم:** فريق الخصم يُرسم من طريقته المكشوفة فقط، ولا يُرسم خط دفاعه أو ضغطه من قيمه المخفية.
