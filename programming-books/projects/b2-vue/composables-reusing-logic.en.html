Practice projects

For each composable, write its signature and a test before its body: what it takes, what it returns, and what it cleans up. If the test is hard to write, the design is usually wrong.

Project {{n}}.1 · Easy

Your own useStoredRef

Write the composable behind VueUse’s useLocalStorage yourself: a ref whose value is saved in the browser, survives reloads, and never crashes on bad data.

You will practise: a generic composable, watch with deep, defensive parsing, and the storage event.

  1. Write useStoredRef<T>(key: string, initial: T). Read the saved JSON inside try, and fall back to initial if it is missing or broken.
  2. Save on every change with watch(value, save, { deep: true }).
  3. Listen to the window’s storage event, which fires when another tab changes the same key, and update the ref, using your useEventListener so it is cleaned up.
  4. Use it for the tasks of Chapter {{n-1}}, and check in two tabs that ticking a task in one updates the other.

Hint: after writing it, compare with VueUse’s source code. Reading how a well-maintained library solves the same problem, and which cases it handles that you missed, is one of the fastest ways to improve.

Project {{n}}.2 · Medium

A tested usePagination

A composable that splits any list into pages, follows the list when it changes, and never shows an empty page.

You will practise: generic types, MaybeRefOrGetter, computed values that depend on each other, and tests written first.

  1. Write the tests first: seven items in pages of three give three pages, and next() shows items 4 to 6.
  2. Write a harder test: go to page 3, then shrink the list to two items. The current page must become 1, not stay on an empty page 3.
  3. Keep only the requested page in a ref. Make the number of pages, the current page (the requested one, clamped) and the rows computed.
  4. Use it in the catalogue of Chapter {{n-2}} with “Previous” and “Next” buttons, disabled at the ends, and “Page 2 of 3” between them.

Hint: clamping in a computed, instead of correcting the ref in a watcher, means the page can never be wrong, not even for a moment.
