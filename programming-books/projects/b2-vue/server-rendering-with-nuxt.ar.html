متجر يتعثر بلطف

أعطِ متجر بِت أخطاء لطيفة، وشريط تحميل، وجزءاً بطيئاً لا يؤخر الصفحة كلها.

ستتدرب على: error.vue وcreateError وclearError و<NuxtLoadingIndicator>، وuseFetch مع lazy.

  1. اجعل error.vue تعرض رسالة مختلفة لـ 404 ولغيره، وتقدم طريقاً إلى الرئيسية بـ clearError({ redirect: "/" }).
  2. اجعل واجهة المنتجات ترمي 500 لمعرّف واحد، وتحقق مما يراه المستخدمون، وأي رمز حالة يبلّغ عنه curl -I.
  3. أضف واجهة «مراجعات» بطيئة (1.5 ثانية) وحمّلها في صفحة المنتج بـ useFetch(…, { lazy: true })، فلا تنتظرها الصفحة. واعرض هيكلاً صغيراً ما دامت status تساوي "pending".
  4. تأكد بشبكة بطيئة في أدوات المطور أن شريط <NuxtLoadingIndicator> يظهر بين الصفحات.

تلميح: الجلب الكسول يرسم الصفحة على الخادم دون تلك البيانات، ويحمّلها في المتصفح. استخدمه للأجزاء أسفل الشاشة أو الأقل أهمية، ولا تستخدمه أبداً للمحتوى الأساسي الذي تحتاجه محركات البحث في HTML.

مدونة ثابتة تحبها محركات البحث

مدونة مقالاتها ملفات Markdown داخل المشروع، تُرسم مسبقاً وقت البناء، ولكل مقال عنوانه ووصفه، ومعها خريطة للموقع.

ستتدرب على: قراءة الملفات في مسارات الخادم، والصفحات المتغيرة، وuseSeoMeta، والرسم المسبق، ومسار خادم يُرجع XML.

  1. ضع ثلاث مقالات في server/content/، يبدأ كل منها بعنوان وتاريخ. واكتب server/utils/posts.ts يقرؤها بـ node:fs/promises.
  2. أضف server/api/posts.get.ts وserver/api/posts/[slug].get.ts، يحوّلان Markdown إلى HTML على الخادم بمكتبة مثل marked.
  3. اكتب pages/blog/index.vue وpages/blog/[slug].vue بـ useFetch وuseSeoMeta، و404 للأسماء المجهولة.
  4. أضف القاعدة "/blog/**": { prerender: true }. فيتبع Nitro الروابط من القائمة ويرسم مسبقاً كل مقال يجده.
  5. أضف server/routes/sitemap.xml.ts الذي يُرجع عنوان كل مقال بـ content-type الصحيح.

تلميح: مكتبة Markdown تعمل على الخادم فقط، فلا تضيف شيئاً إلى JavaScript المتصفح. فالعمل الثقيل مكانه server/، والمتصفح يجب أن يستلم النتائج لا الأدوات.

أسعار يغيّرها المدير

صفحة إدارة محمية يغيّر فيها صاحب المتجر سعر منتج، فتعرض صفحات المنتجات المخزنة السعر الجديد بعد قليل، ولا يستطيع أحد غيره تغيير شيء.

ستتدرب على: ملفات تعريف الارتباط على الخادم، وبرمجيات المسار الوسيطة، ومسارات الخادم مع فحص الصلاحيات، وruntimeConfig، وقواعد المسارات.

  1. احفظ الأسعار في Map على الخادم تستطيع دالة updatePrice(id, price) تغييرها.
  2. اكتب server/api/admin/sign-in.post.ts يقارن كلمة مرور بـ useRuntimeConfig().adminPassword، وعند النجاح يضع ملف تعريف ارتباط httpOnly وsecure وsameSite بـ setCookie.
  3. احمِ الصفحة ببرمجية وسيطة في app/middleware/admin.ts تعيد التوجيه إلى صفحة الدخول حين يغيب ملف تعريف الارتباط، وأعطِ صفحات الإدارة ssr: false في قواعد المسارات.
  4. اكتب server/api/admin/price.post.ts. يفحص ملف تعريف الارتباط مرة أخرى (فبرمجية الصفحة لا تحمي المسار)، ويتحقق بـ zod أن السعر عدد صحيح موجب، ويستدعي updatePrice.
  5. غيّر سعراً، ثم افتح صفحة المنتج. واشرح لماذا قد يظهر السعر القديم حتى مدة swr، وكيف يغيّر ذلك وقتٌ أقصر، أو إلغاء التخزين لهذه الصفحة.

تلميح: فحص الصلاحية يعيش داخل كل مسار خادم، لا في الصفحة التي تعرض النموذج وحدها. فالبرمجية الوسيطة تقرر ما تعرضه الشاشة، والخادم وحده يقرر ما يحدث.
