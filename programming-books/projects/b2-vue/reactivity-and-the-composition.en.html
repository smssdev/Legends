Practice projects

Before each project, write down every piece of state you plan to keep, then cross out each one that can be calculated from the others. What remains goes in refs; the rest becomes computed.

Project {{n}}.1 · Easy

A counter with steps and undo

A counter that adds or subtracts a chosen step, shows its history, and can undo any number of changes.

You will practise: minimal state, computed, changing arrays in place, and v-model.number.

  1. Keep only two refs: the step, and the history of values, starting with [0].
  2. Make the current value a computed: the last item of the history.
  3. Each button pushes a new value onto the history; “Undo” pops one, and is disabled when only the first value is left.
  4. Bind the step with v-model.number, so it is a number, not text.
  5. Give the value aria-live="polite", so screen readers announce the new number.

Hint: because the history is the state, undo is one line. Had you stored the value and changed it with +=, undo would need a second list, kept in step with the first by hand.









Project {{n}}.2 · Medium


A task list that remembers


A task list that saves itself in the browser, and comes back after a reload, safely.


You will practise: v-model on text and checkboxes, a deep watcher, localStorage, and defensive loading.


    

  1. Load the tasks once, when the component starts, inside a try: saved data can be missing, broken or from an older version.
    2. 

  2. Bind the new task’s text with v-model, and add it on @submit.prevent, so Enter works and the page does not reload.
    3. 

  3. Bind each checkbox straight to task.done with v-model: Vue changes the object in place.
    4. 

  4. Save with watch(tasks, save, { deep: true }). Without deep, ticking a box would not be noticed, because the array itself did not change.
    5. 

  5. Show how many tasks are left with a computed, and add a button that removes the done ones.
    6. 



Hint: deep: true walks the whole structure on every change. That is fine for a task list; for thousands of items, save less often, or watch a smaller part.








Project {{n}}.3 · Challenge


Search as you type, without races


Search products while the user types, and never show the results of an old query, even when a slow answer arrives after a fast one.


You will practise: watchers with async work, onWatcherCleanup, AbortController, and loading states announced to screen readers.


    

  1. Use the pretend API below. Like a real search, it answers short queries more slowly, so “b” can arrive after “bit”.
    2. 

  2. Watch the query. For an empty query, clear the results and stop.
    3. 

  3. For each search, create an AbortController, and register controller.abort() with onWatcherCleanup. The next keystroke cancels the previous request.
    4. 

  4. Await the results inside try; an aborted request rejects, and the catch simply ignores it.
    5. 

  5. Show “Searching for…” and the number of results with role="status".
    6. 



Hint: type “bit” quickly with and without the cleanup line. Without it, you will sometimes see the results for “b” replace the results for “bit”: a race condition, one of the most common bugs in real apps.
