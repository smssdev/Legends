Practice projects

Build these as the first pieces of your own small design system: one folder of tokens, one stylesheet generated from them, and a few components that use nothing else.

Project {{n}}.1 · Easy

Badges and alerts from tokens

Two small components that show status: a badge for short labels and an alert for messages, each with four tones and no colour of its own.

You will practise: tone props with union types, semantic tokens, and choosing the right live-region role.

  1. Add soft background tokens for each tone (success-soft, warning-soft, danger-soft) and the matching text tokens, in both themes.
  2. Write the CSS classes .badge-… and .alert-… using only those tokens.
  3. Write Badge with a tone prop and children.
  4. Write Alert: an icon hidden from screen readers, the message, and a role: alert for errors, which interrupts, and status for the others, which waits for a pause.
  5. Never let colour carry the meaning alone: the words “Paid” and “Pending”, and the icons, say it too.

Hint: using role="alert" for everything sounds safe, but it interrupts the user for every small notice. Keep interruptions for things that really need attention now.










Project {{n}}.2 · Medium


A switch that works both ways


An on/off switch that can be used controlled or uncontrolled, works with the keyboard and screen readers, and is clear in every theme.


You will practise: the controlled/uncontrolled pattern, role="switch" with aria-checked, logical CSS properties, and checking states in every theme.


    

  1. Accept checked, defaultChecked and onChange. If checked is given, the parent owns the value; otherwise the component keeps its own.
    2. 

  2. Render a real <button type="button"> with role="switch" and aria-checked. Enter and Space work for free.
    3. 

  3. Draw the track and thumb with tokens, and move the thumb with inset-inline-start, so it slides the right way in Arabic too.
    4. 

  4. Give the off state an outline and the on state a fill. Check both in the dark theme: when this book was written, the first version looked the same on and off in dark mode, until the screenshot showed it.
    5. 

  5. Use it three ways: uncontrolled with defaultChecked, uncontrolled off, and controlled, where it switches the theme of its own panel.
    6. 



Hint: never change from uncontrolled to controlled during a component’s life (from checked={undefined} to checked={true}). React warns about it, because it is almost always a bug: decide once, in the parent.












Project {{n}}.3 · Challenge


A contrast guard for the tokens


A script that checks every important text-and-background pair in every theme against WCAG, and fails the build when one is too weak.


You will practise: reading JSON in Node, the contrast formula, typed tuples, and using the exit code to stop a pipeline.


    

  1. Read tokens.json, and write luminance and contrast from the formula in Book 1.
    2. 

  2. List the pairs that are really used together, as [foreground, background] tuples of semantic names.
    3. 

  3. For each theme and each pair, resolve both names to colours, compute the ratio, and print it with ✓ or ✗.
    4. 

  4. Set process.exitCode = 1 if any pair is below 4.5, so that npm run check and CI stop.
    5. 

  5. Add it to your check script, then try to break it: make text-muted lighter in the light theme and watch it fail.
    6. 



Hint: this is how a design system stays accessible as it grows: not by people remembering the rules, but by a check that runs every time anything changes.
