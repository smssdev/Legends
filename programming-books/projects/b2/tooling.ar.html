مكتبة أدوات صغيرة بواجهة عامة

نظّم الدوال المساعدة في وحدات، وقرّر أيها يحق لباقي التطبيق استخدامه.

ستتدرب على: التصديرات المسماة، وإعادة التصدير، وملف «البرميل»، وإبقاء بعض الكود داخلياً.

  1. أنشئ مجلد modules فيه text.mjs (slugify وtruncate) وnumbers.mjs (clamp وpercent).
  2. slugify تحوّل العنوان إلى جزء من رابط: حروف صغيرة، وبلا مسافات في الطرفين، وكل تتابع من الرموز الأخرى يصير - واحدة. والنمط \p{L} يعني «أي حرف في أي لغة»، فيعمل مع العربية أيضاً.
  3. أضف internal.mjs فيه دالة مساعدة تُستخدم داخل المجلد فقط.
  4. اكتب index.mjs يعيد تصدير الدوال العامة الأربع، دون الداخلية.
  5. في app.mjs استورد من ./index.mjs فقط، وجرّب كل دالة.

تلميح: البرميل وعد لباقي الفريق: «هذه الدوال ثابتة، وكل ما عداها قد يتغير». فأبقِه صغيراً.

أمر واحد يفحص كل شيء


أعطِ مشروعك سكربت check يشغّل فاحص الأنواع والمدقق والمنسّق بالترتيب، ويتوقف عند أول مشكلة.


ستتدرب على: سكربتات npm، و&& لربط الأوامر، وقواعد ESLint، ومعرفة أي أداة فشلت.


    

  1. ثبّت ESLint وtypescript-eslint وPrettier كما في القسم {{n}}.4، وحل تعارض إصدار TypeScript إن ظهر.
    2. 

  2. أضف السكربتات بـ npm pkg set: lint وformat وcheck، وcheck هي tsc && eslint src && prettier --check src.
    3. 

  3. أضف ملفاً يستخدم var، وشغّل npm run check. ولاحظ أن tsc نجح بصمت وأن ESLint أوقف السلسلة.
    4. 

  4. أصلح المشكلة وشغّل الفحص من جديد حتى ينجح.
    5. 

  5. اجعلها عادة: شغّل npm run check قبل كل git commit.
    6. 



تلميح: && تشغّل الأمر التالي فقط إن نجح الذي قبله. فضع الفحوص الأسرع أولاً لتعرف المشكلات أبكر. وكثير من الفرق تشغّل هذا السكربت تلقائياً بخطاف Git (Git hook).

إعدادات لكل بيئة


استخدم عنوان واجهة برمجية أثناء التطوير وآخر في الإنتاج، واقرأهما في وحدة واحدة بالأنواع، وأثبت أيهما استخدمه البناء.


ستتدرب على: ملفات .env، وimport.meta.env، والفشل المبكر عند نقص الإعدادات، وفحص مخرجات البناء.


    

  1. أنشئ .env.development و.env.production، في كل منهما VITE_API_URL مختلف.
    2. 

  2. اكتب src/config.ts، الملف الوحيد الذي يقرأ import.meta.env. فإن كان العنوان ناقصاً ارمِ خطأً برسالة مفيدة فوراً.
    3. 

  3. صدّر كائن config واحداً للقراءة فقط، واستورده حيثما احتجت العنوان.
    4. 

  4. شغّل npm run dev وتحقق من عنوان التطوير في Console، ثم ابنِ.
    5. 

  5. ابحث في JavaScript المبنية بـ grep لتتأكد أن عنوان الإنتاج، وهو وحده، دخلها.
    6. 



تلميح: الخطوة 5 هي طريقتك لإثبات ما في بنائك حقاً. واستخدم الحيلة نفسها لتتأكد أن سراً لم يتسلل: فإن وجدته بـ grep فسيجده أي أحد.
