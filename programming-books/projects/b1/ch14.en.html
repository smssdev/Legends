Practice projects: bug hunts

In this chapter the projects are reversed: the code is already written, and it is broken. Type each program as it is, run it, and see the bug for yourself. Then use the method from section 14.6 (read, reproduce, narrow down, fix, test) until your output matches the fixed one. Professionals spend more time doing this than writing new code.

Project 14.1 · Easy

The greeting that will not start

The program crashes before it prints anything. Read the error message and fix it with a single character.

You will practise: reading an error message from top to bottom: the line, the caret, the type and the description.





    

  1. Find the type of error. A ReferenceError means “I do not know this name”.
    2. 

  2. Find the line and the caret ^: they point at the exact name JavaScript could not find.
    3. 

  3. Compare that name, letter by letter, with the variable you created at the top. JavaScript is case-sensitive.
    4. 

  4. Fix it, run the program again, and make sure the output below appears.
    5. 



Hint: most errors you will ever meet are typos. Your editor can help: when you click on a variable, it highlights every place with the same name. A name that does not light up is a typo.

Project 14.2 · Medium


The checkout that cannot add


No error at all, but the total is nonsense. Find the two bugs hiding in five lines.


You will practise: bugs without errors, tracing values with console.log, the difference between text and numbers, and off-by-one loops.






    

  1. Read the wrong total carefully. Numbers stuck together like 01204535 are a clue: something is joining text, not adding numbers.
    2. 

  2. Add console.log(i, list[i], typeof list[i]) inside the loop and run again.
    3. 

  3. Bug 1: the prices are strings, so + glues them. Convert each one with Number(…).
    4. 

  4. Bug 2: the last line of your trace shows i equal to 3 and the value undefined. The array has no item 3. Change <= to <.
    5. 

  5. Remove your console.log lines, run once more, and check the result by hand: 120 + 45 + 35 = 200.
    6. 



Hint: NaN (“not a number”) spreads like a stain: any sum that touches it becomes NaN. When you see it, look for the first undefined or text that went into a calculation.

Project 14.3 · Challenge


The order that breaks the list


The first order prints, then the program dies. Follow the stack trace back to the cause, and fix it so every order prints.


You will practise: reading a stack trace, finding bad data rather than bad code, and guarding against missing values.






    

  1. Read the stack from the top: the crash is in label, which was called by printAll, which was called from line 17.
    2. 

  2. The message says it could not read name of undefined. So in order.customer.name, the undefined is order.customer.
    3. 

  3. One order printed before the crash, so the problem is the second order. Look at the data: order 2 has no customer.
    4. 

  4. Decide what should happen. Here a missing customer is a guest, so add an if (!order.customer) at the start of label and return a “guest” line.
    5. 

  5. Run again. All three orders should print, and the program should finish normally.
    6. 



Hint: the line that crashes is often not the line that is wrong. The code in label was fine; the data was not what it expected. Real data from users and servers is always missing something, so professionals check before they read deep inside an object.
