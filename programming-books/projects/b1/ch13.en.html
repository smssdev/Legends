Practice projects

Waiting is part of every real app: for a timer, for a file, for a server on the other side of the world. These projects teach you to wait without freezing, to wait for several things at once, and to survive when the answer never comes.

Project 13.1 · Easy

A countdown that waits politely

Count down from 3 with a pause between numbers, then say “Go!”, and discover what the rest of the program does while it waits.

You will practise: wrapping setTimeout in a promise, await inside a loop, and the order in which async code runs.

  1. Copy the wait(ms) helper from this chapter: it returns a promise that resolves after ms milliseconds.
  2. Write async function countdown(from) with a for loop that prints n, then await wait(200).
  3. After the loop, print “Go!”.
  4. Call countdown(3), and on the next line print “Get ready…”.
  5. Before you run it, guess the order of the lines. Then run it and explain the surprise in one sentence.

Hint: an async function runs until its first await, then hands control back. That is why “Get ready…” sneaks in after the 3.

Project 13.2 · Medium


Breakfast: one by one, or all at once?


Make tea, toast and eggs, first one after another and then all at the same time, and measure the difference.


You will practise: functions that return values through promises, Promise.all, and timing code with Date.now().


    

  1. Write async function make(item, ms) that waits ms and returns item.
    2. 

  2. Write seconds(start): the time since start, rounded to one decimal place.
    3. 

  3. One after another: await the three dishes in turn (300, 400 and 500 ms) and print the time.
    4. 

  4. All at once: start all three inside Promise.all([…]), await it, and print the time again.
    5. 

  5. Promise.all gives back an array of results in the same order. Print them joined with " + ".
    6. 



Hint: one by one takes the sum of the times; all at once takes only the longest. When a page needs three independent pieces of data, load them together.

Project 13.3 · Challenge


A weather report that does not break


Ask a small weather API about three cities, one of which does not exist, and finish the report anyway.


You will practise: fetch, checking response.ok, throwing your own errors, and try/catch inside a loop.


    

  1. Build the tiny server the same way as in section 13.3: /api/weather/cairo returns JSON, and an unknown city returns 404.
    2. 

  2. Reuse getJson(url): it throws an Error when response.ok is false.
    3. 

  3. Write async function report(names): print a loading message, then loop over the names and await each city.
    4. 

  4. Put the try/catch inside the loop, so one bad city prints “no data” and the loop carries on.
    5. 

  5. Print a final line so the user knows the report is complete. Then try moving the try outside the loop and see what is lost.
    6. 



Hint: where you put try decides how much one failure can break. Around the whole loop, one bad city stops everything; around each request, it costs only one line.
