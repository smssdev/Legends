Project 4.1 · Easy

URL inspector

Take a list of web addresses apart and print the host, path, query and fragment of each one.

You will practise: the parts of a URL and the URL object.

  1. Before writing code, copy the three addresses from the solution onto paper and underline each part in a different colour, as in Figure 4.1.
  2. Create inspect-urls.js with an array of the three addresses.
  3. For each address, create new URL(text) and print hostname, pathname, search and hash, separated by "|".
  4. Some addresses have no query or fragment, so those properties are empty. Print "-" instead, with url.search || "-".
  5. Compare the output with your paper. Did you find every part correctly?
for (const text of addresses) {
  const url = new URL(text);
  console.log(url.hostname, "|", url.pathname, "|", url.search || "-", "|", url.hash || "-");
}

Hint: for (const text of addresses) repeats the code for each address (Chapter 9), and || picks the right side when the left side is empty (Chapter 8).

A three-page website with a 404 page


Extend your web server so that it serves a home page, an About page and a Contact page, and answers 404 Not Found for anything else.


You will practise: paths, status codes, and how a server decides what to send.

    4. 

  4. Test four paths, including one that does not exist, and print the path, the status and the page.
    5. 

  5. Remove server.close(), open http://localhost:3002/about in your browser, and look at the status in the Network tab.

const page = pages[request.url];
if (page) {
  response.writeHead(200, { "Content-Type": "text/html; charset=utf-8" });
  response.end(page);
} else {
  response.writeHead(404, { "Content-Type": "text/html; charset=utf-8" });
  response.end("<h1>Page not found</h1>");
}


Hint: an object used like this is a small “dictionary” from paths to pages. Real servers do the same thing with many more pages; it is called routing.
