مكوّن Field قابل لإعادة الاستخدام

أكمل نموذج التواصل من هذا الفصل، وتأكد أن لكل حقل تسمية، وأنه مربوط بخطئه، ويأخذ التركيز عند الخطأ.

ستتدرب على: register، وformState.errors، ومكوّن غلاف بـ cloneElement، وخصائص سهولة الوصول.

  1. اكتب المخطط واستنتج النوع. وأعطِ كل قاعدة رسالة تشرح الإصلاح.
  2. اكتب Field: تسمية، والحقل ممرراً children، وفقرة الخطأ بمعرّف.
  3. داخل Field أضف aria-invalid وaria-describedby إلى الحقل فقط حين يوجد خطأ.
  4. استخدم mode: "onTouched"، ثم جرّب كل خطأ: اترك الحقول فارغة، واكتب اسماً قصيراً، وبريداً ناقصاً، وعمر 9.
  5. اختبر بقارئ شاشة (VoiceOver أو NVDA أو TalkBack): انتقل بـ Tab إلى حقل خاطئ واستمع. يجب أن تُقرأ الرسالة مع التسمية.

تلميح: تنقل React Hook Form التركيز إلى أول حقل خاطئ عند الإرسال وحدها، لأن register تعطيها مرجعاً لكل حقل. وهذا سبب آخر لاستخدام register بدل كتابة الحقول باليد.

التسجيل، مع رد من الخادم

نموذج تسجيل بكلمة مرور وتأكيدها ومربع للشروط، يعرض أيضاً رسالة الخادم «البريد مستخدم» على حقل البريد.

ستتدرب على: القواعد التي تقارن حقلين بـ refine، وz.literal(true) لمربع إلزامي، وsetError، وisSubmitting.

  1. اكتب المخطط: بريد، وكلمة مرور من 8 أحرف على الأقل فيها رقم، وتأكيد، وterms: z.literal(true, "…").
  2. قارن كلمتي المرور بـ .refine(…, { path: ["confirm"] })، فيظهر الخطأ تحت حقل التأكيد.
  3. اكتب createAccount وهمية ترد بـ { ok: false, field, message } لبريد معيّن.
  4. في onSubmit استدعها، وعند الفشل استدعِ setError(result.field, { message }, { shouldFocus: true }).
  5. أعطِ كل حقل كلمة مرور autoComplete="new-password"، فتعرض مديرات كلمات المرور إنشاء واحدة قوية.

تلميح: صمّم واجهتك البرمجية لتسمّي أخطاؤها الحقل الذي تخصه، كما تفعل createAccount هنا. فتضع الواجهة كل خطأ من الخادم في مكانه بسطر كود واحد.
