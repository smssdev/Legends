متجر يتعثر بلطف

أعطِ متجر بِت صفحة للأخطاء، وصفحة 404 أفضل للمنتجات المفقودة، وحالة تحميل لكل جزء بطيء، حتى لا يرى المستخدم أبداً شاشة بيضاء أو تفاصيل خطأ تقنية.

ستتدرب على: error.tsx، وnot-found.tsx في مستويات مختلفة، وloading.tsx، و<Suspense> حول جزء بطيء واحد.

  1. اكتب app/error.tsx مكوّنَ عميل يستلم { error, reset }، ويعرض رسالة ودودة، ويقدم زر «حاول مجدداً» يستدعي reset().
  2. اجعل getProduct ترمي خطأ لمعرّف واحد، وتأكد أن منطقة المحتوى وحدها تُستبدل بينما يبقى شريط التنقل.
  3. أضف app/products/[id]/not-found.tsx يقول إن المنتج غير موجود ويعيد رابطاً إلى القائمة. وتظل العناوين المجهولة في غير ذلك تستخدم صفحة 404 العامة.
  4. أضف إلى صفحة المنتج جزء «المراجعات» البطيء (انتظر تأخيراً مدته 1.5 ثانية)، وغلّفه وحده بـ <Suspense> مع هيكل تحميل صغير، فيظهر باقي الصفحة فوراً.

تلميح: يلتقط error.tsx أخطاء الصفحات تحته، لا أخطاء الإطار في المجلد نفسه. ولالتقاط أخطاء الإطار الجذري أيضاً، في Next.js ملف خاص اسمه global-error.tsx، ويجب أن يكتب <html> و<body> بنفسه.

مدونة ثابتة تحبها محركات البحث

مدونة مقالاتها ملفات Markdown داخل المشروع، تُبنى كلها وقت البناء، ولكل مقال عنوانه ووصفه، ومعها خريطة للموقع وملف robots.

ستتدرب على: قراءة الملفات في مكوّن خادم، وgenerateStaticParams، وgenerateMetadata، وsitemap.ts، وrobots.ts.

  1. ضع ثلاث مقالات في content/، يبدأ كل منها بعنوان وتاريخ في أسطره الأولى. واكتب lib/posts.ts فيه getPosts() وgetPost(slug) باستخدام node:fs/promises.
  2. اجعل app/blog/page.tsx تسرد المقالات من الأحدث، وapp/blog/[slug]/page.tsx تعرض مقالاً واحداً. وحوّل Markdown إلى HTML بمكتبة مثل marked، على الخادم.
  3. أضف generateStaticParams وgenerateMetadata، واستدعِ notFound() للمعرّفات المجهولة.
  4. أضف app/sitemap.ts الذي يُرجع عنوان كل مقال، وapp/robots.ts الذي يشير إلى خريطة الموقع. وافتح /sitemap.xml لتتأكد.
  5. ابنِ، وتأكد أن كل مقال ○ أو ◐ في جدول المسارات، ثم تأكد بـ curl أن عنوان المقال داخل HTML.

تلميح: مكتبة Markdown تعمل على الخادم فقط، فلا تضيف شيئاً إلى JavaScript المتصفح. وهذه ميزة هادئة لمكونات الخادم: المكتبات الثقيلة للتنسيق أو التواريخ أو تلوين الكود مجانية لمستخدميك.

أسعار يغيّرها المدير

صفحة إدارة محمية يغيّر فيها صاحب المتجر سعر منتج، فتعرض صفحات المنتجات المخزنة السعر الجديد فوراً، ولا يستطيع أحد غيره تغيير شيء.

ستتدرب على: ملفات تعريف الارتباط، وredirect، وإجراءات الخادم مع فحص الصلاحيات، وcacheTag وupdateTag.

  1. علّم getProducts وgetProduct بـ "use cache" وcacheTag("products")، واحفظ الأسعار في Map على مستوى الوحدة تستطيع دالة updatePrice(id, price) تغييرها.
  2. اكتب إجراء خادم لتسجيل الدخول يقارن كلمة مرور بـ process.env.ADMIN_PASSWORD، وعند النجاح يضع ملف تعريف ارتباط httpOnly وsecure وsameSite بـ cookies() من next/headers.
  3. اجعل app/admin/page.tsx تقرأ ملف تعريف الارتباط وتستدعي redirect("/admin/sign-in") إن لم يوجد.
  4. اكتب الإجراء changePrice. يفحص ملف تعريف الارتباط مرة أخرى (ففحص الصفحة لا يحمي الإجراء)، ويتحقق بـ zod أن السعر عدد صحيح موجب، ويستدعي updatePrice ثم updateTag("products").
  5. غيّر سعراً، وافتح صفحة المنتج، وتأكد أن السعر الجديد ظاهر دون بناء جديد.

تلميح: التطبيق الحقيقي يحفظ الأسعار في قاعدة بيانات والجلسات الموقّعة في مكتبة، لكن الشكل واحد: فحص الصلاحية يعيش داخل كل إجراء، لا في الصفحة التي تعرض النموذج وحدها.
