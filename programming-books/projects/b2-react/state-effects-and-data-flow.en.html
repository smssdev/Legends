Practice projects

Before each project, write down the state you will keep, in one line per variable. Then check every line against the three questions in section {{n}}.3. If the list gets shorter, you are doing it right.

Project {{n}}.1 · Easy

A counter with steps and undo

A counter that moves by a chosen step and can undo any number of moves.

You will practise: choosing the minimal state, updater functions, deriving the current value, and a controlled number input.

  1. Keep two pieces of state: the step, and the history, an array of every value so far, starting at [0].
  2. The current value is not state: it is history.at(-1).
  3. “+” and “−” append a new value with an updater: setHistory((h) => [...h, last + by]).
  4. “Undo” removes the last value, but never the first one. Disable the button when there is nothing to undo.
  5. Show the whole history under the counter.

Hint: storing history instead of only the current value is how real editors implement undo. Because each entry is a new value and nothing is ever changed, going back is just removing the last entry.

Project {{n}}.2 · Medium

A task list that remembers

Rebuild the tasks app from Book 1 in React, with the reducer from this chapter, and keep the tasks after the page is closed.

You will practise: useReducer with a lazy initial state, an effect that saves to localStorage, a form, and a ref to keep the focus in the input.

  1. Import tasksReducer. Create the state with useReducer(tasksReducer, [], load): the third argument runs load only once, on the first render.
  2. Write load with try/catch: saved data may be missing or broken.
  3. Save with an effect whose dependency is [tasks], so it runs after every change.
  4. Keep the text of the new task in its own state, and dispatch added on submit. Then clear the text and move the focus back to the input with a ref.
  5. Derive the number of tasks left, and add a “Clear done” button.

Hint: saving to localStorage is a perfect example of an effect: it keeps something outside React, the browser’s storage, in step with the state. Compare this component with the Book 1 version: the logic is the same, but the code that updates the page by hand has disappeared.

Project {{n}}.3 · Challenge

Search as you type, without races

Search products while the user types, wait for a short pause before asking the server, and never show an old answer.

You will practise: writing your own hook, effects with cleanup, AbortController, and a discriminated union for the result.

  1. Write a custom hook, useDebounced(value, ms): it returns the value only after it has stopped changing for ms milliseconds. Inside, an effect starts a timer and its cleanup clears it.
  2. Model the result as idle | loading | done | error, with the query inside each state that needs it.
  3. In an effect that depends on the debounced query, create an AbortController, set loading, and call searchProducts(query, controller.signal).
  4. Return () => controller.abort() as the cleanup. In the catch, ignore the error if the request was aborted.
  5. Render each state: a “Searching…” line, the results, “No products match”, or the error. Use the fake API, which answers short queries more slowly, and type quickly to watch old requests being cancelled.

Hint: a custom hook is just a function whose name starts with use and which calls other hooks. It is the React way to reuse stateful logic, as the next chapters will show again and again.
