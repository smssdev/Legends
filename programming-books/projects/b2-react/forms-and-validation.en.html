Practice projects

For each form, write the schema first, with every error message, and test it with safeParse in Node before you build any screen. When the rules are right, the form is mostly wiring.

Project {{n}}.1 · Easy

A reusable Field component

Finish the contact form from this chapter, and make sure every field is labelled, linked to its error, and focusable on error.

You will practise: register, formState.errors, a wrapper component with cloneElement, and accessibility attributes.

  1. Write the schema and infer the type. Give every rule a message that explains the fix.
  2. Write Field: a label, the input passed as children, and the error paragraph with an id.
  3. Inside Field, add aria-invalid and aria-describedby to the input only when there is an error.
  4. Use mode: "onTouched", then try every mistake: leave fields empty, type a short name, a broken email, an age of 9.
  5. Test with a screen reader (VoiceOver, NVDA or TalkBack): tab to a wrong field and listen. The message should be read with the label.

Hint: React Hook Form moves the focus to the first wrong field on submit by itself, because register gives it a ref to every input. That is one more reason to use register rather than writing inputs by hand.

Project {{n}}.2 · Medium

Sign up, with an answer from the server

A sign-up form with a password, its confirmation and a terms box, which also shows the server’s “email already used” message on the email field.

You will practise: rules that compare two fields with refine, z.literal(true) for a required checkbox, setError, and isSubmitting.

  1. Write the schema: an email, a password of at least 8 characters with a digit, a confirmation, and terms: z.literal(true, "…").
  2. Compare the passwords with .refine(…, { path: ["confirm"] }), so the error appears under the confirmation field.
  3. Write a pretend createAccount that answers with { ok: false, field, message } for one particular email.
  4. In onSubmit, call it, and on failure call setError(result.field, { message }, { shouldFocus: true }).
  5. Give each password input autoComplete="new-password", so password managers offer to create a strong one.

Hint: design your API so that its errors name the field they belong to, as createAccount does here. Then the frontend can put every server error in the right place with one line of code.
