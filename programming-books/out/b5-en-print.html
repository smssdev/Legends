How to Use This Book

This book takes you from your first line of Dart to your first app in Google Play and the App Store. It is written for people who already know the basics of programming: values and variables, decisions, loops and functions. If you read Parts I and III of Code from Zero, the first book of this series, you are ready. If you learned somewhere else, in any language, you are ready too: the book explains everything that is new in Dart and in Flutter from the beginning, and points out where they differ from JavaScript.

What you need

  • A computer with Windows, macOS or Linux, with at least 8 GB of memory: the Android emulator needs room. To build apps for the iPhone you need a Mac, because Apple’s tools only run there; everything else in the book works on any of the three.
  • An Android phone or an iPhone is welcome but not required: an emulator on your computer does the same job.
  • Free tools that you will install in Chapter 1: Flutter (which includes Dart), Visual Studio Code, and Android Studio.

How the book is organised

The fifteen chapters are grouped in three parts. Read them in order: each one builds on the ones before.

  • Dart installs Flutter and teaches the language every Flutter app is written in: its basics, classes and null safety, collections, and code that waits for things with futures and streams.
  • Building Screens is about what the user sees: widgets, layouts that fit every screen, lists, images and themes, moving between screens, and forms.
  • Real Apps adds what real apps need: state that changes, data from the internet, data saved on the phone, Arabic and English with right-to-left layouts, a complete notes app that uses everything, and publishing to the two stores.

Every chapter

Each chapter follows the same pattern, so you always know where you are: what you will learn; explanations built on real, running examples; a quick check in the middle; boxes with tips, traps and professional habits; a table of common mistakes; a summary; three practice projects (easy, medium and challenge) with steps and hints; and exercises at three levels. Answers to the quick checks follow each summary, and answers to the exercises are at the end of the book.

The projects matter more than anything else. Reading about a skill is not having it. Build at least one project per chapter before moving on.

1.1 What Flutter is

Flutter is a free toolkit, made by Google, for building apps. You write your app once, in a language called Dart, and Flutter turns it into an Android app, an iPhone app, a website, or a desktop program for Windows, macOS and Linux. Each of these is called a platform. This book focuses on the two that matter most for most people: Android and iOS, the system of the iPhone.

Before toolkits like Flutter, a company that wanted an app on both kinds of phone usually built it twice: once in Kotlin or Java for Android, and once in Swift for iOS, often by two different teams. Every feature was written twice, tested twice, and had its bugs fixed twice. Flutter lets one developer, or one team, write it once.

Flutter has one unusual idea that explains much of what you will see in this book: it draws every pixel of the app itself. Many other toolkits ask the phone to draw its own buttons and text boxes, so the app looks slightly different on each phone. Flutter brings its own drawing engine instead, the same one on every platform, so a button looks and behaves exactly as you designed it, everywhere. That is also why a screenshot of a Flutter app running in a browser looks exactly like the same app on a phone.

The language, Dart, was also made by Google. It looks familiar if you know JavaScript, but it checks your types before the program runs, as you will see in Chapter 2. You do not install Dart separately: it comes inside Flutter.

Did you know?

Dart was announced in 2011 as a language for the web. Flutter 1.0 came out in December 2018, with Dart as its only language, and gave Dart a second life: today most Dart code in the world is Flutter apps, running on phones.

Building mobile apps needs more tools than building web pages, because each phone system comes with its own tools from its own company. Here is the whole list. You do not need all of it today; the next sections install it in order.

1.3 Installing the Flutter SDK

Installing Flutter means three things: downloading it, putting it in a folder, and telling your terminal where to find it.

  1. Open docs.flutter.dev, choose Get started, then your system (Windows, macOS or Linux). Follow the instructions for Android as your first target. Install Git first if the page asks for it.
  2. Download the Flutter SDK, a large zip file, and unzip it into a folder whose path has no spaces and does not need administrator rights. Good choices are C:\dev\flutter on Windows and ~/development/flutter on macOS and Linux.
  3. Add the bin folder inside it (for example C:\dev\flutter\bin) to your PATH, the list of folders where the terminal looks for commands. The page shows how for your system.
  4. Close every terminal and open a new one. Then ask Flutter who it is:
Terminal
# Which Flutter, and which Dart inside it?
$ flutter --version
Flutter 3.50.1 • channel stable • https://github.com/flutter/flutter.git
Framework • revision ae9b586f34 (3 days ago) • 2026-11-18 17:01:07 -0800
Engine • hash 51379e6df48ea8ee7205623b90fe66491cad8df3 (revision 4d35714800) (3 days ago) • 2026-11-18 01:50:07.000Z
Tools • Dart 3.14.0 • DevTools 2.61.0

Four lines, and each one means something. The first is the version of Flutter, 3.50.1, from the stable channel: the releases that are tested and safe for real apps. The next two say exactly which code of the framework and the engine you have, with the dates they were made. The last line is the most interesting for the next chapter: Flutter 3.50.1 brings Dart 3.14.0 with it, and DevTools, a set of tools for looking inside a running app that you will meet later.

Watch out

If the terminal answers flutter: command not found (or, on Windows, “not recognized as an internal or external command”), the PATH is wrong, or the terminal was opened before you changed it. Open a new terminal first; that fixes it most of the time. If not, check the path letter by letter: it must end in flutter\bin or flutter/bin.

Tip

Install Visual Studio Code now if you do not have it, then the Flutter extension from its Extensions view (it installs the Dart extension with it). The extension can also download the Flutter SDK for you, when you create your first project from the Command Palette. Either way ends in the same place.

Professional habit

Fix the doctor’s report one line at a time, from the top, and run flutter doctor again after each fix. Fix only the platforms you build for: a red line for Linux desktop on a phone developer’s laptop is not a problem. When something strange happens months later, run the doctor first; it is the fastest way to find out what changed.

Installing the Android tools

  1. Download Android Studio from developer.android.com/studio and install it. Open it once, and let its setup wizard install the Android SDK.
  2. In Android Studio, open the SDK Manager, and on the SDK Tools tab tick Android SDK Command-line Tools, then apply.
  3. Accept Google’s licences for the SDK, from the terminal: flutter doctor --android-licenses. Read each licence and answer y.
  4. Create an emulator: in Android Studio, open the Device Manager, add a virtual device, choose a recent phone (a Pixel is a good choice) and a recent system image, and finish.
  5. Run flutter doctor again. The Android line should now show [✓].

On a Mac: the iOS tools

Install Xcode from the Mac App Store; it is large, so give it time. Open it once to finish its setup, then run flutter doctor and do exactly what the Xcode section of the report says, one line at a time. The report names the commands for your version of Xcode, which is safer than any list printed in a book.

1.6 Reading main.dart

The new project is a small counter app: a number in the middle of the screen, and a button that adds one to it. Its code, in lib/main.dart, is about 120 lines long, most of them comments that explain the code. Here is how it starts:

lib/main.dart (from the template)
import 'package:material_ui/material_ui.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  // This widget is the root of your application.
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Flutter Demo',
      theme: ThemeData(
        // This is the theme of your application.
        //
        // TRY THIS: Try running your application with "flutter run". You'll see
        // the application has a purple toolbar. Then, without quitting the app,
        // try changing the seedColor in the colorScheme below to Colors.green
        // and then invoke "hot reload" (save your changes or press the "hot

        // the command line to start the app).

Do not try to understand every word yet: the next chapters explain them all. For now, look at the shape. The first line imports the Material widgets, so this file can use them. Then comes main, the function where every Dart program starts. It calls runApp, which takes a widget and shows it on the screen. A widget is a description of a piece of the screen: a text, a button, a whole page. In Flutter, everything you see is a widget, and widgets are built from smaller widgets, like boxes inside boxes. Chapter 5 is all about them.

The counter is a fine example, but it is too much to read on your first day. Replace the whole content of lib/main.dart with this much smaller app:

lib/main.dart
import 'package:material_ui/material_ui.dart';

// Every Dart program starts by running main().
void main() {
  runApp(const HelloBitApp());
}

// The whole app is one widget: a description of what to show.
class HelloBitApp extends StatelessWidget {
  const HelloBitApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Hello Bit',
      home: Scaffold(
        appBar: AppBar(
          title: const Text('Hello Bit'),
          centerTitle: true,
          // The colour of the bar, and of the text on it.
          backgroundColor: Colors.indigo,
          foregroundColor: Colors.white,
        ),
        body: const Center(
          child: Text('Hello, Flutter!', style: TextStyle(fontSize: 32)),
        ),
      ),
    );
  }
}

Read it from the outside in, the way Flutter builds it:

  • main calls runApp with our app, HelloBitApp.
  • HelloBitApp is a StatelessWidget: a widget that never changes once it is shown. Its build method returns what it looks like.
  • MaterialApp is the frame of an app in Material style. Its home is the first screen.
  • Scaffold is the skeleton of one screen: here, a bar at the top (appBar) and the rest of the screen (body).
  • AppBar shows a title, centred, on an indigo bar with white text.
  • Center puts its one child in the middle of the space it has, and Text shows the greeting at 32 logical pixels.

Notice how the code is shaped like the screen: the bar and the body are inside the scaffold, which is inside the app. Notice also the commas at the end of almost every line. Dart allows a comma after the last item, and Flutter developers always put one there: the formatter then puts each item on its own line, and the code keeps the shape of the screen.

1.8 Hot reload

This is the moment Flutter developers fall in love with it. Leave the app running. In lib/main.dart, change Colors.indigo to Colors.teal, and the greeting to 'Hello, hot reload!'. Save the file, and press r in the terminal where flutter run is waiting (in VS Code, saving is enough: it reloads for you).

The terminal shows what happened:

Terminal
# lib/main.dart is saved with a new colour and text, then r is pressed
r
Performing hot reload...                                           179ms
Reloaded application in 180ms.
Application finished.

Hot reload sent only the changed code into the running app and rebuilt the screen in a fraction of a second (the terminal gives the exact time), without starting the app again. On a phone it is just as fast. You will change a colour, a size or a word, see it, and change it again, dozens of times a minute. This is how Flutter developers design screens: not by imagining, but by trying.

The other keys are worth knowing:

rHot reload: new code, same running app, values keptAlmost always
RHot restart: the app starts again from main, values lostWhen a change does not appear after r, such as a change inside main

import 'package:flutter_test/flutter_test.dart';
import 'package:hello_bit/main.dart';

void main() {

    await tester.pumpWidget(const HelloBitApp());
    expect(find.text('Hello, hot reload!'), findsOneWidget);
  });
}

testWidgets describes a test with a name. Inside, pumpWidget shows our app in a pretend screen, without any emulator, and expect checks that exactly one widget shows the greeting. Run the tests again:

2.2 Variables and their types

A variable is a name for a value, exactly as in Book 1. Dart gives you several ways to create one:

variables.dart
void main() {
  // Dart works out the type from the first value: score is an int, for ever.
  var score = 0;
  score = score + 10;
  print(score);

  String name = 'Sara';
  print(name);

  // final: set once, when the program runs.
  final joined = DateTime.now().year;
  print(joined > 2000);

  // const: known before the program runs, and never changes.
  const maxPlayers = 4;
  print(maxPlayers);
}

With var, Dart looks at the first value and decides the variable’s type: score starts as 0, so it is an int, a whole number. This is called type inference. You can also write the type yourself, as with String name. Either way, the type is fixed for ever: a variable that holds numbers can never hold text. See what happens if you try:

In JavaScript the same line would have run, and the bug would have appeared later, somewhere else, perhaps on a user’s phone.

Did you know?

Since Dart 2, every Dart program has been type safe: a variable declared as int can never hold anything else while the program runs. Dart’s compiler uses that promise to make your app faster, too.

final and const

Most values in a program never change after they are set. Dart has two words for them:

  • final: the value is set once, when the program reaches that line, and never changes after. It can come from a calculation, the clock, or the user.
  • const: the value is known before the program runs, written directly in the code, like 4 or 'Sara'. Dart can then build it once and share it.

In variables.dart, the year someone joined comes from the clock (DateTime.now()), so it can only be final. The maximum number of players is written in the code, so it can be const. Try to change a final:

2.7 switch and patterns

Dart’s switch is one of its best features, and much more powerful than JavaScript’s:

switch.dart
void main() {
  var size = 'M';

  // No break needed: Dart never runs into the next case.
  switch (size) {
    case 'S':
      print('Small cup');
    case 'M':
      print('Medium cup');
    case 'L':
      print('Large cup');
    default:
      print('Unknown size');
  }

  // A switch expression produces a value. The first pattern that matches wins.
  var day = 'friday';
  var kind = switch (day) {
    'friday' || 'saturday' => 'Weekend',
    _ => 'Workday',
  };
  print(kind);

  for (var score in [95, 83, 71, 40]) {
    var grade = switch (score) {
      // >= 90 is a pattern: it matches any value that is at least 90.
      >= 90 => 'A',
      >= 80 => 'B',
      >= 70 => 'C',
      >= 50 => 'D',
      // _ matches anything: the case for everyone else.
      _ => 'F',
    };
    print('$score -> $grade');
  }
}
Terminal
$ dart run switch.dart
Medium cup
Weekend
95 -> A
83 -> B
71 -> C
40 -> F

The first switch is a statement, like the one you know, with one improvement: there is no break. Each case ends where the next one starts, and Dart never runs into the next case by accident.

The second and third are switch expressions: they produce a value, which goes straight into a variable. Each line has a pattern on the left of => and a result on the right, and the first pattern that matches wins:

  • A plain value, such as 'friday', matches when the value is equal to it.
  • || between two patterns matches either of them.
  • >= 90 is a relational pattern: it matches any value that is at least 90. That makes grading one short, readable list.
  • _, the wildcard, matches anything. Put it last, for everyone else.

A switch expression must cover every possible value. If you remove the _ line from the grades, the program does not compile, because a score of 40 would have no grade. Dart calls this exhaustiveness checking, and in Chapter 3 you will see it catch real bugs.

const cake = 60;
const width = 26;

// The day decides the discount: 20% on Fridays, 10% on Saturdays.
int discountPercent(String day) => switch (day) {
  'friday' => 20,
  'saturday' => 10,
  _ => 0,
};

// One line of the receipt: name on the left, amount on the right.
String line(String name, int amount) =>
    name.padRight(width - 8) + amount.toString().padLeft(8);

void printReceipt({
  required String day,
  int lattes = 0,
  int cookies = 0,
  int cakes = 0,
}) {
  var subtotal = lattes * latte + cookies * cookie + cakes * cake;
  var discount = subtotal * discountPercent(day) ~/ 100;
  // Service is rounded to the nearest pound.
  var service = ((subtotal - discount) * 0.12).round();
  var total = subtotal - discount + service;

  print('=' * width);
  print('BIT CAFÉ · $day');
  print('-' * width);
  if (lattes > 0) print(line('$lattes × Latte', lattes * latte));
  if (cookies > 0) print(line('$cookies × Cookie', cookies * cookie));
  if (cakes > 0) print(line('$cakes × Cake', cakes * cake));
  print('-' * width);
  print(line('Subtotal', subtotal));
  if (discount > 0) print(line('Discount', -discount));
  print(line('Service 12%', service));
  print(line('To pay', total));
  print('=' * width);
}

void main() {
  printReceipt(day: 'friday', lattes: 2, cookies: 3);
  printReceipt(day: 'monday', cakes: 1, lattes: 1);
}

Summary

  • A Dart program starts in main, prints with print, ends statements with ;, and runs with dart run file.dart.
  • Every value has a type, checked before the program runs. var infers it from the first value; it never changes.
  • Prefer final (set once) and const (known before running); use var only for values that change.

3.1 Classes

A class describes a kind of value: what each value knows, and what it can do. Each value made from it is an object, or an instance of the class. Here is a menu item:

menu_item.dart
class MenuItem {
  // Fields: what every menu item knows. final, because an item never changes.
  final String name;
  final int price;

  // The constructor: this.name puts the first argument straight into the field.
  const MenuItem(this.name, this.price);

  // A method: a function that belongs to the item and can use its fields.
  int priceFor(int count) => price * count;

  // What print shows for an item.
  @override
  String toString() => '$name ($price EGP)';
}

void main() {
  var latte = const MenuItem('Latte', 45);
  var cookie = const MenuItem('Cookie', 20);
  print(latte);
  print(latte.name);
  print(cookie.priceFor(3));
}
Terminal
$ dart run menu_item.dart
Latte (45 EGP)
Latte
60
  • Fields are the variables inside each object: every menu item has its own name and price. They are final, because a menu item never changes after it is made.
  • The constructor makes objects. It has the class’s name, and this.name is Dart’s shortcut for “put this argument straight into the field name”. Because every field is final, the constructor can be const, and so can the items made with it.
  • priceFor is a method: a function that belongs to the object and can use its fields.
  • toString decides what print shows. Every class has one; @override says that we replace the default, which would only print Instance of 'MenuItem'.

You reach a field or a method with a dot: latte.name, cookie.priceFor(3). Notice that there is no new: in Dart you make an object by calling the constructor like a function.

Named parameters, getters and private fields

order.dart
class MenuItem {
  final String name;
  final int price;
  // Named parameters, as in Chapter 2: the call says which value is which.
  const MenuItem({required this.name, required this.price});

  // A getter: looks like a field, but is calculated each time.
  bool get isExpensive => price >= 50;
}

class Order {
  // _lines starts with _: private, only this file can touch it.
  final List<MenuItem> _lines = [];

  // Add one line to the order; the quantity starts at 1.
  void add(MenuItem item, [int count = 1]) {
    for (var i = 0; i < count; i++) {
      _lines.add(item);
    }
  }

  int get count => _lines.length;
  int get total => _lines.fold(0, (sum, item) => sum + item.price);
}

void main() {
  const latte = MenuItem(name: 'Latte', price: 45);
  const cake = MenuItem(name: 'Cake', price: 60);
  print(cake.isExpensive);

  var order = Order();
  order.add(latte, 2);
  order.add(cake);
  print('${order.count} items, Total: ${order.total} EGP');
}
Terminal
$ dart run order.dart
true
3 items, Total: 150 EGP

Three more tools appear in this program, and you will see all three in every Flutter app:

  • The constructor of MenuItem takes named parameters, {required this.name, required this.price}. Calls become self-explaining: MenuItem(name: 'Latte', price: 45). This is exactly how Flutter’s widgets are built: Text('Hi', style: ...) calls a constructor with named parameters.
  • A getter, written with get, looks like a field from outside (cake.isExpensive, without brackets) but runs code every time it is read. Order uses two, count and total, so they are always up to date.
  • A name that starts with an underscore, like _lines, is private: only code in the same file can use it. Other code can add to an order only through add, so nobody can break it from outside. This is called encapsulation.

The total uses fold, which walks the list carrying a value from one item to the next: it starts at 0, and for each item returns the sum so far plus the item’s price. Section 3.4 shows it again.

3.2 Null safety

Sometimes a value is simply not there: a customer without a nickname, a contact without a phone, a search with no result. Dart has a special value for “nothing”: null. In many languages any variable can be null at any time, and using one by accident crashes the program. Tony Hoare, who invented the null reference in 1965, later called it his “billion-dollar mistake”.

Dart solves it with null safety: a variable can hold null only if its type says so, with a question mark. String is always a string. String? is a string or null.

null-error.dart
void main() {
  String? nickname;
  print(nickname.length);
}
Terminal

Try accessing using ?. instead.
  print(nickname.length);

The compiler refuses to ask for the length of something that may not exist, and even suggests a fix. Dart gives you four tools to work with nullable values:

nullable.dart
void main() {
  // String? may hold a String, or null: nothing at all.
  String? nickname;
  print(nickname);

  // ?? gives the value on its right when the left is null.
  print(nickname ?? 'Guest');

  // ?. asks only when there is something to ask: null stays null.
  print(nickname?.length);

  // ??= sets a value only if there is none yet.
  nickname ??= 'Bito';
  print(nickname);

  String? other;
  // Inside this if, Dart knows nickname is not null.
  if (other != null) {
    print(other.length);
  } else {
    print('no nickname');
  }
}

  print(nickname!.length);

Professional habit

Treat every ! as a small promise you might break. Prefer an if check, ?? with a sensible default, or a type that is not nullable in the first place. When you do use !, be able to say in one sentence why the value can never be null there.

Did you know?

Dart added null safety in version 2.12, in 2021, and made it compulsory in Dart 3. Every package on pub.dev had to be updated; it was one of the largest migrations any language has done, and it is why Flutter apps rarely crash on a missing value.

3.3 Enums

When a value can only be one of a few fixed choices, such as the sizes of a cup, give the choices names with an enum (short for enumeration):

sizes.dart
// Each size knows how much it adds to the price.
enum CupSize {
  small(0),
  medium(5),
  large(10);

  final int extra;
  const CupSize(this.extra);
}

String label(CupSize size) {
  // The switch covers every size: the compiler checks it.
  return switch (size) {
    CupSize.small => 'small cup',
    CupSize.medium => 'medium cup',
    CupSize.large => 'large cup',
  };
}

void main() {
  for (var size in CupSize.values) {
    print('${size.name}: ${label(size)}, +${size.extra} EGP');
  }
  print(45 + CupSize.large.extra);
}

3.4 Lists

Dart has three main collections, values that hold other values: lists, maps and sets. You met lists in Chapter 2; here they are in full.

lists.dart
void main() {
  // A List<int>: only ints may go in.
  var prices = <int>[45, 20, 60];
  prices.add(15);
  print(prices);
  print(prices[0]);
  print(prices.length);
  print(prices.contains(60));

  prices.remove(20);
  prices.sort();
  print(prices);

  var isFriday = true;
  var extras = [5, 10];
  var all = [
    ...prices,
    ...extras,
    if (isFriday) 0,
    for (var p in prices) p * 2,
  ];
  print(all);

  // fold carries a running total through the list.
  var total = prices.fold(0, (sum, p) => sum + p);
  print(total);
  print(prices.where((p) => p > 20).map((p) => '$p EGP').toList());
}

A list keeps its items in order, and you reach each one by its index, counting from 0. <int>[...] makes a list that can hold only ints: its type is List<int>, read “list of int”. The type in angle brackets is called a type argument, and it is what makes collections safe: Dart will not let a string into a list of numbers.

The middle of the program shows three features that you will use in every Flutter screen:

  • The spread operator ... puts all the items of one list inside another.
  • Collection if: if (isFriday) 0 adds the item only when the condition is true.
  • Collection for: for (var p in prices) p * 2 adds one item for each round of the loop.

In Flutter, a screen is a list of widgets, so you will write things like children: [Title(), if (loggedIn) Profile(), for (var n in notes) NoteCard(n)]. That one line replaces a dozen lines of add calls.

Finally, fold carries a running total through the list, and where and map filter and transform, as in Chapter 2. Both return a lazy Iterable, which only does the work when you need the items; toList() turns it into a real list.

3.5 Maps

A map connects keys to values, like a dictionary connects words to meanings. The café’s stock is a map from the name of each thing to how many are left:

maps.dart
void main() {
  // A Map: each key (a name) leads to one value (a quantity).
  var stock = <String, int>{'sugar': 40, 'milk': 12, 'cups': 200};
  print(stock['milk']);
  print(stock['beans']);

  // Looking up a key gives int?: the key may not be there.
  int beans = stock['beans'] ?? 0;
  print(beans);

  stock['beans'] = 5;
  // update changes a value; ifAbsent says what to do when the key is missing.
  stock.update('milk', (n) => n - 2);
  stock.update('water', (n) => n + 6, ifAbsent: () => 6);
  print(stock.length);
  print(stock.containsKey('sugar'));

  for (var entry in stock.entries) {
    print('${entry.key}: ${entry.value}');
  }
  stock.remove('cups');
  print(stock.keys.toList());
}

3.6 Sets

A set is a collection in which each value appears at most once. Adding something that is already there does nothing:

sets.dart
void main() {
  // A Set keeps each value once, whatever happens.
  var tags = <String>{'sweet', 'hot'};
  tags.add('sweet');
  tags.add('vegan');
  print(tags);
  print(tags.length);

  var cakeTags = {'sweet', 'cold'};
  print(tags.intersection(cakeTags));
  print(tags.union(cakeTags));
  print(tags.difference(cakeTags));

  var orders = ['Latte', 'Tea', 'Latte', 'Cake', 'Tea'];
  print(orders.toSet());
}

3.7 Records and patterns

Sometimes a function needs to return two values. Before Dart 3 you would write a small class just for that. Now there are records:

records.dart
// A record: two values travel together, no class needed.
(int, int) cheapestAndDearest(List<int> prices) {
  var sorted = [...prices]..sort();
  return (sorted.first, sorted.last);
}

({String name, int price}) special() => (name: 'Cake', price: 50);

void main() {
  var prices = [45, 20, 60, 15];
  var result = cheapestAndDearest(prices);
  print(result);
  print(result.$1);

  // A pattern takes the record apart into two variables.
  var (low, high) = cheapestAndDearest(prices);
  print('cheapest: $low, most expensive: $high');

  var today = special();
  print('${today.name}: ${today.price}');
}

Cake: 50

(int, int) is the type of a record with two ints, and (sorted.first, sorted.last) makes one. Its fields are called $1, $2 and so on, but the nicer way is a pattern: var (low, high) = ... takes the record apart into two variables in one line. This is called destructuring. A record can also have named fields, like ({String name, int price}), read with a dot.

The function also shows a cascade, ..: [...prices]..sort() makes a copy of the list, sorts it, and gives back the copy rather than the result of sort (which returns nothing). Cascades let you call several methods on the same object in a row.

Tip

Use a record for a quick pair of values that travel together for a moment, such as the result of a function. When the values have a meaning of their own and methods to go with them, such as a menu item, write a class.

3.8 Project: the café order book

Let us put the chapter together. The café’s menu becomes a list of objects, each with a category, and an order becomes a class that counts how many of each item a table ordered:

cafe.dart
enum Category { drink, food }

class MenuItem {
  final String name;
  final int price;
  final Category category;
  const MenuItem(this.name, this.price, this.category);
}

// The menu: a const list of const items, built once.
const menu = [
  MenuItem('Latte', 45, Category.drink),
  MenuItem('Tea', 15, Category.drink),
  MenuItem('Cookie', 20, Category.food),
  MenuItem('Cake', 60, Category.food),
];

class Order {
  final int table;
  // An order: how many of each item. A Map, because each item appears once.
  final Map<MenuItem, int> _counts = {};

  Order(this.table);

  void add(MenuItem item, {int count = 1}) {
    _counts.update(item, (n) => n + count, ifAbsent: () => count);
  }

  int get total {
    var sum = 0;
    _counts.forEach((item, n) => sum += item.price * n);
    return sum;
  }

  Set<Category> get categories => {
    for (var item in _counts.keys) item.category,
  };

  // One line per item, sorted by name, built with a for inside the list.
  List<String> get lines {
    var items = _counts.keys.toList()..sort((a, b) => a.name.compareTo(b.name));
    return [for (var item in items) '${_counts[item]} × ${item.name}'];
  }
}

void main() {
  var order = Order(4);
  order.add(menu[0], count: 2);
  order.add(menu[3]);
  order.add(menu[0]);
  order.add(menu[2], count: 3);

  print('Order, table ${order.table}');
  for (var line in order.lines) {
    print('  $line');
  }
  print('Total: ${order.total} EGP');
  print(order.categories.map((c) => c.name).toList());
}

Bit

4.1 Later, not now

Start with three lines that do not print in the order you might expect:

order.dart
void main() {
  print('one');
  Future.delayed(Duration(milliseconds: 100), () => print('three'));
  print('two');
}
Terminal
$ dart run order.dart
one
two
three

Future.delayed does not stop the program for 100 milliseconds. It asks Dart to run a function later, and returns at once, so two is printed before three. Dart runs your program on one thread, one line of work at a time, with an event loop: a queue of jobs to do later, such as “run this when 100 milliseconds have passed” or “run this when the server answers”. When the current code finishes, the loop takes the next job that is ready. Nothing ever blocks; things are just scheduled.

In Flutter, the same loop also draws the screen. As long as your code returns quickly and leaves the waiting to the loop, the app stays smooth.

4.2 Futures

A Future is a value that is not ready yet, but will be: a promise of a value. Future<String> is a string that will arrive later. Here the café brews a coffee, which takes 0.3 seconds. Every program in this chapter starts with a small clock that prints the seconds since main started, in tenths, so that you can see when each line runs:

future.dart
// Seconds since main started, in tenths: the same on every machine.
final watch = Stopwatch();
String clock() => '${(watch.elapsedMilliseconds / 1000).toStringAsFixed(1)} s';

// A Future<String>: a String that will be ready later.
Future<String> brew(String drink) {
  return Future.delayed(Duration(milliseconds: 300), () => '$drink ready');
}

void main() {
  watch.start();
  print('${clock()} order');
  // then: what to do with the value when it arrives.
  brew('Latte').then((cup) => print('${clock()} $cup'));
  // main does not wait: its last line runs first.
  print('${clock()} end of main');
}
Terminal
$ dart run future.dart
0.0 s order
0.0 s end of main
0.3 s Latte ready

brew returns a Future<String> at once. then registers what to do with the value when it arrives. And main carries on immediately: the last line of main prints at 0.0 seconds, and the coffee arrives at 0.3.

Watch out

Look at the clock: watch.start() is the first line of every main. A top-level final in Dart is lazy: it is created the first time it is used, not when the program starts. Without that line, the stopwatch would start at the first call of clock(), which may come after the first wait, and every time would be wrong. Being lazy usually saves work; just remember it when the moment of creation matters.

4.3 async and await

Chains of then become hard to read quickly. Dart offers a better way to write the same thing: mark the function async, and await each future. The code then reads from top to bottom, like the programs of the earlier chapters:

await.dart
// Seconds since main started, in tenths: the same on every machine.
final watch = Stopwatch();
String clock() => '${(watch.elapsedMilliseconds / 1000).toStringAsFixed(1)} s';

Future<String> brew(String drink) =>
    Future.delayed(Duration(milliseconds: 300), () => '$drink ready');

Future<void> main() async {
  watch.start();
  // await waits for the value, without blocking anything else.
  var cup = await brew('Latte');
  print('${clock()} $cup');

  // One after the other: the waits add up.
  var a = await brew('Tea');
  var b = await brew('Latte');
  print('${clock()} $a, $b');

  // Both at once: Future.wait waits for all of them.
  var both = await Future.wait([brew('Tea'), brew('Latte')]);
  print('${clock()} $both');
}
Terminal
$ dart run await.dart
0.3 s Latte ready
0.9 s Tea ready, Latte ready
1.2 s [Tea ready, Latte ready]
  • An async function always returns a Future. main becomes Future<void> main() async: a future with no value, done when main is done.
  • await brew('Latte') pauses this function until the coffee is ready, and gives the String inside the future. The rest of the app, and the screen, keep running in the meantime.
  • Awaiting two brews one after the other takes 0.3 + 0.3 seconds: the clock goes from 0.3 to 0.9.
  • Future.wait starts both at once and waits for the slowest: 0.3 seconds for the two, from 0.9 to 1.2. It gives a list of the results, in the order of the futures.

Professional habit

When several slow tasks do not depend on each other, such as loading a user’s profile and their messages, start them together with Future.wait. When one needs the result of another, await them in order. Asking “does this wait need the previous one?” is one of the simplest ways to make an app feel twice as fast.

4.4 Errors while waiting

Waiting gives things time to go wrong: the network drops, the server refuses, the milk runs out. An error inside a future travels with it, and comes out at the await, so the familiar try and catch work exactly as they do for ordinary code:

errors.dart
// Our own error, with a message for people.
class OutOfMilk implements Exception {
  final String drink;
  OutOfMilk(this.drink);

  @override
  String toString() => 'No milk left ($drink)';
}

Future<String> brew(String drink) async {
  await Future.delayed(Duration(milliseconds: 100));
  if (drink == 'Latte') throw OutOfMilk(drink);
  return '$drink ready';
}

Future<void> serve(String drink) async {
  // An error in a future arrives at the await, so try catches it.
  try {
    var cup = await brew(drink);
    print(cup);
  } on OutOfMilk catch (e) {
    print('Sorry: $e');
  } finally {
    // finally runs either way: clean the machine.
    print('  machine cleaned');
  }
}

Future<void> main() async {
  await serve('Tea');
  await serve('Latte');
}
Terminal
$ dart run errors.dart
Tea ready
  machine cleaned
Sorry: No milk left (Latte)
  machine cleaned
  • OutOfMilk is our own kind of error: a class that implements Exception, with a message that people can read.
  • throw stops brew and sends the error to whoever awaits it.
  • on OutOfMilk catch (e) catches only that kind of error; anything else would continue upwards. Catch what you can handle, and let the rest through.
  • finally runs in both cases, after success and after an error: the place for cleaning up.

Giving up: timeouts

A server that never answers is worse than one that fails, because the user waits for ever. timeout puts a limit on any future:

timeout.dart
import 'dart:async';

// Seconds since main started, in tenths: the same on every machine.
final watch = Stopwatch();
String clock() => '${(watch.elapsedMilliseconds / 1000).toStringAsFixed(1)} s';

Future<String> brew(String drink, int ms) =>
    Future.delayed(Duration(milliseconds: ms), () => '$drink ready');

Future<void> main() async {
  watch.start();
  for (var ms in [200, 800]) {
    try {
      // Wait at most 0.5 s, then give up.
      var cup = await brew('Latte', ms).timeout(Duration(milliseconds: 500));
      print('${clock()} $cup');
    } on TimeoutException {
      print('${clock()} too slow, cancelled after 0.5 s');
    }
  }
}

4.5 Streams

A future gives one value, later. A Stream gives many values, one after another, over time: the ticks of a clock, the messages of a chat, the positions of a finger moving on the screen, the orders arriving in a café.

streams.dart
// Seconds since main started, in tenths: the same on every machine.
final watch = Stopwatch();
String clock() => '${(watch.elapsedMilliseconds / 1000).toStringAsFixed(1)} s';

Future<void> main() async {
  watch.start();
  // A Stream: a value every 0.2 s, and only the first 4.
  var ticks = Stream.periodic(
    Duration(milliseconds: 200),
    (i) => i + 1,
  ).take(4);

  // await for: a loop that waits for each value.
  await for (var t in ticks) {
    print('${clock()} tick $t');
  }

  // Streams have where and map too, like lists.
  var prices = Stream.fromIterable([45, 15, 20, 60]);
  var dear = await prices.where((p) => p > 18).map((p) => p * 2).toList();
  print(dear);

  // listen: a function called for every value; the program goes on.
  Stream.fromIterable(['Tea', 'Cake']).listen((item) => print('later: $item'));
  print('now');
}
Terminal
$ dart run streams.dart
0.2 s tick 1
0.4 s tick 2
0.6 s tick 3
0.8 s tick 4
[90, 40, 120]
now
later: Tea
later: Cake
  • Stream.periodic produces a value every 0.2 seconds, for ever; take(4) keeps the first four and then ends the stream.
  • await for is a loop that waits for each value, and ends when the stream ends. It works only inside an async function.
  • Streams have where, map and toList, like lists, except that each one waits for the values to arrive. toList gives a future of the whole list.
  • listen is the other way to use a stream: it registers a function to call for every value, and returns at once. That is why now is printed before later.

Use await for when your function should wait for the stream to finish, and listen when the stream runs alongside everything else, as most streams in an app do.

Making your own stream

Two tools let you create streams. The first, a StreamController, is a stream you feed by hand: whenever something happens, add it.

controller.dart
import 'dart:async';

Future<void> main() async {
  // A StreamController: the café decides when to send each value.
  // broadcast: more than one listener may listen.
  var orders = StreamController<String>.broadcast();

  orders.stream.listen((o) => print('screen: $o'));
  orders.stream
      .where((o) => o.contains('Cake'))
      .listen((o) => print('kitchen: $o'));

  orders.add('table 1: Latte');
  orders.add('table 2: Cake');
  orders.add('table 3: Tea, Cake');
  await orders.close();
  print('closed');
}

A normal stream may have only one listener. broadcast() allows several: here the screen shows every order, and the kitchen listens only to orders with cake. When no more values will come, close the controller, so that listeners and await for loops know the stream has ended.

The second tool is a generator: a function marked async* (with a star), which produces a stream. Each yield sends one value to the listener, and the function can await between them:

generator.dart
// Seconds since main started, in tenths: the same on every machine.
final watch = Stopwatch();
String clock() => '${(watch.elapsedMilliseconds / 1000).toStringAsFixed(1)} s';

// async*: a function that yields values over time, as a Stream.
Stream<int> countdown(int from) async* {
  for (var i = from; i > 0; i--) {
    await Future.delayed(Duration(milliseconds: 200));
    // yield sends one value to whoever is listening.
    yield i;
  }
}

Future<void> main() async {
  watch.start();
  await for (var n in countdown(3)) {
    print('${clock()} boarding in $n');
  }
  print('${clock()} done');
}

4.6 Project: the café kitchen

Let us bring the chapter together. Orders arrive as a stream: two items, then one more order 0.1 seconds later, then a third. Each item takes its own time to prepare. The kitchen starts every order as soon as it arrives, prepares its items at the same time, and announces when each order is ready.

kitchen.dart
import 'dart:async';

// Seconds since main started, in tenths: the same on every machine.
final watch = Stopwatch();
String clock() => '${(watch.elapsedMilliseconds / 1000).toStringAsFixed(1)} s';

// Each item takes its own time to prepare.
const prepTime = {'Latte': 300, 'Tea': 100, 'Cake': 200, 'Cookie': 100};

Future<String> prepare(String item) async {
  await Future.delayed(Duration(milliseconds: prepTime[item] ?? 100));
  return item;
}

// Orders arrive one by one, as a stream.
Stream<List<String>> incoming() async* {
  yield ['Latte', 'Cake'];
  await Future.delayed(Duration(milliseconds: 100));
  yield ['Tea'];
  await Future.delayed(Duration(milliseconds: 100));
  yield ['Cookie', 'Tea', 'Latte'];
}

Future<void> main() async {
  watch.start();
  var n = 0;
  var kitchen = <Future<void>>[];
  await for (var items in incoming()) {
    var number = ++n;
    print('${clock()} order $number arrives: ${items.join(', ')}');
    // The items of one order are prepared at the same time.
    kitchen.add(
      Future.wait(items.map(prepare))
          .then((done) => print('${clock()} order $number ready')),
    );
  }
  await Future.wait(kitchen);
  print('${clock()} all ready');
}
Terminal
$ dart run kitchen.dart
0.0 s order 1 arrives: Latte, Cake
0.1 s order 2 arrives: Tea
0.2 s order 2 ready
0.2 s order 3 arrives: Cookie, Tea, Latte
0.3 s order 1 ready
0.5 s order 3 ready
0.5 s all ready

Read the times. Order 1 (a latte, 0.3 seconds, and a cake, 0.2) arrives at 0.0 and is ready at 0.3, the time of its slowest item, because Future.wait prepares both at once. Order 2, one tea, arrives at 0.1 and is ready at 0.2: before order 1, because the kitchen does not make it wait in line. Order 3 arrives at 0.2 with a latte and is ready at 0.5. Everything is ready at 0.5 seconds; done one item at a time, it would have taken 1.1.

Look at how the program is built. incoming is a generator that yields one order at a time. The await for loop takes each order, and does not await its preparation: it keeps the future in the list kitchen and goes back to the stream for the next order. At the end, Future.wait(kitchen) waits for every order still being prepared. This pattern, start now and collect later, is how real apps download many images, or send many messages, without one slow item holding up the others.

Common mistakes

MistakeWhat happensFix
Forgetting awaitThe code goes on before the result is ready, silentlyAwait it; turn on the unawaited_futures rule

Printing a future instead of its valueInstance of 'Future<String>'print(await fetchName())

Summary

  • Dart runs one thing at a time, with an event loop: slow work is scheduled, never waited for in place, so the app never freezes.
  • A Future<T> is a value of type T that arrives later. then registers what to do with it.
  • An async function returns a future, and await waits for one inside it, so the code reads top to bottom.
  • Future.wait runs independent tasks together; timeout gives up after a limit.
  • Errors inside futures come out at the await: use try, on … catch and finally.
  • A Stream<T> gives many values over time: read it with await for or listen, and shape it with where and map.
  • Make streams with a StreamController (broadcast() for several listeners; close() at the end) or an async* generator with yield.

Quick check answers: 1. Future<int>. 2. One after the other, 0.4 + 0.6 = 1 second; with Future.wait, 0.6 seconds, the time of the slowest. 3. At the await of that future, where a try around it can catch it.

5.6 Widgets that change: StatefulWidget

Every widget so far looks the same for ever. A like button must change when it is tapped: it has to remember something. That memory is called state, and a widget with state is a StatefulWidget:

lib/like.dart (part)
// A StatefulWidget: the widget, and a State object that remembers.
class LikePage extends StatefulWidget {
  const LikePage({super.key});

  @override
  State<LikePage> createState() => _LikePageState();
}

class _LikePageState extends State<LikePage> {
  int likes = 0;

  void like() {
    // setState: change the value, then Flutter calls build again.
    setState(() {
      likes++;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Center(
        child: Column(
          mainAxisSize: MainAxisSize.min,
          children: [
            IconButton(
              iconSize: 72,
              tooltip: 'Like',
              onPressed: like,
              icon: Icon(
                likes > 0 ? Icons.favorite : Icons.favorite_border,
                color: Colors.red,
              ),
            ),
            Text('$likes likes', style: const TextStyle(fontSize: 24)),
          ],
        ),
      ),
    );
  }
}

A stateful widget comes in two classes:

  • LikePage, the widget itself, is still immutable: Flutter may throw it away and make a new one at any time. Its only job is createState.
  • _LikePageState is the State object. Flutter creates it once and keeps it while the widget is on the screen, so its fields, here likes, survive every rebuild. It is private (the underscore), because nobody outside needs it.

The key line is setState. It does two things: it runs the function you give it, which changes the state, and it tells Flutter that this widget needs to be built again. Flutter then calls build, which reads the new likes and returns a new tree: a full heart and the new number. You never change the screen directly; you change the state, and describe the screen for that state. This is the most important idea in Flutter, and Chapter 10 builds on it.

Testing a stateful widget is like using it: tap, then look. Flutter’s test tools do exactly that, without a phone:

Bit

When a layout looks wrong, do not change numbers at random. Ask three questions: how much room did this widget get from its parent, how big did it decide to be, and where did its parent put it? This chapter teaches you to answer all three.

6.1 The rule of layout

Flutter lays out the whole widget tree with one rule, usually summed up in one line:

Constraints go down. Sizes go up. The parent sets the position.

  1. A parent tells each child the constraints it must respect: the smallest and the largest width and height it may have. The screen gives the app its own size; a Padding of 16 gives its child 32 pixels less in each direction; a SizedBox(width: 300) gives exactly 300.
  2. Each child chooses its size within those limits, after asking its own children the same question, and reports it back up.
  3. The parent places each child: Center in the middle, Column one under the other, Row side by side.

A widget does not choose its own position, and cannot be bigger than its constraints allow. Almost every layout problem you will meet is one of these steps doing something you did not expect, and the sections below show the common ones.

6.2 Rows and columns

A Row places its children side by side, along its main axis, which is horizontal. A Column does the same vertically. The other direction is the cross axis. Two properties decide where the children go: mainAxisAlignment along the main axis, and crossAxisAlignment across it. This app shows the same three coloured boxes in four rows:

lib/rows.dart (part)
class RowsPage extends StatelessWidget {
  const RowsPage({super.key});

  @override
  Widget build(BuildContext context) {
    const boxes = [Box(1), Box(2), Box(3)];
    return const Scaffold(
      body: Padding(
        padding: EdgeInsets.all(16),
        // The same three boxes, arranged four ways.
        child: Column(
          children: [
            Labelled('start', Row(children: boxes)),
            Labelled(
              'center',
              Row(mainAxisAlignment: MainAxisAlignment.center, children: boxes),
            ),
            Labelled(
              'spaceBetween',
              Row(
                mainAxisAlignment: MainAxisAlignment.spaceBetween,
                children: boxes,
              ),
            ),
            Labelled(
              'spaceEvenly + cross end',
              Row(
                mainAxisAlignment: MainAxisAlignment.spaceEvenly,
                crossAxisAlignment: CrossAxisAlignment.end,
                children: boxes,
              ),
            ),
          ],
        ),
      ),
    );
  }
}

start packs the boxes at the beginning, center in the middle, spaceBetween puts all the free space between them, and spaceEvenly gives equal space around each one. In the last row, CrossAxisAlignment.end moves the boxes to the bottom of the 80-pixel band. Box and Labelled are two small widgets written for this example, in the same file; Box is reused all through the chapter.

Tip

“Start” and “end” mean the beginning and the end of the reading direction, not left and right. In an Arabic app a row starts on the right, and every start in your code follows it. Write start and end, never “left” and “right”, and your layouts will work in both directions for free; Chapter 13 uses this.

6.3 Sharing the space: Expanded and Flexible

Boxes of fixed sizes rarely fill a screen exactly. Expanded and Flexible decide who gets the space that is left:

lib/expanded.dart (part)
class ExpandedPage extends StatelessWidget {
  const ExpandedPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          spacing: 24,
          children: [
            // Expanded takes the free space; flex shares it out.
            const Row(
              children: [
                Box(1),
                Expanded(child: Box(2)),
                Box(3),
              ],
            ),
            const Row(
              children: [
                Expanded(child: Box(1)),
                Expanded(flex: 2, child: Box(2)),
                Expanded(child: Box(3)),
              ],
            ),
            // Flexible: as wide as it needs, but no wider than the room left.
            Row(
              children: [
                const Icon(Icons.local_cafe, size: 32),
                const SizedBox(width: 8),
                const Flexible(
                  child: Text(
                    'A very long name for a drink that does not fit on one line',
                    style: TextStyle(fontSize: 18),
                  ),
                ),
                const SizedBox(width: 8),
                Container(width: 48, height: 32, color: Colors.teal),
              ],
            ),
          ],
        ),
      ),
    );
  }
}
  • In the first row, boxes 1 and 3 keep their 56 pixels, and Expanded makes box 2 take everything else.
  • In the second, all three are expanded, and flex: 2 gives box 2 two shares of the space for every one share of the others.
  • In the third, the text is wrapped in Flexible: it may use the space left between the icon and the teal box, and no more, so it goes onto a second line instead of pushing the box off the screen.

The difference between the two: Expanded must fill its share, while Flexible may use up to its share, and is happy to be smaller.

6.6 Flowing onto the next line: Wrap

A Row never goes onto a second line. When you have a number of small items, such as tags or filter chips, use Wrap: it fills a line, then starts the next.

lib/wrap.dart (part)
        child: Wrap(
          spacing: 8,
          runSpacing: 8,
          children: [for (final tag in tags.split(',')) Chip(label: Text(tag))],

spacing is the gap between chips on a line, and runSpacing the gap between lines. On a wider screen the same code puts more chips on each line, without any change.

6.7 Every screen size

Your app will run on phones of many widths, held upright or sideways, and on tablets. Two tools tell you how much room you have:

  • MediaQuery.sizeOf(context) gives the size of the whole screen.
  • LayoutBuilder gives the constraints of the place where it sits, and lets you build different widgets for different widths. Prefer it: a widget should depend on the room it gets, not on the size of the screen, so that it also works inside half of a tablet.
lib/responsive.dart (part)
    final size = MediaQuery.sizeOf(context);
    final held = size.width > size.height ? 'landscape' : 'portrait';
    final menu = Panel('Menu', 'Latte, tea, cake…', Colors.teal.shade100);
    final order = Panel('Your order', '2 × Latte', Colors.orange.shade100);
    return Scaffold(
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            Text(
              'width ${size.width.round()}, height ${size.height.round()}, $held',
            ),
            const SizedBox(height: 16),
            // LayoutBuilder tells us how much room we have; we choose the layout.
            LayoutBuilder(
              builder: (context, constraints) {
                // Narrow: one column. Wide: side by side.
                if (constraints.maxWidth < 600) {
                  return Column(
                    spacing: 16,
                    crossAxisAlignment: CrossAxisAlignment.stretch,
                    children: [menu, order],
                  );
                }
                return Row(
                  spacing: 16,
                  crossAxisAlignment: CrossAxisAlignment.start,
                  children: [
                    Expanded(flex: 2, child: menu),
                    Expanded(child: order),
                  ],
                );
              },
            ),

The first line of the app prints what MediaQuery says. Below it, LayoutBuilder chooses: under 600 pixels, a column; from 600, a row with Expanded panels. The number 600 is a breakpoint, the width where the layout changes. Material’s guidelines use 600 as the boundary between phones and tablets, which is why so many apps use it too.

Watch out

Real phones have notches, rounded corners and a home bar that cover parts of the screen. Wrap the content of a screen in SafeArea when it has no AppBar, and Flutter keeps it clear of them. The screenshots in this book come from a browser, which has none of these, but your phone does.

  5. Two workers share one queue. Each takes the next coffee, brews it, and comes back for another, so at most two coffees brew at any moment. Five coffees of 0.3 seconds take 0.9 seconds instead of 1.5:
    answers/pool.dart
    // Seconds since main started, in tenths: the same on every machine.
final watch = Stopwatch();
String clock() => '${(watch.elapsedMilliseconds / 1000).toStringAsFixed(1)} s';

Future<void> brew(int n) async {
  await Future.delayed(Duration(milliseconds: 300));
  print('${clock()} #$n ready');
}

// At most two coffees at a time: one machine slot per worker.
Future<void> worker(List<int> queue, String name) async {
  while (queue.isNotEmpty) {
    var n = queue.removeAt(0);
    print('${clock()} machine $name: #$n');
    await brew(n);
  }
}

Future<void> main() async {
  watch.start();
  var queue = [1, 2, 3, 4, 5];
  await Future.wait([worker(queue, 'A'), worker(queue, 'B')]);
  print('${clock()} done');
}

Chapter 5

  1. MaterialApp → Scaffold → (AppBar → Text) and (Padding → Column → three InfoRows). Each InfoRow → Padding → Row → Icon, SizedBox, Text. Counting MaterialApp as level 1, the deepest widgets, the icons and texts of the rows, are on level 8. Real screens are often twenty or thirty levels deep; that is normal, and it is why small widgets of your own keep the code readable.
  2. (a) Padding(padding: EdgeInsets.all(20), child: ...). (b) SizedBox(width: 20) between them, or spacing: 20 on the row. (c) A Container (or DecoratedBox) with a BoxDecoration: color: Colors.white, borderRadius and boxShadow; or simply a Card. (d) Center.

In build, use Icon(icon, color: color). On the page: InfoRow(icon: Icons.place, text: '...', color: Colors.red).
  4. (a) Stateless: it shows what it is given. (b) Stateful, or better, stateless with its value and a callback from the parent, like the star rating in Project 5.3: that is how Flutter’s own Checkbox works. (c) Stateless: nothing changes.   5. Nothing changes on the screen: likes really becomes 3, but nobody told Flutter to build the widget again. Chapter 6

  1. 390 − 16 − 16 = 358 pixels. The SizedBox(width: 500) asks for 500, but a child cannot be bigger than its constraints, so it is 358 wide. Constraints go down, and a widget can only choose a size inside them.
  2. (a) A Spacer() before the price (or mainAxisAlignment: MainAxisAlignment.spaceBetween on the row, or an Expanded on what comes before it). (b) Two Expandeds, with flex: 2 on the wider one. (c) A Stack with the picture first and the ribbon in a Positioned or PositionedDirectional.
  3. spaceAround gives each child the same space on both of its sides, so the gaps at the two ends are half the gaps between children. spaceEvenly makes every gap equal, the ends included. With three 56-pixel boxes in a 358-pixel row, 190 pixels are free: spaceEvenly makes four gaps of 47.5, and spaceAround makes end gaps of about 31.7 and middle gaps of about 63.3.
  4. A LayoutBuilder around the whole content below the banner decides. Under 900 pixels, it returns the column of today (the stats row, then the sections); from 900, it returns a Row with the stats in a narrow Column on the side (for example in SizedBox(width: 220)) and the two sections in an Expanded beside them. Breakpoints can nest: the inner LayoutBuilder of the sections still decides by the width it gets.
  5. Pump const MaterialApp(home: SizedBox(width: 320, child: Dashboard())) in a testWidgets with no expect at all: any overflow is reported as an exception and fails the test, as in Section 6.4. At 320 pixels the three stat cards are each about 96 pixels wide; if a number or label does not fit, make the label smaller, allow it to wrap, or show two stats per row below a breakpoint. Keeping the test means the dashboard is checked at that width on every change.
