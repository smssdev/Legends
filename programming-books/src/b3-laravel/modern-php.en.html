Chapter {{n}}

Modern PHP for JavaScript Developers

In this chapter you will learn to

  • read and write PHP 8.5 by comparing it with the JavaScript you know
  • use types strictly, and know exactly when PHP converts values on its own
  • work with PHP’s arrays, closures and named arguments, and avoid their traps
  • model a domain with readonly classes, enums, property hooks and exceptions
  • organise code in namespaces, loaded automatically by Composer
  • check types before running anything, with PHPStan

Many developers still picture the PHP of 2005: untyped, inconsistent, mixed into HTML. The language Laravel runs on today is a different one. It has types that are checked when your code runs, enums, readonly objects, first-class functions, and a static analyser as strict as TypeScript’s compiler. You already know most of the ideas from JavaScript and TypeScript. This chapter maps them onto PHP, and spends its time on the places where PHP behaves differently, because those are where bugs come from.

The first PHP bug I wrote was a closure that added to a total, and the total stayed zero. In JavaScript the same code worked. Nothing was wrong with PHP: it simply copies where JavaScript shares. Once I learned the handful of rules like that one, PHP stopped surprising me.

{{n}}.1 A first script

Every PHP file starts with <?php. (The tag exists because PHP began as a language mixed into HTML; in a file that holds only code, it appears once at the top and is never closed.) The php command runs a file, just as node does:







The first differences are already visible:


    

  • Every variable starts with $, and there is no let or const for local variables: the first assignment creates the variable.
    • 

  • Strings are joined with a dot (.), not +. In PHP, + is only for numbers.
    •

    • 

  • echo prints, and statements end with a semicolon, always.
    • 




All of this book’s PHP runs on PHP 8.5, the current version. Laravel 13 needs 8.3 or later; a few features in this chapter are marked with the version that introduced them.



{{n}}.2 Types, and the strict mode



PHP checks types when the code runs. A function declares the types of its parameters and of its result, much as in TypeScript. But by default, PHP tries to convert a value of the wrong type before it gives up:






A string "45000", as it would arrive from an HTML form, became the number 45000; even true became 1. Both calls ran without a word. One line at the top of a file switches this off for every call made from that file:









Now the wrong call is a TypeError that names the function, the argument, the expected type and the line. Start every PHP file with declare(strict_types=1);: you want to hear about a string where a number belongs, not have it guessed for you. (Laravel converts input from requests deliberately, in its validation layer, which is the right place for it.)

{{n}}.3 Comparison: always three equals signs



PHP has the same two comparisons as JavaScript. === compares the type and the value; == converts first. PHP’s conversion rules differ from JavaScript’s, and some of them are surprising:









Two strings that both look like numbers are compared as numbers: "10" == "1e1" is true, because 1e1 is 10 in scientific notation. That has caused real security holes, in code that compared password hashes with ==. And null, false and an empty array are all loosely equal. The rule is the same as in JavaScript, and even more important: use === and !==, and pass true as the last argument to functions such as in_array, which compare loosely unless you ask them not to.

  2. A file without declare(strict_types=1) calls total("3 kits", 2). What happens?
  3. Why is "10" == "1e1" true?

{{n}}.4 Arrays: lists and maps in one



PHP has one array type for what JavaScript splits into arrays and plain objects. Its keys are integers or strings, and it keeps them in the order you add them:









Line by line, the points that catch JavaScript developers:


    

  • $prices[] = 2500 appends, like push. ?? gives a default when a key is missing (or null), exactly as in JavaScript.
    • 

  • Arrays are values. $copy = $prices makes a copy; adding to the copy left the original with 4 items. In JavaScript, both names would point to the same array. Objects, on the other hand, are shared in PHP as in JavaScript.
    • 

  • Destructuring uses square brackets for both kinds: [$first, $second] by position, ['name' => $name] by key.
    • 

  • The array functions take their arguments in different orders: array_map(callback, array) but array_filter(array, callback). Your editor will remind you; there is no logic to remember.
    • 

  • array_filter keeps the keys: the cheap prices are at keys 1 and 3. Encoded as JSON, an array with gaps in its keys becomes an object, not a list. Pass the result through array_values, as the next line does, whenever you need a list again.
    • 

  • PHP 8.4 added array_find, array_any and array_all, the equivalents of find, some and every.
    • 

  • PHP 8.5 added the pipe operator |>: it passes the value on its left to the function on its right, so a chain of steps reads from left to right instead of from the inside out. trim(...) with three dots is a first-class callable: the function itself, like writing trim without calling it in JavaScript.
    • 




{{n}}.5 Functions and closures



A function written inside another piece of code can use the variables around it. JavaScript simply shares them. PHP is more careful, and this is the rule from Bit’s story:









    

  • An arrow function, fn (...) => expression, captures the variables it uses automatically, by value, when it is created. Changing $discount afterwards changes nothing: the price is 40500, 10% off.
    • 

  • A full function () { ... } captures nothing unless you list the variables in use, again by value. That is why $count stayed 0: each call increased the closure’s own copy.
    • 

  • To share a variable the JavaScript way, capture it by reference with &. Use this rarely; a function that returns a new value is easier to follow.
    • 

  • Named arguments let you pass arguments by name, in any order, skipping the optional ones you do not need. Laravel uses them often, and they make long calls readable.
    • 




{{n}}.6 Classes for a real domain



Larger PHP code is organised in classes, one class per file, grouped by namespaces: the PHP version of folders for names. A class Money in the namespace Shop is Shop\Money in full, and other files bring it in with use Shop\Money;, like an import. Nobody writes require for every class file: Composer, PHP’s package manager (its npm), generates an autoloader that finds the file the first time a class is used. One rule in composer.json says that classes in the namespace Shop live in the folder src/; this convention is called PSR-4:









Now the classes. Bit’s shop needs money that never loses a piastre, and currencies that cannot be mistyped. A currency is a fixed set of values, which is exactly what an enum is:






A backed enum has a value for each case (here the ISO code), so it can be stored in a database and read back. Enums can have methods. match is a stricter switch: it compares with ===, returns a value, has no fall-through, and throws an error if no case matches, so a new currency cannot be forgotten silently.






    

  • Constructor promotion: parameters marked public in the constructor become properties. Six lines of boilerplate disappear.
    • 

  • readonly class: every property can be set once, in the constructor, and never again. A Money value never changes: plus and times return new objects. This is the same immutability you used in React and Vue state, and it removes a whole family of bugs.
    • 

  • final: nobody can extend the class. Make classes final unless they are designed to be extended.
    • 

  • The constructor refuses a negative amount, and plus refuses to add different currencies. An object that checks its own rules can never exist in a broken state.
    •

The cart uses two features from PHP 8.4:






    

  • public private(set) is asymmetric visibility: anyone may read $lines, only the class may change it. Before PHP 8.4 this needed a private property and a getter method.
    • 

  • $total and $count have property hooks: they are read like properties ($cart->total) but computed by the get code every time, like a getter in a JavaScript class. The total is always correct, because it is never stored.
    • 

  • add returns static, the cart itself, so calls can be chained.

A product is readonly, so a sale cannot change it. clone($this, [...]) makes a copy with some properties changed, the PHP version of { ...product, price }. Here is everything at work:









Read the output against the code. The cart counts 3 items worth 570.00 (450 + 2 × 60). from turns a stored value into an enum case, and tryFrom returns null instead of throwing for an unknown one, which is what you want for input from outside. Then the three errors show the rules being enforced by the language: the cart’s lines cannot be replaced from outside, a money amount cannot be changed, and even clone with new values is refused from outside the class, because a readonly property may only be set from inside it. That is why onSale is a method of Product: the class decides how its copies are made.



Tip: Exception and Error
Everything that can be thrown implements Throwable. Exception and its subclasses are for problems your program expects and can handle: an invalid argument, a missing record, a currency mismatch. Error and its subclasses (TypeError, ValueError, and the visibility errors above) mean the code itself is wrong. Catch exceptions where you can do something useful about them; let errors reach the framework, which logs them and answers 500, as our server did in Chapter {{n-1}}.



{{n}}.7 Checking before running: PHPStan



PHP checks types when a line runs, so a bug in a branch that rarely runs stays hidden until the day it runs in production. PHPStan reads the code without running it and reports type errors, as tsc does for TypeScript. It was installed with the project, as a development dependency, and its configuration asks for the strictest level:






This function has two bugs, neither of which would show up in a quick manual test:









php -l checks only that the file is valid PHP, which it is. PHPStan found both bugs: $status may be null, so calling a method on it would crash, and '0' is a string where the constructor needs an int. Notice the PHPDoc comment in Cart.php, @var array<int, array{product: Product, quantity: int}>: PHP’s own types cannot describe what is inside an array, but PHPStan reads these comments and checks them too. For Laravel projects, the Larastan extension teaches PHPStan about the framework’s conventions.



Professional habit: strict from the first line
Every file starts with declare(strict_types=1);. PHPStan runs at the highest level your project can pass, in CI, on every pull request, and the level only goes up. A formatter (Laravel Pint, which follows the community’s PER coding style) settles every question of layout automatically. With these three in place, reviews are about design, not about types and spaces.



{{n}}.8 How PHP runs on a server



You saw in Chapter {{n-1}} that PHP starts each request with an empty memory and forgets everything when it ends. Two details complete the picture. First, PHP does not parse your files again for every request: OPcache keeps the compiled code in shared memory, so only your code’s work is repeated, not the parsing. Second, servers such as FrankenPHP (with Laravel Octane) can run in worker mode, keeping the application in memory between requests for speed, like a Node server. Then static properties and singletons survive from one request to the next, and code that was safe under shared-nothing may leak one user’s data into another’s request. We return to this when we measure performance in Chapter {{n+13}}.

Summary



    

  • Variables start with $; strings join with .; double quotes interpolate.
    • 

  • Types are checked at run time. declare(strict_types=1) stops silent conversions in a file.
    • 

  • Always compare with ===; PHP’s loose rules differ from JavaScript’s.
    • 

  • One array type for lists and maps. Arrays are copied on assignment; array_filter keeps keys. PHP 8.4 adds array_find, array_any, array_all; PHP 8.5 adds the pipe operator |>.
    • 

  • Closures capture by value: fn automatically, function with use. Named arguments make long calls readable.
    • 

  • Namespaces and Composer’s PSR-4 autoloader replace require.
    •
