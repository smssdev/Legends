1. The fifth request is stopped by ThrottleRequests with 429 Too Many Requests. The 50 MB body is stopped by ValidatePostSize with 413 Content Too Large, because it is bigger than PHP’s post_max_size. During php artisan down, PreventRequestsDuringMaintenance answers 503 Service Unavailable to everything except the addresses you allow. In all three cases the controller never runs, which is the point: cheap checks first.
  2. In routes/api.php, before the resource: Route::get('products/{product}/stock', [ProductController::class, 'stock'])->whereNumber('product')->name('products.stock');. In the controller, stock(int $product) finds the product with findOrFail and returns ['id' => …, 'stock' => …, 'in_stock' => $found['stock'] > 0]. The test exercise 2 stock in the code repository checks the exact JSON for a product with no stock.
  3. Validate the query at the top of index: $request->validate(['min_price' => ['sometimes', 'integer', 'min:0'], 'max_price' => ['sometimes', 'integer', 'min:0', Rule::when($request->has('min_price'), 'gte:min_price')]]). Rule::when adds the comparison only when there is something to compare with. Then filter with both bounds, using $request->integer('min_price', 0). The answer test checks a range with one product, a maximum alone, and min_price=9000&max_price=100, which gets a 422 naming max_price. validate on the request is fine for a few query values; a form request is better once the rules grow.
  4. tests/Fakes/ArrayProductCatalog.php implements the same interface with a plain array. The test binds it with $this->app->instance(ProductCatalog::class, new ArrayProductCatalog([...])) and fills it with exactly the products the test needs. The controller needed no change because it never names a class: it asks the container for a ProductCatalog, and the container decides which one. A fake in memory makes tests faster and lets each test state its data in its own code, where the reader can see it.
  5. The middleware sets Accept: application/json on the request, so Laravel’s error handling and validation answer in JSON, and then refuses a body that is not JSON with abort_if($sendsBody && ! $request->isJson(), 415, 'Send JSON.'). Register it first in the group with $middleware->api(prepend: [RequireJson::class], …), so it runs before anything reads the body. The answer test sends a form body (415), and an empty JSON body without an Accept header, which gets a 422 with Content-Type: application/json. All seven tests, the chapter’s and the answers’, pass together.
