Add 'q' => ['sometimes', 'string', 'min:2', 'max:50'] to ListProductsRequest, and one more condition to the query: ->when($request->validated('q'), fn ($query, $q) => $query->whereLike('name', "%$q%")). whereLike ignores case and writes the right SQL for each database. The cursor still works: it records a position in the sorted order, and withQueryString keeps q in the next link, so the next page continues among the matching products. The answer test checks a search that matches two products with limit=1, follows links.next to the second one, and checks that a one-letter search is refused with 422. On a large table, a search like this needs a suitable index, which Chapter {{n+1}} covers.
  4. One way: make cancel idempotent in its result. If the order is already cancelled, answer 200 with the order, because the client’s goal (a cancelled order) is reached. Another way: put the Idempotent middleware on the cancel route too, so a retry replays the first answer. The first is simpler and right here, because a second cancel changes nothing; keep 409 for orders that can no longer be cancelled because they were shipped. The general lesson: design actions so that repeating them is harmless, whenever the domain allows it.
  5. In the middleware, read $client = (string) $request->header('X-Client-Id', 'anonymous') and build the cache key from both: 'idempotency:'.$client.':'.$key. The expiry is already there: Cache::put(..., now()->addDay()). The answer test sends the same key and body for clients a and b and gets two different orders, then moves time forward with $this->travel(25)->hours() and checks that client a’s key creates a new order instead of a replay. Laravel’s time travel moves the clock the cache reads, so a test checks a day of expiry in milliseconds. In Chapter {{n+5}}, the client becomes the authenticated user, and the header goes away.
