Chapter {{n}}

Classes, Null Safety and Collections

In this chapter you will learn to

  • describe your own kinds of value with classes: fields, constructors, methods and getters
  • work safely with values that may be missing, using Dart’s null safety
  • give a fixed set of choices a name with enums
  • keep many values in lists, maps and sets, and choose the right one
  • return several values at once with records, and take them apart with patterns

At the end of Chapter {{n-1}}, the café’s prices were loose constants and an order was a handful of parameters. Real programs need better shapes for their data: a menu item that knows its name and its price, an order that knows its lines and its total. This chapter gives you those shapes. It also introduces the feature that makes Dart stand out among languages: null safety, which turns the most common crash in the world into a message from the compiler.

Every Flutter widget you will ever write is a class, and every screen shows a list of something. This chapter is where Dart stops being a calculator and starts being the language of apps.

{{n}}.1 Classes

A class describes a kind of value: what each value knows, and what it can do. Each value made from it is an object, or an instance of the class. Here is a menu item:






    

  • Fields are the variables inside each object: every menu item has its own name and price. They are final, because a menu item never changes after it is made.
    • 

  • The constructor makes objects. It has the class’s name, and this.name is Dart’s shortcut for “put this argument straight into the field name”. Because every field is final, the constructor can be const, and so can the items made with it.
    • 

  • priceFor is a method: a function that belongs to the object and can use its fields.
    • 

  • toString decides what print shows. Every class has one; @override says that we replace the default, which would only print Instance of 'MenuItem'.
    • 




You reach a field or a method with a dot: latte.name, cookie.priceFor(3). Notice that there is no new: in Dart you make an object by calling the constructor like a function.



Named parameters, getters and private fields








Three more tools appear in this program, and you will see all three in every Flutter app:


    

  • The constructor of MenuItem takes named parameters, {required this.name, required this.price}. Calls become self-explaining: MenuItem(name: 'Latte', price: 45). This is exactly how Flutter’s widgets are built: Text('Hi', style: ...) calls a constructor with named parameters.
    • 

  • A getter, written with get, looks like a field from outside (cake.isExpensive, without brackets) but runs code every time it is read. Order uses two, count and total, so they are always up to date.
    • 

  • A name that starts with an underscore, like _lines, is private: only code in the same file can use it. Other code can add to an order only through add, so nobody can break it from outside. This is called encapsulation.
    • 




The total uses fold, which walks the list carrying a value from one item to the next: it starts at 0, and for each item returns the sum so far plus the item’s price. Section {{n}}.4 shows it again.



Tip
In VS Code, put the cursor on a class name and press Ctrl+. (Cmd+. on a Mac): the Dart extension offers quick fixes, such as creating a constructor for the final fields you just wrote. Write the fields; let the editor write the repetitive part.



{{n}}.2 Null safety



Sometimes a value is simply not there: a customer without a nickname, a contact without a phone, a search with no result. Dart has a special value for “nothing”: null. In many languages any variable can be null at any time, and using one by accident crashes the program. Tony Hoare, who invented the null reference in 1965, later called it his “billion-dollar mistake”.



Dart solves it with null safety: a variable can hold null only if its type says so, with a question mark. String is always a string. String? is a string or null.








The compiler refuses to ask for the length of something that may not exist, and even suggests a fix. Dart gives you four tools to work with nullable values:










ToolMeaningExample



??The value on the left, or the one on the right if the left is nullnickname ?? 'Guest'


?.Use the member only if the value is not null; otherwise the result is nullnickname?.length


??=Give the variable a value only if it is nullnickname ??= 'Bito'


if (x != null)Inside the if, Dart knows x is not nullother.length






The last one is called type promotion: after you check, Dart promotes other from String? to String for the rest of the block, so you can use it freely. It is the cleanest of the four, and the one to reach for first.



The ! operator, and why to avoid it



There is a fifth tool: ! after a value tells Dart “trust me, this is not null”. The compiler believes you, and checks only when the program runs:








This time the program compiled, ran, and crashed: an unhandled exception. The line starting with #0 says where: in main, line 4. On a phone, this is an app that closes in the user’s hand.



Professional habit
Treat every ! as a small promise you might break. Prefer an if check, ?? with a sensible default, or a type that is not nullable in the first place. When you do use !, be able to say in one sentence why the value can never be null there.



Did you know?
Dart added null safety in version 2.12, in 2021, and made it compulsory in Dart 3. Every package on pub.dev had to be updated; it was one of the largest migrations any language has done, and it is why Flutter apps rarely crash on a missing value.



{{n}}.3 Enums



When a value can only be one of a few fixed choices, such as the sizes of a cup, give the choices names with an enum (short for enumeration):








CupSize has exactly three values: CupSize.small, CupSize.medium and CupSize.large. A Dart enum can carry fields, like a class: here each size knows how much it adds to the price, given in brackets after its name. CupSize.values is the list of all of them, and every value has a name.



Why not just use the strings 'small', 'medium' and 'large'? Because a typo such as 'lagre' is a perfectly good string, and the bug appears much later. A typo in CupSize.lagre does not compile. And because the compiler knows every value of an enum, it checks that a switch covers them all:








This is the exhaustiveness checking promised in Chapter {{n-1}}. Imagine the café adds an extra-large cup next year: every switch that forgot it stops compiling, and points you straight to it. Notice also that the message does not say “add a default”: a wildcard _ would silence it, but then the new size would silently get the wrong label. Add the case instead.

{{n}}.4 Lists



Dart has three main collections, values that hold other values: lists, maps and sets. You met lists in Chapter {{n-1}}; here they are in full.








A list keeps its items in order, and you reach each one by its index, counting from 0. <int>[...] makes a list that can hold only ints: its type is List<int>, read “list of int”. The type in angle brackets is called a type argument, and it is what makes collections safe: Dart will not let a string into a list of numbers.



The middle of the program shows three features that you will use in every Flutter screen:


    

  • The spread operator ... puts all the items of one list inside another.
    • 

  • Collection if: if (isFriday) 0 adds the item only when the condition is true.
    • 

  • Collection for: for (var p in prices) p * 2 adds one item for each round of the loop.
    • 



In Flutter, a screen is a list of widgets, so you will write things like children: [Title(), if (loggedIn) Profile(), for (var n in notes) NoteCard(n)]. That one line replaces a dozen lines of add calls.



Finally, fold carries a running total through the list, and where and map filter and transform, as in Chapter {{n-1}}. Both return a lazy Iterable, which only does the work when you need the items; toList() turns it into a real list.



{{n}}.5 Maps



A map connects keys to values, like a dictionary connects words to meanings. The café’s stock is a map from the name of each thing to how many are left:








The type Map<String, int> says the keys are strings and the values are ints. Each key appears once. stock['milk'] looks a value up; stock['beans'] = 5 adds or replaces one.



Look at the second line of the output: asking for a key that is not there gives null. That is why the type of stock['milk'] is int?, not int, and why Dart refuses to put it straight into an int:








Null safety reaches everywhere. The fix is the one used in maps.dart: decide what a missing key means, here ?? 0, and say it in the code. To change a value, update takes the key and a function from the old value to the new one, and ifAbsent says what to do when the key is missing. To visit every pair, loop over stock.entries; each entry has a key and a value.



{{n}}.6 Sets



A set is a collection in which each value appears at most once. Adding something that is already there does nothing:








Sets answer questions about groups: which tags do the latte and the cake share (intersection), which tags appear on either (union), which belong to one but not the other (difference). And toSet() is the shortest way to remove repeats from a list. Checking contains on a set is fast even for millions of items, because a set does not have to look through its values one by one.





CollectionWrittenChoose it when



List[1, 2, 2]Order matters, or the same value may appear twice: a queue, the lines of a receipt


Set{1, 2}Each value once, and you ask “is it in?”: tags, selected items


Map{'a': 1}You look things up by a key: stock by name, users by id






Watch out
{} on its own is an empty map, not an empty set, because maps came first. Write <String>{} for an empty set of strings, and <String, int>{} for an empty map, so that both you and Dart know which you mean.



{{n}}.7 Records and patterns



Sometimes a function needs to return two values. Before Dart 3 you would write a small class just for that. Now there are records:








(int, int) is the type of a record with two ints, and (sorted.first, sorted.last) makes one. Its fields are called $1, $2 and so on, but the nicer way is a pattern: var (low, high) = ... takes the record apart into two variables in one line. This is called destructuring. A record can also have named fields, like ({String name, int price}), read with a dot.



The function also shows a cascade, ..: [...prices]..sort() makes a copy of the list, sorts it, and gives back the copy rather than the result of sort (which returns nothing). Cascades let you call several methods on the same object in a row.



Tip
Use a record for a quick pair of values that travel together for a moment, such as the result of a function. When the values have a meaning of their own and methods to go with them, such as a menu item, write a class.



{{n}}.8 Project: the café order book



Let us put the chapter together. The café’s menu becomes a list of objects, each with a category, and an order becomes a class that counts how many of each item a table ordered:








Follow the order for table 4: two lattes, a cake, another latte, and three cookies. add uses update with ifAbsent, so the second latte adds to the first instead of making a new line: there are three lattes. The lines are sorted by name, with a cascade and a collection for. The total is 3 × 45 + 60 + 3 × 20 = 255. And categories is a set built with a collection for, so each category appears once however many items share it.



Notice how much the class hides. Code outside Order cannot touch _counts: it can only add items and read the total and the lines. If tomorrow the café wants to store orders differently, only Order changes, and every screen that uses it keeps working.

Summary



    

  • A class describes a kind of object: fields, a constructor (with this.field and named parameters), methods, getters, and toString. Names starting with _ are private to the file.
    • 

  • Null safety: a type can hold null only if it ends in ?. Use if (x != null), ??, ?. and ??=; avoid !.
    • 

  • An enum names a fixed set of values, can carry fields, and lets the compiler check that a switch covers them all.
    • 

  • Lists keep order; sets keep each value once; maps connect keys to values, and looking a key up gives a nullable value.
    • 

  • Inside a collection, ..., if and for build items; Flutter uses them to build lists of widgets.
    • 

  • A record, like (int, int), returns several values at once, and a pattern takes it apart: var (a, b) = ....
    • 




Quick check answers: 1. An int always holds a number; an int? holds a number or null, and must be checked before it is used as a number. 2. 0: name?.length is null, and ?? 0 replaces it. 3. A misspelt enum value does not compile, and a switch on the enum is checked for every value; a misspelt string is still a valid string, and nothing checks the switch.
