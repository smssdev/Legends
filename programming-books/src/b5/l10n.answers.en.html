1. The tool still generates the code, and warns that the Arabic file has one untranslated message. For that key, the Arabic class uses the template’s text, so the Arabic app shows “Language” in English in the middle of an Arabic screen. Nothing crashes, which is why the warning matters: read it after every gen-l10n, or add untranslated-messages-file: untranslated.json to l10n.yaml to get the list in a file.
  2. Icons.chevron_right mirrors like Icons.arrow_forward: both point “forward”, and forward is left in Arabic; Material marks such icons with matchTextDirection. Icons.coffee does not: a cup is a picture of a real object, and its handle is not a direction. A mirrored cup is not wrong, just strange; a mirrored clock or a mirrored logo would be wrong.
  3. In English: "basketLine": "{count, plural, =0{Your basket is empty} =1{1 item · {total} EGP} other{{count} items · {total} EGP}}" with placeholders count (int) and total (int, decimalPattern); in Arabic each form carries its own words and order. Joining two messages in code fixes the order and the separator for every language, and a translator who sees “3 items” and “145 EGP” apart cannot know they form one sentence. One message per sentence lets each language write it whole.
  4. Add app_fr.arb (say) with "@@locale": "fr"; supportedLocales grows by itself, since it is generated from the files. Untranslated keys are reported by gen-l10n, and the French class uses the English text for them until they are translated. Material’s own texts are already in French: material_ui ships translations for dozens of languages.

The app’s code decides, from the clock: it compares the pick-up day with today (a DateTime without the time) and passes 'today', 'tomorrow' or 'other' to l.pickUpWhen(when, day), whose message is {when, select, today{Today} tomorrow{Tomorrow} other{{day}}}. The ARB file holds words, not rules: it cannot know what day it is, and a test of the rule belongs in Dart, with a clock the test controls, as in Chapter {{n+1}}.
