Dart Basics

In this chapter you will learn to

  • write and run a Dart program from the terminal
  • store values in variables, and choose between var, final and const
  • work with Dart’s basic types: int, double, String and bool
  • make decisions with if, and with switch and its patterns
  • repeat work with loops, and package it in functions with named parameters
  • read the Dart compiler’s error messages, and let them help you

Every Flutter app is a Dart program, so before you build screens you need the language. The good news: if you know JavaScript, or any other language with variables, if and loops, Dart will feel familiar within an hour. The one big difference is that Dart knows the type of every value, and checks your program before it runs. That catches whole families of bugs before they reach a user’s phone. This chapter teaches the basics, one small program at a time, and ends with a receipt printer for Bit’s café.

In this chapter we leave the phone for a while and talk to Dart directly, in the terminal. No screens, no emulator: just you, the language, and very fast answers.

{{n}}.2 Variables and their types



A variable is a name for a value, exactly as in Book 1. Dart gives you several ways to create one:








With var, Dart looks at the first value and decides the variable’s type: score starts as 0, so it is an int, a whole number. This is called type inference. You can also write the type yourself, as with String name. Either way, the type is fixed for ever: a variable that holds numbers can never hold text. See what happens if you try:








The program did not run at all. Before running anything, Dart compiles the program: it reads it all and turns it into instructions for the computer, checking the types on the way. The error says where (line 3, column 11, marked with ^) and why, in plain words. In JavaScript the same line would have run, and the bug would have appeared later, somewhere else, perhaps on a user’s phone.



Did you know?
Since Dart 2, every Dart program has been type safe: a variable declared as int can never hold anything else while the program runs. Dart’s compiler uses that promise to make your app faster, too.



final and const



Most values in a program never change after they are set. Dart has two words for them:


    

  • final: the value is set once, when the program reaches that line, and never changes after. It can come from a calculation, the clock, or the user.
    • 

  • const: the value is known before the program runs, written directly in the code, like 4 or 'Sara'. Dart can then build it once and share it.
    • 



In variables.dart, the year someone joined comes from the clock (DateTime.now()), so it can only be final. The maximum number of players is written in the code, so it can be const. Try to change a final:

Professional habit
Use final by default, const for values written in the code, and var only when the value must change. In Flutter, const matters even more: a const widget is built once and reused, which is why you saw const Text(...) in Chapter {{n-1}}. The analyzer reminds you when you forget.



{{n}}.3 Numbers, text and truth



Dart has a small set of basic types that you will use in every program:










TypeWhat it holdsExamples



intWhole numbers7, -3, 2026


doubleNumbers with a decimal point12.5, 0.1


numEither of the two3 or 3.5


StringText'Cairo'


booltrue or false, nothing elsetrue






JavaScript has one kind of number; Dart has two, and the difference shows in division. The operator / always gives a double: 7 / 2 is 3.5. The operator ~/ divides and drops everything after the point, giving an int: 7 ~/ 2 is 3. The remainder, %, works as you know it.



Dart never turns text into a number, or a number into text, by itself. Text that contains a number, from a text box or a file, is turned into a number with int.parse or double.parse. A number becomes text with toString(), or with toStringAsFixed(2) to keep exactly two digits after the point, which is what you want for prices.



Watch out
int.parse('12a') stops the program with an error, because '12a' is not a number. When the text comes from a user, use int.tryParse, which gives null (no value) instead of stopping. Chapter {{n+1}} explains null, and Chapter 9 uses tryParse in real forms.



{{n}}.4 Strings



Dart’s strings have one feature you will use in almost every line of a Flutter app: interpolation, putting values inside text.








    

  • $name inside a string puts the value of the variable name there.
    • 

  • ${items * price}, with braces, puts the result of any expression there. Use the braces whenever there is more than a plain name, even ${price.toStringAsFixed(2)}.
    • 

  • Three quotes, ''', start a string that can run over several lines, keeping the line breaks and the spaces.
    • 

  • Strings have useful methods: trim() removes spaces at both ends, toUpperCase() makes capitals, contains searches, padLeft(3, '0') fills on the left up to a length, and length counts the characters.
    • 




Notice that none of these methods changed raw or name. Strings in Dart cannot be changed; every method returns a new string. That is why the result of raw.trim() must be used, or stored, to be useful.



{{n}}.5 Operators



The operators are almost the same as in JavaScript:








+=, ++, the comparisons and the logical operators &&, || and ! work as you know them. One thing is simpler: Dart has only ==, no ===, because it never converts types when comparing. 5 == 5.0 is true (both are the number five), but '5' == 5 is false: text is never equal to a number.



Quick check
  1. What do 9 / 2 and 9 ~/ 2 give?
  2. Which do you use for a value that comes from the clock: final or const?
  3. How do you write the text Total: 30 from a variable total that holds 30?

{{n}}.6 Decisions with if



if, else if and else work exactly as in Book 1. Here is the cinema kiosk again, in Dart:








Two details are new. First, int price; declares a variable without a value. Dart then checks that every path through the if gives it one before it is used: remove the else, and the program does not compile. Second, a condition must be a real bool. In JavaScript, if (count) was true for any number but zero; in Dart, it is an error. Write what you mean: if (count > 0).



The conditional operator, condition ? a : b, works as in JavaScript, and you will use it constantly in Flutter to choose between two widgets or two colours.



{{n}}.7 switch and patterns



Dart’s switch is one of its best features, and much more powerful than JavaScript’s:








The first switch is a statement, like the one you know, with one improvement: there is no break. Each case ends where the next one starts, and Dart never runs into the next case by accident.



The second and third are switch expressions: they produce a value, which goes straight into a variable. Each line has a pattern on the left of => and a result on the right, and the first pattern that matches wins:


    

  • A plain value, such as 'friday', matches when the value is equal to it.
    • 

  • || between two patterns matches either of them.
    • 

  • >= 90 is a relational pattern: it matches any value that is at least 90. That makes grading one short, readable list.
    • 

  • _, the wildcard, matches anything. Put it last, for everyone else.
    • 




A switch expression must cover every possible value. If you remove the _ line from the grades, the program does not compile, because a score of 40 would have no grade. Dart calls this exhaustiveness checking, and in Chapter {{n+1}} you will see it catch real bugs.



Look at the grades again: five lines, no if, no else, and you can read it aloud like the table on a teacher’s wall. That is why I love switch expressions.



{{n}}.8 Loops








All of these are familiar. The classic for counts. for (var drink in drinks) visits each item of a list in order, like for...of in JavaScript. while repeats as long as its condition is true. continue skips the rest of one round, and break leaves the loop: the last loop skips even numbers and stops after 7.



The square brackets, ['tea', 'coffee', 'juice'], make a list, Dart’s name for an array. Chapter {{n+1}} covers lists fully, with maps and sets.



{{n}}.9 Functions



Functions in Dart declare the type of what they return, and the type of each parameter:








    

  • int square(int n) takes an int and returns an int. A function that returns nothing is declared void, like main.
    • 

  • When the body is one expression, the arrow => replaces the braces and return, as in cube.
    • 

  • Named parameters are written in braces, {...}, and given by name when you call the function: price(cups: 2). Their order does not matter, and the call reads like a sentence. required means it must be given; the others need a default value, such as each = 12.5.
    • 

  • Optional positional parameters go in square brackets, [...], as in greet.
    • 




Named parameters are everywhere in Flutter: every Text(..., style: ...) and AppBar(title: ..., centerTitle: true) you wrote in Chapter {{n-1}} was a call with named parameters. And when you forget a required one, Dart tells you before anything runs:








The second part of the message, Context, shows the function you were trying to call, so you can see what it expects.



Functions are values








A function can be stored in a variable, like change, and passed to another function. (p) => p < 20 is an anonymous function, a function without a name, written right where it is needed. where keeps the items for which it returns true, map transforms every item, and forEach runs it for each item. If you read Book 1, these are filter, map and forEach under slightly different names. In Flutter, every button’s onPressed is an anonymous function: the code to run when it is pressed.



{{n}}.10 Project: the café receipt



Bit’s café needs a program that prints receipts. The rules:


    

  1. A latte costs 45 pounds, a cookie 20, a cake 60.
    2. 

  2. On Fridays everything is 20% off, and on Saturdays 10% off.
    3. 

  3. A 12% service charge is added after the discount, rounded to the nearest pound.
    4. 

  4. The receipt lists only what was ordered, with names on the left and amounts on the right.
    5. 









Follow Friday’s receipt as the computer does. Two lattes and three cookies make 150. Friday gives 20%, so the discount is 150 * 20 ~/ 100, which is 30. The service is 12% of 120, which is 14.4, and round() makes it 14. The total is 150 − 30 + 14 = 134.



Look at what each part of the program uses. The prices are const. The discount is a switch expression in an arrow function. line builds each line with padRight and padLeft, so the amounts line up. printReceipt uses named parameters with defaults, so a customer who only ordered a cake does not need to say “zero lattes”. And '=' * width repeats a string: another small Dart convenience.



Try it
Add tea, at 15 pounds, to the menu and to printReceipt. Then print a Saturday receipt for two teas and a cake, and check the total by hand before you run it.

Summary



    

  • A Dart program starts in main, prints with print, ends statements with ;, and runs with dart run file.dart.
    • 

  • Every value has a type, checked before the program runs. var infers it from the first value; it never changes.
    • 

  • Prefer final (set once) and const (known before running); use var only for values that change.
    • 

  • int and double are two kinds of number: / gives a double, ~/ an int. Convert text with parse, and numbers with toString or toStringAsFixed.
    • 

  • Strings use interpolation: $name and ${expression}.
    • 

  • Conditions must be bool. == never converts types.
    • 

  • switch needs no break; switch expressions with patterns (||, >= 90, _) produce values and must cover every case.
    • 

  • Functions declare their types; => for one expression; named parameters in {}, with required or defaults. Functions are values.
    • 




Quick check answers: 1. 4.5 (a double) and 4 (an int). 2. final: the value is only known when the program runs. 3. 'Total: $total'.

Project {{n}}.3 · Challenge


The change machine
