1. /menu?q=co answers 200 with one drink, the Cookie: the server keeps every drink whose name contains “co”, ignoring case. /nothing answers 404 with {"error": "Not found"}: no route matches it, and the last else of the server catches every address it does not know.
  2. The failed state, with the button “Try again”. The message is not the server’s this time, because there is no server to answer: it is the ClientException of the http package, something like “Connection refused” (in a browser, “XMLHttpRequest error”). That is a good reason to catch http.ClientException in _send and throw ApiException('Cannot reach the café. Check your connection.') instead: people should never see the words of a library. After starting the server, “Try again” loads the menu.
  3. Map<String, dynamic> toJson() => {'id': id, 'name': name, 'price': price, 'image': image};. The test: final d = Drink(id: 1, name: 'Latte', price: 45, image: 'latte'); final back = Drink.fromJson(d.toJson()); then expect each field of back to equal the field of d. To compare whole objects with one expect, give Drink an operator == and hashCode; Book 6 shows packages that write them for you.
  4. In handle, before the last else: } else if (request.method == 'GET' && path == '/hours') { await send(response, 200, {'open': '8:00', 'close': '22:00'}); }. Check it with curl -s localhost:8080/hours. In the app, add Future<(String, String)> hours() to CafeApi returning a record, load it once in the page’s State, and show it with a FutureBuilder under the list, as in Section {{n}}.2; or keep it in MenuModel and load both with Future.wait (Chapter 4).
  5. In load, do not clear drinks; on failure, set status to failed only if drinks is empty, and otherwise keep ready and set a flag stale = true that the page shows as a small MaterialBanner above the list. It is better for people when old data is still useful: a menu that changes once a day, news, a list of orders that were already placed. It is dangerous when old data can lead to a wrong decision: a price that may have changed before paying, a stock count, a balance. Then the app must say clearly that the data is old, and refuse the action until it is fresh.
