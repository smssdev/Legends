1. sounds = await prefs.getBool('sounds') ?? true;. The default answers the question “what should someone who never touched this switch get?”, and a sounds setting that is on by default must read true when nothing was saved. Using false would silently turn the sounds off for everyone on their first visit.
  2. The key dark with the value true: on the web, SharedPreferencesAsync writes each key to the browser’s local storage, its value encoded as JSON text. (The older SharedPreferences interface adds flutter. before every key.) This is also a good reminder of the warning in Section {{n}}.1: anyone with the device can read and change it.
  3. Future<void> clear() async { final file = await _file; if (await file.exists()) { await file.delete(); } }. The test adds an order, calls clear() twice, and expects load() to be empty. The exists check is what makes the second call safe: deleting a missing file throws.
  4. OpenDatabaseOptions(version: 2, onCreate: (db, v) => db.execute('CREATE TABLE notes (id INTEGER PRIMARY KEY AUTOINCREMENT, text TEXT NOT NULL, done INTEGER NOT NULL, created INTEGER NOT NULL DEFAULT 0)'), onUpgrade: (db, from, to) async { if (from < 2) { await db.execute('ALTER TABLE notes ADD COLUMN created INTEGER NOT NULL DEFAULT 0'); } }). onCreate builds the newest design for new installs; onUpgrade brings old ones up to it step by step, and if (from < 2) leaves room for a future if (from < 3). Old notes get 0, which the app can show as “unknown date”.
  5. Only CafeApi (or a small cache class it uses) and MenuModel change. CafeApi.menu writes the body to menu.json in getApplicationCacheDirectory() after a success; MenuModel.load, on failure, reads that file and, if it exists, sets status to ready with a flag fromCache = true, shown as a small note above the list. Drink, the pictures and the list itself do not change. This is the “professional habit” of the chapter at work: storage and network live behind small classes, so a feature like this touches two of them and no screen logic.
