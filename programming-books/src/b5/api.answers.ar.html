1. /menu?q=كو يجيب برمز 200 ومشروب واحد، الكوكيز: فالخادم يُبقي كل مشروب يحتوي اسمه على «كو». و/nothing يجيب برمز 404 و{"error": "غير موجود"}: فلا مسار يطابقه، وelse الأخيرة في الخادم تلتقط كل عنوان لا يعرفه.
  2. حالة الفشل، بزر «أعد المحاولة». والرسالة هذه المرة ليست رسالة الخادم، لأنه لا خادم ليجيب: إنها ClientException من حزمة http، شيء مثل «Connection refused» (وفي المتصفح «XMLHttpRequest error»). وهذا سبب جيد لالتقاط http.ClientException في _send ورمي ApiException('تعذّر الوصول إلى المقهى. تحقق من اتصالك.') بدلاً منها: فالناس يجب ألا يروا كلمات مكتبة أبداً. وبعد تشغيل الخادم، تحمّل «أعد المحاولة» القائمة.
  3. Map<String, dynamic> toJson() => {'id': id, 'name': name, 'price': price, 'image': image};. والاختبار: final d = Drink(id: 1, name: 'لاتيه', price: 45, image: 'latte'); final back = Drink.fromJson(d.toJson()); ثم expect لكل حقل من back أن يساوي حقل d. ولتقارن الكائنين كاملين بـ expect واحدة، أعطِ Drink المعامل operator == وhashCode؛ ويعرض الكتاب السادس حزماً تكتبهما عنك.
  4. في handle، قبل else الأخيرة: } else if (request.method == 'GET' && path == '/hours') { await send(response, 200, {'open': '8:00', 'close': '22:00'}); }. وجرّبه بـ curl -s localhost:8080/hours. وفي التطبيق أضف إلى CafeApi الدالة Future<(String, String)> hours() التي تعيد record، وحمّلها مرة واحدة في State الصفحة، واعرضها بـ FutureBuilder تحت القائمة كما في القسم {{n}}.2؛ أو احفظها في MenuModel وحمّل الاثنين معاً بـ Future.wait (الفصل 4).
  5. في load لا تُفرغ drinks؛ وعند الفشل اجعل status يساوي failed فقط إن كانت drinks فارغة، وإلا فأبقِ ready وفعّل علامة stale = true تعرضها الصفحة MaterialBanner صغيراً فوق القائمة. وهذا أفضل للناس حين تبقى البيانات القديمة مفيدة: قائمة تتغير مرة في اليوم، أو أخبار، أو قائمة طلبات أُرسلت فعلاً. وهو خطير حين قد تقود البيانات القديمة إلى قرار خاطئ: سعر ربما تغيّر قبل الدفع، أو كمية في المخزن، أو رصيد. وحينها يجب أن يقول التطبيق بوضوح إن البيانات قديمة، ويرفض الفعل حتى تتجدد.
