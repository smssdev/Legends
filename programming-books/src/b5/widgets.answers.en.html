1. MaterialApp → Scaffold → (AppBar → Text) and (Padding → Column → three InfoRows). Each InfoRow → Padding → Row → Icon, SizedBox, Text. Counting MaterialApp as level 1, the deepest widgets, the icons and texts of the rows, are on level 8. Real screens are often twenty or thirty levels deep; that is normal, and it is why small widgets of your own keep the code readable.
  2. (a) Padding(padding: EdgeInsets.all(20), child: ...). (b) SizedBox(width: 20) between them, or spacing: 20 on the row. (c) A Container (or DecoratedBox) with a BoxDecoration: color: Colors.white, borderRadius and boxShadow; or simply a Card. (d) Center.
  3. Add a field final Color color; and the parameter this.color = Colors.teal to the constructor (a default value keeps it optional, and it can be const because Colors.teal is a constant). In build, use Icon(icon, color: color). On the page: InfoRow(icon: Icons.place, text: '...', color: Colors.red).
  4. (a) Stateless: it shows what it is given. (b) Stateful, or better, stateless with its value and a callback from the parent, like the star rating in Project {{n}}.3: that is how Flutter’s own Checkbox works. (c) Stateless: nothing changes. (d) Stateful: the seconds change every second, and the State also keeps the timer that ticks them.
  5. Nothing changes on the screen: likes really becomes 3, but nobody told Flutter to build the widget again. Hot reload rebuilds every widget, keeping the state, so after r the screen suddenly shows 3 likes and a full heart. The value was right all along; only the picture was out of date. That is exactly what setState prevents.
