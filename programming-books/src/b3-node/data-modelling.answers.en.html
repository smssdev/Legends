  2. The generator sees a text column; the CHECK is a rule, not a type, so it cannot turn it into a union by itself. Tell it with --overrides: '{"columns":{"orders.status":"\"pending\" | \"paid\" | \"shipped\" | \"cancelled\""}}'. The run in the code repository generates status: "pending" | "paid" | "shipped" | "cancelled". Because the column has a default, wrap it as Generated<…> in the override, so inserts may still leave it out. A PostgreSQL ENUM type would be read as a union automatically, at the cost of a migration for every new value.
