1. The salt makes every user’s hash different, so identical passwords do not show as identical hashes, one computation cannot attack every row at once, and precomputed tables are useless. It does not make each guess slower: SHA-256 is still billions of guesses a second, so a weak password in any single row falls in seconds. The fix is a slow, memory-hard function (scrypt, Argon2, bcrypt), with a salt.

  5. Sign-in returns two tokens: an access token, a JWT valid for 10 minutes carrying the user id and role, and a refresh token, random bytes stored as a hash in the database with a long expiry. Every API request checks only the JWT’s signature and expiry, without a database query. When the access token expires, the client sends the refresh token to POST /auth/refresh, which checks it in the database, replaces it with a new one (so a stolen refresh token works only once), and returns a new JWT. Sign-out deletes the refresh token; the access token stays valid for up to 10 minutes, which is the price. The gain is no database lookup on most requests, which matters when many services check tokens; for a single API with a database already involved in every request, this chapter’s sessions are simpler.
