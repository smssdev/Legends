The request shrinks, and so does the cost, but the reviewer can no longer see that a behaviour changed without a test, or that the documentation now says something false. A middle way is to send the full list of changed files, and the full diff only for the code.
  4. Real verdicts can differ between runs on borderline diffs. To stabilise: make the criteria in the prompt precise (“a blocker is…”), keep the schema strict, use a fixed model version, and treat a disagreement as information: fail only when the review finds a blocker it can name with a file and a line, and let a person decide on the rest. Running twice and requiring agreement is possible, at twice the cost.
