الفصل {{n}}

Claude Code للفرق والتكامل المستمر

في هذا الفصل ستتعلم أن

  • تطبّق إعدادات الفريق والإعدادات الشخصية طبقة فوق طبقة، وتعرف أيها يغلب
  • تشغّل Claude Code في التكامل المستمر، بلا إنسان أمام لوحة المفاتيح
  • تحصل على حكم كبيانات منظّمة يستطيع السكربت التصرف بها
  • تُبقي تشغيلات التكامل المستمر صغيرة ومحدودة ورخيصة
  • تُبقي الناس أصحاب القرارات التي تُخبرها المراجعة الآلية

الفريق الذي يستخدم Claude Code يحتاج شيئين لا يحتاجهما المطور الواحد. الأول قواعد مشتركة لا يستطيع شخص أن يرخيها خطأً: ما يُسمح لكل جلسة به، وما لا يُسمح لأي منها. والثاني الأتمتة: Claude Code يعمل مع كل طلب دمج، في خط العمل نفسه مع الاختبارات، دون أن يكتب أحد. وهذا الفصل يبني الاثنين، ويُظهر كم يكلّف كل منهما.

الإعدادات، والرفض، وسكربت التكامل المستمر، ورموز خروجه، وتكاليفه سلوك Claude Code حقيقي. أما الأحكام فمن خادم التدريب، مكتوبة لتتوقف على الفرق الذي تلقاه: تمنع الإجمالي غير المقرّب، وتمرّر المقرّب.

يحفظ الفريق .claude/settings.json؛ ويستطيع كل مطور إضافة .claude/settings.local.json، الذي يتجاهله git. وهنا يسمح الفريق بالاختبارات ويرفض الدفع، وقد سمح أحد المطورين بالدفع لنفسه:






رُفض الدفع. فحين تتعارض القواعد، يغلب الرفض السماح، أينما كُتب كل منهما، فلا يستطيع ملف شخصي إلغاء رفض الفريق. وهذه الخاصية التي يحتاجها الفريق: يمكن إضافة السماح حيث يحتاجه الناس؛ وتبقى الأشياء القليلة التي لا يجوز لأحد فعلها مرفوضة. والمؤسسات التي تحتاج أكثر تستطيع تثبيت إعدادات مُدارة (managed settings) على كل جهاز، تتقدم على الاثنين ولا يستطيع المستخدمون تغييرها.



نصيحة
اكتب حالات رفض الفريق أولاً، ثم السماح. فالرفض قصير (الدفع إلى الفرع الرئيسي، وقراءة مجلد الأسرار، وحذف البيانات) ونادراً ما يتغير؛ والسماح ينمو مع العمل، ويمكن أن يعيش أقرب إلى الناس الذين يحتاجونه.



{{n}}.2 مراجعة في التكامل المستمر



في التكامل المستمر لا يستطيع أحد الموافقة على استدعاء أداة، فأأمن تشغيل هو الذي بلا أدوات أصلاً: يقرأ Claude Code الفرق من المدخل القياسي، ويجيب، ويتوقف. وثلاثة خيارات تجعله مناسباً لخط العمل: --tools "" فلا يقرأ إلا ما يُعطى، و--max-budget-usd فلا يتجاوز التشغيل ميزانيته، و--json-schema فيعود الحكم بيانات:








الفرع يضيف الضريبة إلى الإيصالات، تغيير الفصل 7، مع مسألة التقريب التي وجدتها مراجعته. وخطوة التكامل المستمر:






الحكم كائن، لا فقرة: ok خاطئة والعائق يسمّي الملف والمشكلة، فيخرج السكربت بـ 1 ويفشل خط العمل. ومع --json-schema، يعطي Claude Code النموذج أداة ليبلّغ بجوابه بذلك الشكل، ويعيده في structured_output؛ فلا يضطر السكربت أبداً إلى تحليل نثر.



وانظر إلى التكلفة أيضاً: سنت ونصف. فتشغيلات الفصول السابقة كلّفت نحو اثني عشر سنتاً للدور، معظمها لتعليمات Claude Code وأوصاف أدواته؛ وبلا أدوات، لا يبقى ما يُرسل إلا الفرق والطلب تقريباً. وفي خط عمل يعمل مع كل دفع، ذلك الفرق هو الميزانية.

انتبه
الفرق مدخل من فاتح طلب الدمج، وطلب دمج من خارج الفريق قد يحوي نصاً مكتوباً لتوجيه المراجع. والمراجعة بلا أدوات لا تستطيع إلا أن تجيب؛ ولا تستطيع تشغيل شيء. فلا تعطِ تشغيل تكامل مستمر أدوات تكتب، ولا أسراراً لا يحتاجها، على كود لم ينظر فيه أحد من الفريق.



{{n}}.3 في خط العمل



يشغّل ملف سير العمل السكربت نفسه مع كل طلب دمج، بمفتاح الـ API من أسرار المستودع، ووصول للقراءة فقط إلى محتواه، وحد زمني (المشروع {{n}}.3 يفحص الملف). وتنشر Anthropic أيضاً GitHub Action لـ Claude Code، يستطيع مراجعة طلبات الدمج والرد على التعليقات التي تذكره؛ والمبادئ نفسها: أقل الأدوات التي تؤدي المهمة، وحد للإنفاق، ومخرجات يستطيع السكربت قراءتها.



وما تُنتجه المراجعة الآلية معلومات لإنسان، لا قرار. فالمراجعة الفاشلة يجب أن تمنع الدمج كما يمنعه الاختبار الفاشل؛ والناجحة يجب ألا توافق على شيء. وما زال طلب الدمج يحتاج مراجعاً إنساناً، يبدأ الآن والمشكلات الآلية قد وُجدت.



اختبر نفسك
  1. لماذا رُفض الدفع، مع أن الإعدادات الشخصية سمحت به؟
  2. ماذا يضيف كل من --tools "" و--max-budget-usd و--json-schema في التكامل المستمر؟
  3. لماذا كلّفت مراجعة التكامل المستمر عُشر التشغيلات السابقة؟
الإجابات في آخر الفصل، بعد الملخص.



عادة المحترفين
تتبّع ما تجده المراجعة الآلية وما يجده الناس بعدها، لشهر. فإن ظل الناس يجدون ما تفوته، فحسّن تعليماتها؛ وإن ظلت تمنع ما يوافق عليه الناس، فخففها. فالمراجع الآلي الذي لا يقيسه أحد يتحول إلى ضجيج يتجاهله الجميع.

  • إعدادات الفريق محفوظة، والشخصية لا، والرفض يغلب السماح أينما كُتب كل منهما.
    • 

  • في التكامل المستمر، شغّل Claude Code في وضع الطباعة بلا أدوات، وبحد إنفاق، ومخطط JSON للحكم.
    • 

  • يقرأ السكربت structured_output ويُفشل البناء عند العائق؛ وتنجح الخطوة نفسها بعد إصلاح المشكلة.
    • 

  • أدوات أقل تعني طلباً أصغر في كل دور: كلّفت مراجعة التكامل المستمر نحو عُشر تشغيل بأدوات Claude Code كاملة.
    • 

  • المراجعات الآلية تُخبر الناس؛ ولا توافق.

إجابات «اختبر نفسك»: 1. لأن إعدادات الفريق ترفض Bash(git push:*)، والرفض يغلب السماح، حتى السماح في ملف شخصي. 2. --tools "" يزيل كل أداة، فلا يستطيع المدخل غير الموثوق أن يجعله يتصرف؛ و--max-budget-usd يوقف التشغيل الذي سينفق أكثر من اللازم؛ و--json-schema يعيد الحكم بيانات يستطيع السكربت فحصها. 3. لأنه بلا أدوات، لا يحمل الطلب أوصاف أدوات، وأقل بكثير من تعليمات Claude Code نفسه: الفرق والطلب في الغالب.
