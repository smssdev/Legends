1. One. A 401 is not in the list of temporary errors, so withRetry throws at once: a wrong key will be just as wrong in 200 milliseconds. Retrying it would multiply the waiting and, at a real provider, could look like an attack and get the key blocked.
  2. Wrap complete: note the start, await the call, and write one line such as {"provider":"hosted","ms":812,"ok":true}, also on failure, with the error. One structured line per call is enough to answer “is it slow?”, “is it failing?” and “which provider?” later.
  3. Send stream: true, read response.body as text, split it into lines, take the ones that start with data: , stop at data: [DONE], parse the JSON of the others and pass each piece of text to onText. A fake server that writes three such lines with small pauses tests it without any account.
  4. Before calling the provider: if check(question) fails, answer 413 with its error; if allow(user) is false, answer 429 with a Retry-After header. Both refusals cost nothing and protect the model for everyone else.
  5. Wrap the call: try the hosted provider with retries; if it still fails, call the local provider and add fallback: true to the result. The user should see a normal answer, perhaps with a small note (“answered by our backup assistant”) if the backup is noticeably weaker. Log every fallback: many of them mean the main provider needs attention.
