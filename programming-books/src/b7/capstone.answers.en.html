1. Each new case is a question, the id of the document that answers it, and a word the right answer must contain; write the documents first if they do not exist. If the score drops, read the lines: “MISSED” means search did not bring the document, often because the question uses words the document does not (“ship” for “deploy”); “WRONG” with “found” means the model had the document and misread it, or the expected word is too narrow, as in Section 17.7. Read the answer before you judge.
  2. With one source, questions that fall between two documents are the first to change, and they change in the “found” column: the one nearest document is not always the one that answers. If the right document is still found, the answers usually stay right, and the prompt is shorter. The evaluation tells you whether the saving is worth it; two sources cost a line of prompt.
  3. The secrets check in lib/checks.mjs, if the model repeats the key: the answer contains a string shaped like a key, so the result has the problem “a secret” and ok is false, whatever the model wrote around it. The team should remove the key from the document, rotate it, because it has been in a shared file, and add a scan for secrets to the place where documents are committed, as in Chapter 15. The check is the last line of defence, not the first.
  4. Read the file line by line with JSON.parse, and count the lines and the lines with ok: false. The log as built does not record refusals, so add a refused field to the entry first; then count them, and list their questions. The owner of the documents should read it weekly: refusals are missing pages, failed checks are answers to look at, and a question asked by many hashed users is a page to make easier to find.
  5. Give assistant a provider option and call provider.complete({system: rule, prompt}) where it now prompts the session; for the hosted provider, pass the prompt through redact before sending and restore on the answer, and run the secret scan on the prompt too. Start the fake server of Chapter 13, run the evaluation against each provider, and compare the scores. With the fake server the hosted scores test your wiring, not a model: the point is that the same evaluation runs unchanged against any provider you choose.
