1. With a “sandwiches” document in the handbook, search finds it first, and the answer should cite it: “We do not sell food other than cakes [food]”. The fixed “not in our documents” was the right answer before; a cited answer is a better one now. Each new document turns a refusal into an answer, which is how a support assistant grows: from the questions it could not answer.
  2. Run your three questions through nearest with k = 1. Questions that use the handbook’s own words are easy; the useful test is questions in customers’ words, synonyms, or another language. Any miss is worth a look: is the document unclear, is the question ambiguous, or does it belong to two documents?

Asking for a quote first (“quote the sentence you use, then answer”) makes the model look for the sentence before deciding there is none, and gives you something to check: the quote must appear in the cited document, exactly. Whether it fixes the oat milk refusal is a measurement to make, not a promise; either way, a verifiable quote makes every answer easier to trust or reject.
  4. Save {id, text, vector} for each document in a JSON file, and load it instead of embedding at start. Rebuild when a document changes, when a document is added or removed, and when the embedding model changes: vectors from two different models cannot be compared. Store the model’s name in the file and refuse to load a file made by another one.
  5. Score each document by embedding similarity plus a small weight times the number of shared words, and rank by the sum. Embeddings handle paraphrase (“big latte”); shared words handle exact tokens that embeddings blur: names, product codes, order numbers. Search engines call this hybrid search, and it usually beats either method alone on real questions.
