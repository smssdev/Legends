Chapter {{n}}

Components and Templates

In this chapter you will learn to

  • explain the core idea of Vue: the screen follows the data, by itself
  • write single-file components, with a script, a template and scoped styles
  • use the template syntax: text, bindings, classes, styles and directives
  • pass data down with typed props, content with slots, and events up with emits
  • render lists with keys, and choose what to show with v-if
  • give a component its first piece of state, and calculate values with computed

In Book 1 you built a tasks app with the DOM: find an element, listen for an event, change the element. It worked, but every new feature meant more code that changed the page by hand, and more chances to forget to update one part of it. Vue turns this around. You write a template that describes the screen for the current data, and Vue keeps the page matching it. When the data changes, Vue knows exactly which parts of the page used it, and updates only those.

Remember the tip at the end of the quiz project in Book 1? “The data is the truth, and show() draws it on the page.” That is exactly Vue, except that you never call show(): Vue notices the change and redraws for you.

{{n}}.1 A component is a file

A Vue app is built from components: pieces of the screen with their own data and behaviour, such as a product card or a like button. Each one usually lives in its own single-file component, a file ending in .vue, with up to three parts:




    

  • <script setup lang="ts"> holds the component’s TypeScript. Everything declared here is available to the template.
    • 

  • <template> describes the HTML. Double braces, {{ }}, insert the value of an expression as text.
    • 

  • <style scoped>, which we will meet below, holds CSS that applies only to this component.
    • 




A browser cannot read .vue files. A build tool such as Vite, with Vue’s compiler, turns each one into a JavaScript module that exports the component. To see the HTML a component makes, we can ask Vue to render it to a string, as a server would:








In a real app you mount the root component once, into an element of the page: createApp(App).mount("#app"). From then on, Vue owns everything inside that element.



{{n}}.2 Template syntax



A template looks like HTML, with a few additions for data:










    

  • Text: {{ count }} inserts a value. Any JavaScript expression works, such as {{ total.toFixed(2) }}, but not statements like if or for.
    • 

  • Attributes: v-bind:disabled="isEmpty", shortened to :disabled, sets an attribute from an expression. Notice the output: when the value is false, Vue leaves the attribute out completely.
    • 

  • Classes and styles: :class takes an object whose keys are added when their values are true, and merges with a plain class. :style takes an object of CSS properties.
    • 

  • Safety: text in {{ }} is always escaped, so a product named <script> is shown, not run. The directive v-html inserts raw HTML; never use it with data that users wrote (Chapter {{n+10}}).
    • 




{{n}}.3 Props, slots and emits



Components become useful when they can be reused with different data. Props are the inputs of a component, declared with defineProps and a TypeScript type. First, the shop’s data:






A card for one product. It receives the product as a prop, and tells its parent when the button is pressed by emitting an event, declared with defineEmits:






A section with a title, and a <slot>: a hole that the parent fills with any content it likes:






And the shop, which puts them together:








Three rules make components work well together:


    

  • Data flows down, events flow up. A parent passes props to a child; the child never changes them. When the child needs something to change, it emits an event, and the parent, which owns the data, decides. The parent listens with @add="…", exactly as it would listen to @click.
    • 

  • A colon means JavaScript. title="Bit's shop" passes a string; :product="product" passes the value of the expression product. Forgetting the colon passes the word itself.
    • 

  • Slots compose. ShopSection does not know or care what is inside it. The same section can hold a grid of products, a form, or a message.
    • 




Tip: small components with good names
When a template grows past what fits on one screen, or when you want to give a part of it a name, it is time for a new component. A file called ProductCard.vue explains itself; a <div> forty lines deep does not.



{{n}}.4 Lists and keys



v-for="product in products" repeats an element for every item of an array. Each repeated element needs a :key, a value that is unique among its siblings and stays the same for the same item, usually its id.



Keys tell Vue which item is which between two updates. Without them, when you delete the first product, Vue sees “one item fewer” and updates the remaining elements in place, so anything those elements remember, such as the text typed in an input or a running animation, ends up next to the wrong product. With keys, Vue knows that product 1 is gone, and removes exactly its element.



Watch out: the index is not a key
v-for="(p, i) in products" :key="i" stops the warning but not the problem: after a deletion, the item that was second becomes first and takes key 0. Use an id from the data. An index is only safe for a list that never changes order or length.

v-if, v-else-if and v-else choose between elements. A component that shows a list of orders must handle four situations, and good interfaces design all four:

Tip: v-if or v-show?
v-if adds and removes the element. v-show keeps it in the page and only toggles display: none. Use v-show for something that switches very often, such as a dropdown, and v-if for everything else, so hidden parts cost nothing.

{{n}}.6 Events and a first piece of state



@click (short for v-on:click) runs code when an event happens. To make a component remember something between updates, such as whether it is liked, give it state with ref:










ref(41) returns a small box, a reactive reference, whose current value is in .value. In the script you write likes.value; in the template Vue unwraps it for you, so you write likes. Changing .value is all it takes: Vue knows which parts of the template read likes, and updates them. The next chapter explains how this works.



Every instance of a component gets its own state. The two buttons above share the code, but not the liked and likes boxes.



{{n}}.7 Computed values, and pure templates



When a value can be calculated from other values, calculate it: the followers shown are the followers plus one if you follow; the visible products are the products that match the filter. Vue offers two ways, and the difference matters:










A function called in the template runs every time the template is drawn, once for every place it appears. A computed value runs once, remembers its result, and runs again only when something it read changes. Use computed for anything derived from state.



The counters in this example are there to show the difference; in real code, a template and a computed value must have no side effects. They should only calculate. Vue decides when and how often to draw, and code that changes things while drawing gives different results each time. Changes belong in event handlers.



Professional habit: keep the logic in the script
A template that reads {{ items.filter((i) => i.inStock).length }} works, but it hides logic where it is hard to test and to name. Give it a name in the script, const inStock = computed(…), and the template stays a simple description of the screen.

Summary



    

  • In Vue, the screen follows the data: you describe it in a template, and Vue keeps the page matching it.
    • 

  • A single-file component has a <script setup>, a <template> and optional <style scoped>.
    • 

  • Templates use {{ }} for text, : for bindings, @ for events, and :class and :style objects. Text is escaped.
    • 

  • Props pass data down, typed with defineProps; slots pass content; emits pass events up.
    • 

  • v-for renders lists, always with a stable key. v-if chooses what to show; design all four states.
    • 

  • ref gives a component state; computed derives values and remembers them. Templates only calculate.
    •

Accessible tabs
