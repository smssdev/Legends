1. With Curves.linear the height at 50 ms is about 110 (a sixth of the way from 96 to 180), against 130 with Motion.move; at 150 ms it is 138 against 170. The linear card starts slower and arrives at full speed, which is why it feels like it hits a wall at the end.
  2. The transitionBuilder: (child, animation) => SlideTransition(position: Tween(begin: const Offset(0, 1), end: Offset.zero).animate(animation), child: child). Wrap it in a ClipRect so that the numbers do not slide over the card’s title. Nothing else changes: the key still makes each number a new child.
  3. Stop the repetition and finish the current turn: turns.stop(); turns.animateTo(1, curve: Motion.enter), which takes the ring from where it is to the end of the turn and stops there. Calling stop() alone freezes it mid-turn; calling reset() makes it jump back to the start. When the next order begins, turns.repeat() again.
  4. flightShuttleBuilder: (context, animation, direction, from, to) => ClipOval(child: to.widget) on both heroes. It is needed when the two ends do not have the same shape, for example a square photo in the list and a round one on the page, or when the destination widget depends on something that is not there during the flight (a Material ancestor, text styles). With two circles, as here, the default shuttle is already right.
  5. Read every .dart file under lib/ except lib/motion/, and report each line that matches RegExp(r'Duration\(\s*milliseconds:') as file:line, expecting none. It protects the motion tokens the way Chapter 7’s guard protects colours and spacing: new screens cannot invent their own speeds. It should allow durations that are not motion, such as a network timeout or a debounce, so either keep those in a named constant in their own layer (lib/data/, excluded from the check) or allow them line by line with a short, reviewed list.
