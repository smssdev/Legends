1. A const is decided when the app is compiled, not at sign-in; a value received at run time cannot be one. What the colleague means is a variable in memory, which is right for the access token, as TokenStore does. But a const secret would be the worst of both: compiled into the app, the same for every user, and readable with strings as section {{n}}.3 showed.
  2. Add (RegExp(r'\b(?:\d[ -]?){9,15}(\d{4})\b'), (m) => '**** ${m[1]}'): nine to fifteen digits, each perhaps followed by a space or hyphen, then the last four, captured. Test a spaced card number, a plain one, and an order number of five digits that must stay untouched.
  3. On Android, FLAG_SECURE on the window blocks screenshots and screen recording and hides the screen in the recent-apps list (set from Kotlin, or with a plugin, only on that page). iOS has no equivalent block; the app can detect a screenshot after it happened, or blur its content when the app moves to the background. Neither stops a second phone pointed at the screen: the real protection is that the code is single-use and checked on the server.
  4. A certificate changes at every renewal; its key pair can stay the same if the server team renews with the same key. Pinning the hash of the public key (the SubjectPublicKeyInfo, SHA-256, base64) then survives renewals. Get it with openssl x509 -in cert.pem -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | base64, and in Dart, compare it in HttpClient.badCertificateCallback or a custom check on connectionInfo, while keeping normal validation on.
  5. A root or jailbreak check is a speed bump: it stops casual users of rooted phones and makes automated abuse a little more work, but the attacker controls the phone and can patch the check out of the app. Payments must be protected where the attacker has no control: the payment provider’s own SDK and server, server-side verification of every transaction, and, where available, platform attestation (Play Integrity, App Attest) whose verdict your server checks, not the app.
