1. expect(total(const [Line('latte', 45, 3)], DateTime(2026, 11, 23, 16)), 108);. The subtotal is 135, and 20% of it, computed as 135 * 20 ~/ 100, is 27, so the total is 108. It is an int, never 108.0, because prices are kept in whole pounds and ~/ divides without leaving integers: money in floating point collects rounding errors.
  2. Inside the MockClient callback, add expect(request.method, 'GET');. An expect that fails inside the callback fails the test, because the error travels back through the Future that menu() returns.
  3. Pump the screen with a FakeMenu whose Completer is never completed, then expect(find.textContaining('Total'), findsNothing) and expect(find.byType(CircularProgressIndicator), findsOneWidget). It passes today because the total is built inside the data branch; the test makes sure nobody moves it out of there without noticing.
  4. Load a font file before the test draws, and use it in the theme: final loader = FontLoader('Roboto')..addFont(rootBundle.load('assets/fonts/Roboto-Regular.ttf')); await loader.load();, with ThemeData(fontFamily: 'Roboto'), and the same for the icon font. You gain images a designer can review, and catch problems like text that overflows or wraps. You risk goldens that differ between machines, because real fonts are drawn with anti-aliasing that depends on the platform: generate and compare such goldens on one kind of machine only, usually the CI runner.
  5. A Linux CI runner can run it as this chapter did: it needs Flutter, the Linux desktop tools (clang, cmake, ninja-build, pkg-config, libgtk-3-dev) and a virtual screen, then xvfb-run flutter test integration_test -d linux. The first build takes a minute or two and each journey a few seconds; keep the pull-request suite under about ten minutes, and run longer journeys, or the same tests on an Android emulator, after merging or every night.
