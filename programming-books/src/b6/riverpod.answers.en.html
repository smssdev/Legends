1. The first tap throws: build returns const {}, and a constant map cannot be changed, so state[item] = … fails with an UnsupportedError and every test that adds to the basket fails with it. Make the first state a plain {} and the error disappears, which is worse: the map now changes, but state is the same object, so nothing is notified, the circles on the screen keep showing 0, and the select test counts one build each. Constant first states are a cheap guard against this mistake.
  2. The order is placed and the basket empties, but “Your orders” still says “Nothing ordered yet”: the history was loaded once and nothing told it that it was stale. It catches up only when something rebuilds it from scratch: the Retry button, leaving and reopening a screen whose provider was disposed, or restarting the app. Invalidating at the place where data changes is what keeps every screen right without knowing about each other.
  3. ref.listen(placeControllerProvider, (previous, next) { if (next.value case Ok(:final value)) { ScaffoldMessenger.of(context).showSnackBar(SnackBar(content: Text('… ${value.id}'))); } }); at the start of build. listen runs a callback once per change, which is what a side effect needs: a snack bar, a navigation, a sound. watch only rebuilds, and showing a snack bar from build would show it again on every rebuild, even when nothing new happened.
  4. FutureProvider(…, retry: (count, error) => null). The offline screen then shows the error at once instead of a value that stays loading while retrying; the Retry button still works, because it invalidates. Choose it when a retry cannot help (a 403, a validation error, a missing record), or when the person should decide, for example on metered data; keep automatic retries for transient failures such as timeouts.
  5. historyProvider.overrideWith((ref) async => [order1, order2, order3]). It skips the source, the DTOs and the repository’s mapping: good for screenshots and for testing how the page draws a known list, but it no longer tests that the data layer produces that list, and new orders never appear, because invalidating the history runs the override again and returns the same three. Overriding the source keeps every layer in play.
