JavaScript غير المتزامنة وfetch

ستتعلم في هذا الفصل أن

  • تفهم لماذا يحدث بعض العمل في JavaScript «لاحقاً»
  • تستخدم المؤقتات والوعود وasync وawait
  • تحمّل بيانات JSON من خادم بـ fetch
  • تتعامل مع الأخطاء بـ try وcatch، وتعرض حالتي التحميل والخطأ
  • تجعل المتجر يحمّل منتجاته من الخادم

بعض الأشياء تستغرق وقتاً. فطلب بيانات من خادم في قارة أخرى قد يأخذ نصف ثانية، واتصال هاتف بطيء قد يأخذ خمس ثوانٍ. ولو توقفت JavaScript وانتظرت لتجمدت صفحتك كلها: لا تمرير ولا نقر ولا شيء. بدلاً من ذلك تبدأ JavaScript العمل البطيء، وتمضي في أشياء أخرى، وتعود حين تجهز النتيجة. ويُسمى هذا البرمجة غير المتزامنة، وهي الطريقة التي يتحدث بها كل تطبيق حديث مع الإنترنت.

تخيّل أنك تطلب الطعام في مطعم. لا تقف في المطبخ حتى ينضج، بل تجلس وتتحدث، ويأتيك النادل بالطعام حين يجهز. وJavaScript تتعامل مع المهام البطيئة بالطريقة نفسها!

الكود الذي يُنفَّذ سطراً بعد سطر، وكل سطر ينتظر الذي قبله، كود متزامن (synchronous). والكود الذي يبدأ مهمة ويستمر دون انتظار نتيجتها كود غير متزامن (asynchronous). والمؤقتات وطلبات الشبكة وقراءة الملفات كلها غير متزامنة.



13.2 الوعود وasync وawait



الوعد (promise) كائن يمثل نتيجة لم تجهز بعد: «أعدك أن أعطيك قيمة لاحقاً، أو أن أخبرك بما ساء». والوعد يكون أولاً معلّقاً، ثم إما يُوفى بقيمة أو يُرفض بخطأ.



وJavaScript الحديثة تسهّل استخدام الوعود بكلمتين. فالدالة الموسومة بـ async تستطيع استخدام await، التي توقف تلك الدالة وحدها حتى يجهز الوعد، دون أن تجمّد أي شيء آخر:








داخل makeTea تحدث الخطوات بالترتيب، فيُقرأ الكود كأنه وصفة. لكن أثناء انتظارها يستمر بقية البرنامج: «في الأثناء، أجهّز المائدة» طُبعت ثانياً. والدالة async تُرجع دائماً وعداً، و.then() تشغّل دالة بنتيجته حين يجهز.



نصيحة
نادراً ما ستنشئ وعوداً بنفسك كما تفعل wait. ففي أغلب الأحيان تستلمها من دوال جاهزة مثل fetch، وكل ما تفعله أن تنتظرها بـ await. وتذكّر القاعدة: await لا تعمل إلا داخل دالة async (أو في أعلى مستوى من الوحدة).

13.4 حين يسوء شيء: try وcatch



الشبكة غير موثوقة: الهواتف تفقد الإشارة، والخوادم تتعطل، والعناوين تتغير. والكود الاحترافي يتوقع الفشل. فحين يُرمى خطأ، تقفز JavaScript إلى أقرب catch:



try {
  // code that might fail
} catch (error) {
  // what to do if it does: error.message says what happened
}



في fetch.js أرجع طلب /api/missing الرمز 404، فرمت getJson خطأً، وطبع catch رسالة هادئة بدل أن ينهار البرنامج. وفي صفحة الويب يتيح لك النمط نفسه أن تعرض «حاول مرة أخرى» لطيفة بدل صفحة معطوبة.



عادة المحترفين: ثلاث حالات
كل جزء من الصفحة يحمّل بيانات له ثلاث حالات ممكنة: التحميل، والنجاح، والخطأ. صمّم الثلاث واكتب كودها. فالمستخدمون يسامحون الاتصال البطيء إن رأوا أن شيئاً يحدث، ولا يسامحون شاشة فارغة.

async function start() {
  const status = document.querySelector("#status");
  status.textContent = "جارٍ تحميل المنتجات…";
  try {
    const response = await fetch("products.json");
    if (!response.ok) {
      throw new Error(`HTTP ${response.status}`);
    }
    catalog = await response.json();
    status.textContent = "";
    renderProducts();
    renderCart();
  } catch (error) {
    status.textContent = "عذراً، تعذّر تحميل المنتجات. حاول مرة أخرى.";
    console.error(error);
  }
}

  2. أعد استخدام getJson(url): ترمي Error حين تكون response.ok خاطئة.
