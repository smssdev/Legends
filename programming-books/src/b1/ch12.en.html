Chapter 12

The DOM and Events

In this chapter you will learn to

  • connect JavaScript to a web page with a <script> element
  • find elements on a page and change their text, classes and styles
  • create new elements and add them to the page
  • react to clicks, typing and form submissions with events
  • build a real, interactive shop page

Until now your JavaScript has printed its results in the terminal. That is great for learning, but nobody will visit your terminal. In this chapter JavaScript moves into the browser, where it can change the page while people look at it and respond the moment they click. This is the chapter where your pages come alive.

Every like button, every “add to cart”, every chat message that appears without reloading the page: that’s JavaScript and the DOM. After this chapter, you’ll know how all of them work!

12.1 The DOM: the page as objects

When the browser reads your HTML, it builds a tree of objects in memory, one object for each element. This tree is called the DOM, the Document Object Model. You saw it in the Elements panel of DevTools in Chapter 5. JavaScript can read and change this tree, and every change appears on the screen immediately.

To run JavaScript in a page, put a <script> element at the end of the <body>, pointing to your file:

<script src="change.js"></script>

Why at the end? The browser runs the script as soon as it reaches it. At the end of the body, every element above already exists, so your code can find it.

12.2 Finding and changing elements

document.querySelector finds the first element that matches a CSS selector, the same selectors you learned in Chapter 6. Once you have an element, you can change it:









CodeWhat it does



document.querySelector(".note")The first element with class note


document.querySelectorAll("li")All matching elements, as a list you can loop over


element.textContent = "…"Replaces the element’s text


element.classList.add("x")Adds a class (also remove and toggle)


document.createElement("li")Makes a new element, not yet on the page


parent.append(child)Puts an element inside another, at the end






Professional habit: classes, not styles
You could write element.style.background = "yellow". But it is better to add a class and let CSS decide what the class looks like, as change.js does. Then the look stays in the CSS file, where designers and your future self will look for it.



Watch out: textContent, not innerHTML
You will see code that uses innerHTML to put text into a page. It works, but if the text comes from a user, they can sneak in HTML and even scripts, a serious security hole called XSS. Use textContent for text and createElement for new elements, as in this chapter. Book 2 covers web security in depth.



12.3 Events: reacting to people



An event is something that happens on the page: a click, a key press, a form being sent, the mouse moving. You tell an element what to do when an event happens with addEventListener:









Read addButton.addEventListener("click", () => { … }) as: “when addButton is clicked, run this function”. The function is a callback, like the ones you gave to map in Chapter 10. You do not call it yourself; the browser calls it every time the event happens.



Notice the structure of counter.js. The data lives in a variable, count. Event handlers change the data, then call show(), which updates the page from the data. Keeping these three apart (data, changes, display) is the idea behind every modern frontend framework, including React and Vue in Book 2.





EventHappens when



clickAn element is clicked or tapped


inputThe value of a text field changes, on every key press


submitA form is sent, by a button or by pressing Enter


keydownA key is pressed


DOMContentLoadedThe whole HTML has been read

Project 12.1 · Easy


A night mode switch


One button switches the whole page between a day theme and a night theme, and its label always says what it will do next.


You will practise: querySelector, addEventListener, classList.toggle and classList.contains.


    

  1. Create theme.html with a heading, a paragraph and a button with id="theme".
    2. 

  2. In the CSS, write the night colours under body.dark, for example body.dark { background: #1e1b4b; color: #e0e7ff; }.
    3. 

  3. In theme.js, find the button and listen for "click".
    4. 

  4. On each click, call document.body.classList.toggle("dark"): it adds the class if it is missing and removes it if it is there.
    5. 

  5. Update the button’s textContent using classList.contains("dark") and the ternary operator.
    6. 



Hint: JavaScript only switches a class; CSS decides how it looks. Keeping colours in CSS means a designer can change them without touching your script.








Project 12.2 · Medium


A live character counter


As the reader types a message, show how many characters are left out of 120, and turn the number red when fewer than 20 remain.


You will practise: the input event, reading value, labels for form fields, and classList.toggle with a condition.


    

  1. Add a <label for="message">, a <textarea id="message" maxlength="120"> and a paragraph with <span id="left">120</span>.
    2. 

  2. Listen for "input" on the text area. Unlike "change", it fires on every key press.
    3. 

  3. Work out limit - message.value.length and show it in the span.
    4. 

  4. Call left.classList.toggle("low", remaining < 20). With a second argument, toggle adds the class when the condition is true and removes it when it is false.
    5. 

  5. Type, then delete some text, and watch the colour come back.
    6. 



Hint: maxlength already stops the reader at 120. Your script does not enforce the limit; it only tells the reader where they stand. Good pages do both.








Project 12.3 · Challenge


A quiz that builds itself


Write the questions as data, and let JavaScript build the buttons for each one, check the answer, move on, and show the score at the end.


You will practise: arrays of objects, createElement and append, replaceChildren, template literals, and splitting the work into functions.


    

  1. Create an array questions: each item has text, an options array, and answer, the index of the right option.
    2. 

  2. Write show(): write the question number and text, clear the old buttons with options.replaceChildren(), then create one button per option with forEach.
    3. 

  3. Each button calls choose(index). Compare it with answer, add a point if it is right, and show the feedback in green or red.
    4. 

  4. Move to the next question. When there are none left, call finish() to show Your score: 2 / 3.
    5. 

  5. In finish(), add a “Play again” button that resets current and points and calls show().
    6. 

  6. Add two questions of your own to the array. The page grows without a single new line of HTML.
    7. 



Hint: the data (questions, current, points) is the truth, and show() draws it on the page. This idea, “draw the page from the data”, is exactly how React and Vue work.
