هذا الفصل الذي يجتمع فيه كل شيء. ستبني تطبيقاً حقيقياً تستخدمه كل يوم: قائمة مهام يومية تضيف إليها، وتعلّم المنجز منها، وتصفّيها، وتحذف منها، وتتذكر كل شيء حين تغلق المتصفح. ثم تعطيه عنواناً على الإنترنت تفتحه على هاتفك وترسله إلى أصدقائك. ولكل مهارة من الفصول الستة عشر السابقة دور فيه.

هذا فصلي المفضل! في آخره لن تكون قد تعلمت البرمجة فقط، بل أطلقت شيئاً: تطبيقاً حقيقياً حياً على الويب، بنيته أنت من لا شيء. هيا بنا!

17.1 خطط أولاً

علّمك الفصل 2 أن تفكر قبل أن تكتب. والمحترفون يبدؤون كل مشروع بالطريقة نفسها: يكتبون ما يجب أن يفعله التطبيق، ويرسمون شكله، ويقررون البيانات التي يحتاجها.

ماذا يفعل التطبيق

  1. يضيف مهمة حين تكتبها وتضغط Enter أو زر «أضف».
  2. يعلّم المهمة منجزة حين تضع عليها علامة، ويلغي ذلك.
  3. يحذف مهمة.
  4. يعرض كل المهام، أو المتبقية وحدها، أو المنجزة وحدها.
  5. يعرض عدد المهام المتبقية، ويحذف كل المنجزة دفعة واحدة.
  6. يتذكر كل شيء بعد إغلاق المتصفح.
  7. يعمل بلوحة المفاتيح، وعلى الهاتف، بالعربية أو الإنجليزية.

الرسم

البيانات

كل مهمة تحتاج id فريداً، ونصها text، وهل هي منجزة done. وبيانات التطبيق كله مصفوفة من هذه الكائنات، ومعها التصفية الحالية:

[
  { id: 1741766400000, text: "اقرأ الفصل 17", done: true },
  { id: 1741766460000, text: "تدرّب على Flexbox", done: false }
]

وكل شيء آخر على الشاشة، القائمة والعدّاد والتصفية المميزة، يُحسب من هذه البيانات. وهذا القرار سيجعل الكود بسيطاً.

17.2 HTML

أنشئ مجلداً اسمه my-tasks فيه ثلاثة ملفات. HTML تحمل البنية، وتكاد تكون فارغة حيث ستأتي المهام:




لاحظ تفاصيل الوصول من الفصل 16: <form> حقيقي ليعمل Enter، وتسمية لخانة الإدخال (مخفية بصرياً، لأن النص المؤقت والزر يوضحان الغرض للمبصرين)، وعناصر <button> حقيقية، وaria-pressed لتعرف قارئات الشاشة أي تصفية مفعّلة، وaria-live ليُعلن العدد حين يتغير.



17.3 CSS



ملف التنسيق يستخدم الخصائص المخصصة وFlexbox والزوايا المستديرة والتركيز الظاهر، كلها من الفصلين 6 و7. ولا يستخدم أي جهة فعلية، فالملف نفسه ينسّق النسخة العربية والإنجليزية. وهو في مستودع كود الكتاب باسم style.css، وهذه أطرف أجزائه:



form {
  display: flex;
  gap: 8px;
}
form input {
  flex: 1;                /* the input takes all the free space */
}
.filters button[aria-pressed="true"] {
  color: white;           /* the active filter is styled from */
  background: var(--brand); /* the same attribute screen readers use */
}
li.done label {
  color: var(--muted);
  text-decoration: line-through;
}



تنسيق التصفية المفعّلة بـ [aria-pressed="true"] حيلة احترافية أنيقة: الشكل ومعلومات الوصول لا يمكن أن يختلفا، لأنهما الخاصية نفسها.



17.4 JavaScript



البرنامج يتبع نمط الفصل 12: البيانات، والتغييرات، والعرض، والأحداث. اقرأه قسماً قسماً:






تذكّر البيانات: localStorage



المتغيرات تختفي حين تُغلق الصفحة. أما localStorage فمساحة تخزين صغيرة يأخذها كل موقع في المتصفح، وتبقى بعد إعادة التحميل وإعادة التشغيل. وهي تحفظ النصوص فقط، فنستخدم JSON من الفصل 11:


    

  • save() تحوّل المهام إلى JSON وتحفظها تحت المفتاح "my-tasks".
    • 

  • load() تقرؤها حين تُفتح الصفحة، أو تبدأ بمصفوفة فارغة في المرة الأولى.
    • 

  • وكل تغيير يمر بـ update() التي تحفظ ثم تعيد الرسم. ولأن الطريق واحد، لا يمكن أن تختلف الشاشة والتخزين.
    • 




العربية والأعداد



في النسخة العربية دالة leftText تختار صيغة الكلمة المناسبة للعدد: «مهمة واحدة»، و«مهمتان»، و«3 مهام»، و«11 مهمة». فالواجهة العربية الجيدة لا تكتفي بترجمة الكلمات، بل تحترم قواعد اللغة. والمتصفحات تقدم لهذا أداة جاهزة اسمها Intl.PluralRules، ستقابلها في كتاب الواجهات.



انتبه
localStorage تخص متصفحاً واحداً على جهاز واحد. فالمهام التي تضيفها على هاتفك لن تظهر على حاسوبك، ومسح بيانات المتصفح يحذفها. والمزامنة بين الأجهزة تحتاج خادماً وقاعدة بيانات، وهذا بالضبط ما تعلّمه كتب الخوادم في هذه السلسلة.



تفاصيل أخرى تستحق الانتباه


    

  • Date.now() تُرجع عدد أجزاء الألف من الثانية منذ 1970، وهي طريقة بسيطة لمعرّف فريد.
    • 

  • tasks.filter(…) تنشئ مصفوفات جديدة للحذف والمسح، وهذا أبسط وأسلم من حذف عناصر من وسط المصفوفة.
    • 

  • replaceChildren(...visibleTasks().map(taskItem)) تعيد رسم القائمة كلها في سطر واحد: صيغة النشر من الفصل 11 تمرر كل عناصر <li> الجديدة دفعة واحدة.
    • 

  • لكل مهمة مربع اختيار حقيقي مع <label>، فالنقر على النص يعلّم المربع، ولزر الحذف aria-label تقول أي مهمة يحذف.
    •

17.6 انشره بـ GitHub Pages



GitHub Pages خدمة مجانية تحوّل مستودع GitHub إلى موقع. ولأن تطبيقك HTML وCSS وJavaScript فقط، بلا كود خادم، فيمكن استضافته عليها في دقائق:



    

  1. ضع مجلد my-tasks تحت Git واحفظ commit، كما في الفصل 15.
    2. 

  2. أنشئ مستودعاً عاماً اسمه my-tasks على GitHub وأرسل إليه.
    3. 

  3. في صفحة المستودع افتح Settings ثم Pages.
    4. 

  4. تحت Build and deployment اختر Deploy from a branch، ثم الفرع main والمجلد / (root)، واضغط Save.
    5. 

  5. انتظر دقيقة وأعد التحميل، فيعرض GitHub عنوانك: https://your-username.github.io/my-tasks/.
    6. 




افتح ذلك العنوان على هاتفك. هذا تطبيقك على الإنترنت، عبر HTTPS، بنيته أنت. ومن الآن، كلما أرسلت commit جديداً إلى main يحدّث GitHub الموقع تلقائياً.



نصيحة
الصفحة الرئيسية للموقع يجب أن يكون اسمها index.html، فهو الملف الذي يرسله خادم الويب حين ينتهي العنوان باسم مجلد. ولهذا سمّينا ملفنا هكذا من البداية.



أرسل الرابط إلى صديق واطلب منه أن يضيف مهمة. أن تشاهد شخصاً آخر يستخدم شيئاً صنعته من أجمل المشاعر في البرمجة. لقد فعلتها!



17.7 أفكار لتستمر



أفضل طريقة لمواصلة التعلم أن تواصل البناء. وهذه تحسينات مرتبة تقريباً من السهل إلى الصعب:


    

  • عدّل المهمة بالنقر المزدوج على نصها.
    • 

  • أضف تاريخ استحقاق لكل مهمة، ورتّب به.
    • 

  • أضف وضعاً داكناً يتبع إعداد النظام بـ prefers-color-scheme.
    • 

  • اسحب المهام لتعيد ترتيبها.
    • 

  • أضف مفتاح لغة يبدّل كل نصوص التطبيق بين العربية والإنجليزية، ويضبط lang وdir.
    • 




الخلاصة



    

  • خطط قبل البرمجة: اكتب الميزات، وارسم الشكل، وصمّم البيانات.
    • 

  • احسب كل ما على الشاشة من البيانات، ومرّر كل تغيير بدالة واحدة تحفظ وتعيد الرسم.
    • 

  • localStorage تحفظ النصوص في المتصفح بعد إعادة التحميل، فاحفظ الكائنات JSON.
    • 

  • ابنِ الوصول من البداية: نماذج وأزرار وتسميات حقيقية وتركيز ظاهر. واحترم قواعد العربية في الأعداد.
    • 

  • اختبر الحالة الفارغة والمدخلات غير المعتادة والحفظ ولوحة المفاتيح وعرض الهاتف والـ Console قبل النشر.
    • 

  • GitHub Pages ينشر الموقع الثابت من المستودع مجاناً.
    • 





مشاريع تطبيقية: طوّر تطبيقك



انتهى التطبيق، وهنا يبدأ التطوير الحقيقي: تحسين شيء يعمل أصلاً دون أن تكسره. انسخ مجلد التطبيق كله لكل مشروع، وأنشئ فرعاً في Git، واحفظ بـ commit كلما تقدمت. وكل مشروع يلمس الملفات الثلاثة، تماماً كأي ميزة حقيقية.





مشروع 17.1 · سهل


شريط التقدّم


اعرض كم أُنجز من القائمة، شريطاً وكلمات، وأبقِه متوافقاً مع كل تغيير.


ستتدرب على: العنصر <progress>، والإضافة إلى render()، وaccent-color.


    

  1. في HTML، فوق القائمة، أضف <progress id="progress" max="1" value="0"> و<span id="progress-text">، واربطهما بـ aria-labelledby ليكون للشريط اسم.
    2. 

  2. في CSS اجعل الشريط يملأ السطر بـ flex: 1، ولوّنه بـ accent-color: var(--brand).
    3. 

  3. في render() احسب done = tasks.length - count، ثم اضبط max وvalue للشريط.
    4. 

  4. استخدم tasks.length || 1 لـ max، فلا تقسم القائمة الفارغة على صفر.
    5. 

  5. اكتب «1 من 3 منجزة» في الـ span. علّم المهام وألغِ علامتها وأضف واحذف، وتحقق أن الشريط صحيح دائماً.
    6. 



تلميح: لم تلمس addTask ولا toggleTask ولا deleteTask. فلأن كل تغيير ينتهي بـ render() تكفي كتلة واحدة جديدة هناك. وهذه مكافأة البنية التي بنيتها في هذا الفصل.








مشروع 17.2 · متوسط


تعديل المهمة


الأخطاء الإملائية تحدث. دع المستخدم يصحح نص المهمة في مكانها: Enter يحفظ، وEscape يلغي.


ستتدرب على: دالة تغيير جديدة، وreplaceWith، وأحداث لوحة المفاتيح، وfocus() وselect().


    

  1. أضف renameTask(id, text) بجانب دوال التغيير الأخرى: جِد المهمة، وغيّر نصها، واستدعِ update().
    2. 

  2. في taskItem أضف زر «عدّل» بـ aria-label يسمّي المهمة، مثل زر الحذف.
    3. 

  3. اكتب startEditing(li, task): أنشئ حقلاً فيه النص الحالي، وضعه مكان التسمية بـ label.replaceWith(input)، ثم استدعِ focus() وselect().
    4. 

  4. استمع إلى keydown على الحقل. عند "Enter" احفظ النص بعد تنظيفه إن لم يكن فارغاً، وعند "Escape" استدعِ render() فقط.
    5. 

  5. حين يفقد الحقل التركيز (blur) استدعِ render() أيضاً، فلا تبقى مهمة نصف معدّلة على الشاشة.
    6. 



تلميح: اقترح القسم 17.7 النقر المزدوج، والزر أفضل: فالنقر المزدوج لا تؤديه لوحة المفاتيح ولا يسهل على الجوال، وعرفت في الفصل 16 لماذا يهم هذا.








مشروع 17.3 · تحدٍّ


العربية والإنجليزية في تطبيق واحد


أضف زراً يبدّل كل نصوص التطبيق بين العربية والإنجليزية، ويقلب الاتجاه بين اليمين واليسار، ويتذكر الاختيار.


ستتدرب على: حفظ النصوص بيانات، وخصائص data-*، والدوال المحفوظة في الكائنات، وlang وdir، ومفتاح ثانٍ في localStorage.


    

  1. أنشئ كائن TEXTS بجزأين en وar، فيهما كل كلمة يعرضها التطبيق. وleft دالة، لأن الجمع العربي يتغير مع العدد.
    2. 

  2. اكتب دالة مساعدة صغيرة t(key) تُرجع النص باللغة الحالية language.
    3. 

  3. في HTML علّم كل نص بمفتاحه: <h1 data-text="title">، وأضف زر اللغة في الترويسة.
    4. 

  4. اكتب applyLanguage(): اضبط lang وdir على document.documentElement، واملأ كل عنصر [data-text]، واضبط النص الإرشادي والتسميات، ثم render().
    5. 

  5. استبدل كل كلمة ثابتة في app.js بـ t(…)، ثم احذف leftText القديمة.
    6. 

  6. الزر يبدّل language، ويحفظها بمفتاحها الخاص، ويستدعي applyLanguage(). أعد تحميل الصفحة: يجب أن تفتح باللغة التي اخترتها آخر مرة.
    7. 



تلميح: لأن CSS تستخدم flex وgap ولا «يسار» أو «يمين» ثابتاً، ينعكس التخطيط كله وحده حين يتغير dir. والتطبيقات الحقيقية تحفظ نصوصها هكذا، وبهذا تُترجم إلى لغات كثيرة دون أن يُلمس الكود.







تمارين



    

  1. سهل غيّر ألوان التطبيق وعنوانه ليصير خاصاً بك، وانشر النسخة الجديدة بـ git push واحدة.
    2. 

  2. سهل أضف عدّاداً للمهام المنجزة بجانب عدّاد المتبقية.
    3. 

  3. متوسط اسمح للمستخدم بتعديل نص المهمة بالنقر المزدوج عليه، واحفظ التعديل بـ Enter وألغه بـ Escape.
    4. 

  4. متوسط أضف «أولوية» لكل مهمة (منخفضة، وعادية، وعالية) تُختار بـ <select> عند الإضافة، واعرض المهام العالية أولاً.
    5. 

  5. تحدٍّ أضف إلى التطبيق مفتاح لغة. احفظ كل النصوص في كائن مثل { en: {…}, ar: {…} }، وتذكّر الاختيار في localStorage، وحدّث lang وdir في عنصر <html>.
    6. 




حلول التمارين في آخر الكتاب، وفي مستودع الكود الخاص بالكتاب.
