18.2 Four paths

Frontend developer

Builds what people see and touch: the pages, buttons, forms and animations of websites and web apps. Frontend developers care about design, speed, accessibility and every detail of the user’s experience. They work daily with HTML, CSS, JavaScript and TypeScript, and with a framework such as React or Vue. Next: Book 2, Senior Frontend Engineering, in the React or the Vue edition.

Backend developer

Builds what happens behind the scenes: the servers, databases and APIs that store data, check passwords, take payments and send emails. Backend developers care about correctness, security and performance under heavy load. They work with a server language such as JavaScript with Node.js or PHP with Laravel, and with SQL databases. Next: Book 3, Senior Backend Engineering, in the Node.js or the Laravel edition.

Full stack developer

Works on both sides and connects them: from the database to the button, and from the idea to the running product. Full stack developers are especially valuable in small teams and start-ups. Next: Books 2 and 3, then Book 4, Senior Full Stack Engineering.

Mobile developer

Builds apps for phones and tablets. With Flutter, one codebase in the Dart language runs on both Android and iPhone. Mobile developers care about smooth animations, battery life, working offline, and publishing in the app stores. Next: Book 5, Flutter from Zero, then Book 6, Senior Flutter Engineering.

18.4 What “senior” really means

This series is called “From Zero to Senior”. A senior developer is not simply someone who has written code for many years, or who knows more tricks. The difference is in the size of the problems they can be trusted with:

JuniorMid-levelSenior
Typical workA clearly defined taskA whole featureA whole system, or a hard, unclear problem
NeedsGuidance and code reviewOccasional adviceGives guidance and reviews others
Thinks aboutMaking it workMaking it clean and testedTrade-offs: cost, risk, the team, the future
ImpactTheir own codeTheir featureThe whole team’s work

Seniority comes from experience with real projects, real mistakes and real users, plus the deliberate habits described next. The senior books in this series teach the technical side; the habits are up to you.

18.5 Habits that make professionals

  • Build, every week. Reading teaches you what exists; building teaches you how to use it. Small projects finished beat big projects abandoned.
  • Read other people’s code. Open-source projects on GitHub are a free library of how professionals write.
  • Get your code reviewed, and review others’. Join a study group or an online community.
  • Explain what you learn. Write short posts or teach a friend. Teaching is the fastest way to discover what you have not really understood.
  • Practise reading documentation. MDN today; the official docs of every tool tomorrow.
  • Keep the fundamentals sharp. Frameworks change every few years; HTTP, HTML, CSS, JavaScript and clear thinking stay.

About AI assistants

AI tools can now write a lot of code. That makes understanding more valuable, not less: someone has to decide what to build, check that the code is correct and secure, fix it when it breaks, and take responsibility for it. Use AI as a fast assistant, and keep building your own understanding. The developers who thrive are the ones who could do the work without it.

18.6 Your portfolio and your first job

Employers want to see what you can do. Start building a portfolio now:

  1. Put your best projects on GitHub, each with a short README that explains what it does, with a screenshot and a live link.
  2. Publish your profile page from Chapters 5 to 7 as your personal site, with links to your projects.
  3. Aim for three solid projects that show different skills, rather than ten unfinished ones. The tasks app from Chapter 17, improved with the exercises, is a great first one.
  4. Make every project accessible and responsive. Few beginners do this, so it makes you stand out.

Professional habit: be kind to yourself

Almost every developer, including very experienced ones, sometimes feels that everyone else knows more. It has a name: impostor syndrome. It is normal, and it is not true. Take breaks, sleep well, and compare yourself only with yourself a month ago. Learning to code is a marathon, not a sprint.

Graduation projects

These last three projects turn everything you built in this book into something you can show the world. They are not about new code; they are about presenting your work the way professionals do. When you finish them, you will have a portfolio, not just a folder of exercises.

Project 18.1 · Easy

A README that sells your project

Write the page a visitor sees first on GitHub, so that in thirty seconds they know what your app does, can try it, and can see what you learned.

You will practise: Markdown headings, lists, links and images, and writing for a busy reader.

  1. In your tasks app folder, create README.md. GitHub shows it automatically under your files.
  2. Start with the name and one sentence that says what it is and who it is for.
  3. Add the live link from GitHub Pages and a screenshot, saved in the same folder.
  4. List the features in short lines. Mention accessibility and both languages: they make you stand out.
  5. End with “What I learned”, in two or three honest sentences. Recruiters read this part.
  6. Commit, push, and look at your repository page on GitHub.

Hint: write it for someone who will never run your code. Most visitors only read the first screen, so put the link and the screenshot near the top.
