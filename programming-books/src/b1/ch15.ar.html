  • تعمل على الميزات الجديدة بأمان في الفروع

هل حفظت يوماً ملفات اسمها profile-final.html وprofile-final-2.html وprofile-REALLY-final.html؟ واجه المطورون المحترفون المشكلة نفسها، وحلّوها بأداة اسمها Git. يتذكر Git كل نسخة من كل ملف في مشروعك، ويتيح لك العودة إلى أي منها، ويتيح لأشخاص كثيرين العمل على الكود نفسه في الوقت نفسه. ويستخدمه تقريباً كل فريق برمجيات في العالم.

Git مثل نقاط الحفظ في ألعاب الفيديو. قبل أن تجرب شيئاً خطيراً تحفظ، وإن ساء الأمر تحمّل آخر حفظ وتحاول من جديد. لكن مع Git تحتفظ بـكل حفظ إلى الأبد، ومعه ملاحظة عما فعلته!

15.1 ما التحكم في الإصدارات؟

نظام التحكم في الإصدارات (version control) يسجّل تغييرات الملفات عبر الزمن. وبه تستطيع أن:

  • ترى بالضبط ما تغيّر ومتى ولماذا؛
  • تعود إلى أي نسخة سابقة حين يتعطل شيء؛
  • تجرب أفكاراً جديدة دون أن تخاطر بالنسخة التي تعمل؛
  • تجمع عمل عدة أشخاص دون أن يكتب أحدهم فوق عمل الآخر.

Git هو نظام التحكم في الإصدارات الذي يستخدمه الجميع تقريباً اليوم. وهو مجاني، ويعمل على حاسوبك، حتى بلا إنترنت. وGitHub موقع يحفظ مشاريع Git على الإنترنت، لتنسخها احتياطياً وتشاركها وتعمل عليها مع غيرك. فـ Git هو الأداة، وGitHub أحد الأماكن التي تحفظ فيها ما يسجّله Git.

15.3 أول commit لك



مشروع Git يُسمى مستودعاً (repository أو repo)، واللقطة من المشروع تُسمى commit. وحفظ commit خطوتان: أولاً تختار التغييرات التي تدخل فيه، ثم تحفظها مع رسالة.





وهذه العملية كاملة لموقع الفصل 7 التعريفي، منفّذة في مجلده:






    

  • git init تحوّل المجلد إلى مستودع، وتنشئ مجلداً مخفياً اسمه .git يعيش فيه التاريخ؛ لا تعدّله بيدك أبداً.
    • 

  • git status هو الأمر الذي ستكتبه أكثر من غيره. و--short تعطي عرضاً مختصراً: ?? تعني ملفاً جديداً لا يتتبعه Git بعد، وA تعني أنه أُضيف إلى منطقة التجهيز.
    • 

  • git add تضع التغييرات في منطقة التجهيز، وgit add . تضيف كل ما في المجلد.
    • 

  • git commit -m "…" تحفظ اللقطة، ويعطيها Git معرّفاً، هنا 166f9d5، تجدها به لاحقاً.
    • 




نصيحة
رسائل commit بالعربية تعمل تماماً كما ترى. لكن في الفرق الدولية والمشاريع المفتوحة تُكتب الرسائل بالإنجليزية عادة، فتعوّد عليها مبكراً إن كنت تنوي العمل مع فرق من بلدان مختلفة.

git diff تعرض التغييرات التي لم تحفظها بعد: الأسطر التي تبدأ بـ + أُضيفت، والتي تبدأ بـ - حُذفت. وgit commit -am تضيف كل الملفات المتتبَّعة المتغيرة وتحفظها في خطوة واحدة. وgit log --oneline تعرض التاريخ، commit واحداً في كل سطر.

15.5 الفروع



الفرع (branch) خط عمل منفصل. والفرع الرئيسي، main، يحمل النسخة التي تعمل. وحين تبدأ ميزة جديدة تنشئ لها فرعاً، تعمل فيه وتحفظ بحرية، وحين تجهز تدمجها (merge) في main:








git switch -c contact تنشئ فرعاً اسمه contact وتنتقل إليه. والحفظ فيه لا يمس main: فحين تعود إليه يختفي contact.html من مجلدك، ويعود حين تنتقل إلى contact مرة أخرى. وgit merge contact تُدخل لقطات الفرع في main. ولأن main لم يتغير في هذه الأثناء، حرّكه Git إلى الأمام ببساطة، ويسمي ذلك fast-forward.



نصيحة: تعارضات الدمج
إن غيّر فرعان السطر نفسه بطريقتين مختلفتين، فلن يستطيع Git أن يخمّن أي نسخة تريد، فيبلّغ عن تعارض (conflict)، ويعلّم المكان في الملف بـ <<<<<<< و======= و>>>>>>>. لا تقلق: عدّل الملف لتُبقي النسخة الصحيحة، واحذف العلامات، ثم git add وgit commit. وVS Code يعرض التعارضات بأزرار تسهّل ذلك.



15.6 GitHub: كودك على الإنترنت



أنشئ حساباً مجانياً على github.com، واضغط New repository، وأعطه اسماً، واتركه فارغاً. فيعرض لك GitHub عنوانه. اربط مستودعك المحلي به وأرسل إليه لقطاتك:






    

  • المستودع البعيد (remote) نسخة من المستودع في مكان آخر، والرئيسي منها يُسمى origin بحكم العادة.
    • 

  • git push ترسل لقطاتك إلى المستودع البعيد. وفي المرة الأولى تتذكر -u origin main أين ترسل، فيكفي بعدها git push وحدها.
    • 

  • git clone تنزّل مستودعاً كاملاً، بتاريخه، على حاسوب آخر.
    • 

  • git pull تجلب اللقطات التي أرسلها غيرك (أو أنت من حاسوب آخر).
    • 




وفي أول مرة ترسل فيها يطلب منك Git تسجيل الدخول إلى GitHub. اتبع التعليمات في نافذة المتصفح التي يفتحها؛ فـ GitHub لم يعد يقبل كلمة مرور حسابك مباشرة في الطرفية.



ملفات لا مكان لها في Git



بعض الملفات لا تنتمي إلى المستودع: الحزم المنزّلة التي يمكن إعادة تثبيتها، وملفات النظام، والسجلات، وقبل كل شيء الأسرار مثل كلمات المرور ومفاتيح الواجهات البرمجية. اكتبها في ملف اسمه .gitignore فلن يتتبعها Git أبداً:






انتبه: لا تحفظ الأسرار أبداً
كل ما ترسله إلى مستودع عام يستطيع أي أحد قراءته، والبرامج الآلية تفتش GitHub بحثاً عن المفاتيح خلال دقائق. وحذف الملف في commit لاحق لا يكفي، فهو يبقى في التاريخ. وإن أرسلت سراً بالخطأ يوماً، فغيّر كلمة المرور أو المفتاح فوراً.



15.7 كيف تعمل الفرق معاً



في الفريق لا يحفظ أحد مباشرة في main، بل يتبع كل تغيير المسار نفسه:



    

  1. أنشئ فرعاً للتغيير واحفظ فيه.
    2. 

  2. أرسل الفرع إلى GitHub.
    3. 

  3. افتح طلب دمج (pull request أو PR): صفحة على GitHub تعرض التغييرات وتطلب دمجها.
    4. 

  4. يُراجع زملاؤك الكود، ويعلّقون، ويطلبون تحسينات، وتُشغَّل الاختبارات تلقائياً.
    5. 

  5. وحين يرضى الجميع يُدمج الطلب في main.
    6. 




وهكذا يكون كل سطر في main قد رآه شخصان على الأقل. ومراجعة الكود من أفضل طرق التعلم: ستتعلم من قراءة طلبات دمج غيرك بقدر ما تتعلم من كتابة طلباتك.



عادة المحترفين: رسائل commit جيدة
اكتب رسائل commit للشخص الذي سيقرأ التاريخ بعد عام. ابدأ بملخص قصير بصيغة الأمر: «أضف قسم التواصل»، و«أصلح سعر الأطفال»، لا «أشياء» أو «تعديلات». واجعل كل commit تغييراً منطقياً واحداً. فاللقطات الصغيرة الموصوفة جيداً تجعل العلل سهلة الإيجاد وسهلة التراجع عنها.



اختبر نفسك
  1. ما الخطوتان لحفظ لقطة؟
  2. ما الفرق بين Git وGitHub؟
  3. لماذا لا تُحفظ كلمات المرور في Git أبداً، حتى لو حذفتها لاحقاً؟
الإجابات في آخر الفصل، بعد الخلاصة.



الخلاصة



    

  • Git يسجّل كل نسخة من المشروع، وGitHub يحفظ مستودعات Git على الإنترنت.
    • 

  • git init تبدأ مستودعاً، وgit status تعرض الحال.
    • 

  • git add تجهّز التغييرات، وgit commit -m تحفظ لقطة مع رسالة.
    • 

  • git diff وgit log --oneline تعرضان التغييرات والتاريخ، وgit restore وgit revert تتراجعان.
    • 

  • الفروع (git switch -c) تفصل العمل الجديد حتى يُدمج.
    • 

  • git push وgit pull وgit clone تعمل مع مستودع بعيد مثل GitHub.
    • 

  • .gitignore تُبعد الأسرار والملفات المولّدة، والفرق تعمل بالفروع وطلبات الدمج.
    • 




إجابات «اختبر نفسك»: 1. git add لاختيار التغييرات، ثم git commit لحفظها. 2. Git الأداة التي تسجّل النسخ على حاسوبك، وGitHub موقع يحفظ مستودعات Git على الإنترنت ويساعد الناس على العمل عليها معاً. 3. لأنها تبقى في التاريخ، حيث يجدها كل من يصل إلى المستودع.




مشاريع تطبيقية



يُتعلَّم Git بالأصابع لا بالعيون. افتح الطرفية واكتب كل أمر بنفسك. والجلسات التالية حقيقية: هذا بالضبط ما طبعه Git. وستختلف أرقام الـ commit عندك لأنها تعتمد على اسمك والوقت، ويجب أن يطابق كل ما عداها.

دفتر تعلّم تحت إدارة الإصدارات


ابدأ مستودعاً لدفتر تكتب فيه ما تتعلمه، واحفظ commit واحداً لكل يوم.


ستتدرب على: git init وadd وcommit وcommit -am وlog --oneline وshow.


    

  1. أنشئ مجلداً اسمه journal، وافتحه في VS Code، وشغّل git init في طرفيته.
    2. 

  2. أنشئ journal.md بعنوان، وأضفه، واصنع أول commit.
    3. 

  3. كل يوم أضف سطراً عما تعلمته، واحفظه بـ commit برسالة قصيرة. و-am تضيف وتحفظ في خطوة واحدة، لكن للملفات التي يتتبعها Git أصلاً فقط.
    4. 

  4. اقرأ تاريخك بـ git log --oneline.
    5. 

  5. انظر داخل آخر commit بـ git show --stat. ثم جرّب git show وحدها لترى السطر الذي أضفته بالضبط.
    6. 



تلميح: احتفظ بهذا الدفتر حتى آخر الكتاب. بعد أسابيع سيصير git log يوميات تقدّمك، وعادة الـ commit الصغير المتكرر هي بالضبط ما تتوقعه الفرق منك.









مشروع 15.2 · متوسط


طريقتان للتراجع


اصنع خطأين عمداً، واحداً لم تحفظه بعد وآخر حفظته، وتراجع عن كل منهما بالأداة المناسبة.


ستتدرب على: git status --short، وgit restore للتغييرات غير المحفوظة، وgit revert للـ commits.


    

  1. استبدل محتوى journal.md كله بسطر سخيف، واحفظ. فيُظهر git status --short الحرف M: معدَّل.
    2. 

  2. شغّل git restore journal.md. يعود الملف إلى آخر commit، وتعود الحالة نظيفة.
    3. 

  3. اكتب اليوم 3 كما يجب واحفظه بـ commit.
    4. 

  4. الآن أنشئ quote.md وأضفه واحفظه بـ commit. وتخيّل أنك تندم على هذا الـ commit.
    5. 

  5. شغّل git revert --no-edit HEAD. يصنع Git commit جديداً يفعل العكس، فيختفي الملف.
    6. 

  6. اقرأ git log --oneline: الخطأ والتراجع عنه كلاهما في التاريخ، فلا يُفاجأ أحد.
    7. 



تلميح: restore تتخلص من عمل لم يُحفظ أبداً، فلا رجعة فيه، فاستخدمها بحذر. أما revert فآمنة دائماً، حتى بعد الرفع، لأنها تضيف إلى التاريخ ولا تمحو منه.









مشروع 15.3 · تحدٍّ


اصنع تعارض دمج ثم حُلّه


التعارضات تخيف المبتدئين حتى يحلّوا أول واحد. اصنع واحداً عمداً، واقرأه، وحلّه بهدوء.


ستتدرب على: الفروع، وgit switch -c، والدمج السريع والدمج الحقيقي، وعلامات التعارض، وإنهاء الدمج.


    

  1. على main أضف سطر عنوان في أعلى الدفتر واحفظه بـ commit.
    2. 

  2. أنشئ فرعاً personal، وغيّر العنوان، واحفظ. ثم عُد إلى main.
    3. 

  3. أنشئ فرعاً ثانياً ambitious من main، وغيّر سطر العنوان نفسه بشكل آخر، واحفظ. ثم عُد إلى main.
    4. 

  4. ادمج personal: دمج سريع (fast-forward) لأن main لم يتحرك. ثم ادمج ambitious: لا يستطيع Git أن يختار بين تغييرين للسطر نفسه، فيتوقف.
    5. 

  5. افتح الملف. بين <<<<<<< و======= نسختك (HEAD)، وبين ======= و>>>>>>> النسخة القادمة.
    6. 

  6. اكتب السطر الذي تريده فعلاً، واحذف أسطر العلامات الثلاثة، ثم git add وgit commit. ويُظهر الرسم التقاء الفرعين.
    7. 



تلميح: التعارض ليس خطأ، بل Git يطلب بأدب أن يقرر إنسان. ويعرض VS Code أزراراً فوق كل تعارض («Accept Current» و«Accept Incoming» و«Accept Both»)، لكن اقرأ النتيجة دائماً قبل الحفظ.








تمارين



    

  1. سهل ضع مجلد code-from-zero تحت Git، واحفظ أول commit فيه كل ما كتبته حتى الآن.
    2. 

  2. سهل غيّر ملفاً، وانظر إلى التغيير بـ git diff، ثم تخلص منه بـ git restore.
    3. 

  3. متوسط أنشئ فرعاً اسمه dark-mode، وأضف فيه وضعاً داكناً لصفحتك التعريفية في commit اثنين، ثم ادمجه في main.

    5. 

  5. تحدٍّ اصنع تعارض دمج عمداً: غيّر السطر نفسه في index.html بطريقتين في فرعين، وادمجهما، وحُلّ التعارض.
