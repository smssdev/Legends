الرقم يحفظ عمراً، والنص يحفظ اسماً. لكن الأشياء الحقيقية لها تفاصيل كثيرة معاً: للكتاب عنوان وسعر وعدد صفحات وقائمة وسوم. والكائنات تتيح لك أن تُبقي كل تفاصيل الشيء الواحد معاً تحت أسماء واضحة. إنها طريقة JavaScript في وصف العالم، ومعظم البيانات التي ستقابلها كمطور كائنات.

لو كنت كائناً لكنت { name: "بِت", colour: "بنفسجي", antennas: 1, loves: ["HTML", "CSS", "JavaScript"] }. أرأيت؟ الكائنات طريقة طبيعية لوصف الأشياء!

11.1 إنشاء الكائنات وقراءتها

يُكتب الكائن (object) بين قوسين معقوصين، وبداخله خصائص (properties): أزواج من اسم (يُسمى المفتاح) وقيمة تفصلهما نقطتان، وبين الأزواج فواصل:






    

  • صيغة النقطة، book.title، هي الطريقة المعتادة لقراءة الخاصية.
    • 

  • صيغة الأقواس، book["pages"]، تفعل الشيء نفسه والمفتاح نص، وتفيد حين يكون المفتاح في متغير: book[field].
    • 

  • القيمة يمكن أن تكون أي شيء: رقماً، أو نصاً، أو boolean، أو مصفوفة، أو حتى كائناً آخر.
    • 

  • تغيّر الخاصية بأن تسند إليها قيمة، وتضيف خاصية بالطريقة نفسها: book.price = 25 أنشأت خاصية لم تكن موجودة.
    • 




وقراءة خاصية غير موجودة ليست خطأً، بل تحصل على undefined. هذا مريح، لكنه يعني أن خطأً إملائياً مثل book.titel يفشل بصمت، فانتبه لإملائك. ولاحظ أن المفاتيح تُكتب بالإنجليزية دائماً، أما القيم النصية فبأي لغة.

أكثر أشكال البيانات شيوعاً في البرامج الحقيقية هو مصفوفة الكائنات: قائمة منتجات، أو مستخدمين، أو رسائل، أو مباريات. ولكل كائن المفاتيح نفسها:








هنا تتألق دوال الفصل 10. فـ filter تختار الكتب، وmap تأخذ أسماءها فقط، وfind تُرجع أول عنصر يطابق، أو undefined إن لم يوجد. ولاحظ أن كل سطر يُقرأ كأنه سؤال: «المنتجات التي فئتها كتاب»، و«المنتج الذي معرّفه 2».



نصيحة
console.table(products) تطبع مصفوفة الكائنات جدولاً مرتباً في الطرفية أو Console المتصفح. وهي من أنفع الحيل للنظر في البيانات.



11.3 التفكيك والنشر



صيغتان قصيرتان تظهران في كل مكان في JavaScript الحديثة:








    

  • التفكيك (destructuring)، const { name, city } = visitor، ينشئ متغيرات من الخصائص التي تحمل الأسماء نفسها، وهو اختصار لـ const name = visitor.name وconst city = visitor.city.
    • 

  • وصيغة النشر (spread)، { ...visitor, age: 35 }، تنسخ كل الخصائص إلى كائن جديد ثم تستبدل age. والأصل لا يتغير، كما تُظهر المخرجات.
    • 




انتبه: النسخ والمراجع
const copy = visitor لا تنسخ الكائن. فالاسمان يشيران الآن إلى الكائن نفسه، وتغيير copy.age يغيّر visitor.age أيضاً، لأن الكائنات والمصفوفات تُشارَك بالمرجع. ولتحصل على نسخة مستقلة حقاً استخدم النشر: { ...visitor } للكائنات، و[...list] للمصفوفات.



11.4 JSON: الكائنات نصاً



الكائنات تعيش في ذاكرة البرنامج. فكيف تحفظ كائناً في ملف، أو ترسله من خادم إلى متصفح في الطرف الآخر من العالم؟ تحوّله إلى نص. والصيغة النصية المعتمدة للبيانات على الويب هي JSON (ترميز كائنات JavaScript)، وهي تشبه كائن JavaScript تماماً تقريباً:








    

  • JSON.stringify(value) تحوّل القيمة إلى نص JSON. وJSON.stringify(value, null, 2) تضيف أسطراً جديدة وإزاحات تسهّل القراءة.
    • 

  • JSON.parse(text) تعيد نص JSON كائنات ومصفوفات.
    • 




وJSON أكثر صرامة من JavaScript: المفاتيح بين علامتي تنصيص مزدوجتين، والنصوص كذلك، ولا تعليقات ولا دوال ولا فواصل زائدة في الآخر. ومعظم الواجهات البرمجية في العالم ترسل JSON وتستقبله. وفي الفصل 13 ستجلب JSON من خادم حقيقي.

11.5 مشروع: سلة تسوق



لنبنِ منطق سلة متجر إلكتروني: كتالوج منتجات، وسلة تتذكر أي المنتجات وكم منها، ودوال تضيف العناصر وتحسب المجاميع. وهذا المنطق نفسه الذي يعمل خلف المتاجر الحقيقية، لكنه أصغر:








تفاصيل تستحق الانتباه:


    

  • السلة تحفظ id المنتج والكمية فقط، لا نسخة من المنتج. فالسعر يعيش في مكان واحد هو الكتالوج، وإن تغير سعر صارت كل السلال صحيحة تلقائياً. وقواعد البيانات الحقيقية مصممة على هذه الفكرة بالضبط.
    • 

  • إضافة منتج موجود أصلاً في السلة تزيد كميته بدل إضافة سطر ثانٍ. و+= اختصار لـ line.quantity = line.quantity + quantity.
    • 

  • { productId, quantity } اختصار لـ { productId: productId, quantity: quantity }: حين يتطابق المفتاح واسم المتغير تكتبه مرة واحدة.
    • 

  • السطر الأخير يحوّل السلة إلى JSON، جاهزة للحفظ في المتصفح أو الإرسال إلى خادم، وستفعل ذلك في الفصول القادمة.
    • 




مصفوفات وكائنات ودوال وحلقات وقرارات، كلها تعمل معاً. هذه السلة الصغيرة لها شكل الكود نفسه الذي يعمل داخل أكبر المتاجر على الإنترنت. والخطوة التالية: نضعها في صفحة ويب يضغط فيها الناس!

إعدادات التطبيق محفوظة بصيغة JSON


التطبيقات الحقيقية تبدأ بإعدادات افتراضية، ثم تحمّل ما حفظه المستخدم في المرة الماضية، وتطبّق تغييراً، ثم تحفظ النتيجة من جديد. ابنِ هذه الدورة.


ستتدرب على: JSON.parse، وJSON.stringify بمسافات، ودمج الكائنات بالنشر دون تغيير الأصل.


    

  1. أنشئ defaults فيه theme وfontSize وlanguage.
    2. 

  2. افترض أن التطبيق حفظ هذا النص في المرة الماضية: '{"theme":"dark","fontSize":18}'. ولاحظ أنه بلا language.
    3. 

  3. ادمجهما: { ...defaults, ...JSON.parse(saved) }. الخصائص اللاحقة تغلب، فالقيم المحفوظة تحل محل الافتراضية، والناقصة تبقى على افتراضيتها.

    6.
