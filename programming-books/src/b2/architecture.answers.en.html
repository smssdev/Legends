1. A type-based tree has folders like components/, hooks/ and services/; the feature version has features/cart, features/catalog and so on, each holding its own components, hooks and API calls, plus a small shared/ for truly generic code.
  2. In AccountPage.tsx import CartBadge from "../cart". For Header.tsx, the real fix is a design decision: either the header stops knowing about the cart and receives the badge as a prop or child from app/, or it moves into a feature. Shared code must not reach into a feature at all.
  3. Add if (from.layer === "features" && to.layer === "app") (already covered by “nothing imports from app”, so the test proves it), and if (relative(root, file).startsWith("shared/ui") && relative(root, resolve(dirname(file), target)).startsWith("shared/api")) with its own message.
  4. A good ADR is short: one paragraph of context (the problem and the forces), one of decision (what you chose), and a few lines of consequences, good and bad. Number it and never edit an accepted ADR: write a new one that supersedes it.
  5. In eslint.config.js, for files in src/shared/**, add "no-restricted-imports": ["error", { patterns: ["**/features/**"] }]; for src/features/**, a pattern such as "../*/!(index)" or a group for each other feature’s internal paths. ESLint then reports the same two imports in the editor, as you type.
