Before you begin

How to Use This Book

This book is for developers who can already build a small API and want to build services the way senior backend engineers do: correct under concurrency, safe against attackers, observable in production, fast where it matters, and easy for a team to change. If you finished Code from Zero, the first book of this series, you are ready. If you learned elsewhere, you need to be comfortable with one programming language, the command line, JSON and Git; the book explains HTTP, SQL and everything after them from the beginning.

Two editions, one book

The book exists in two editions, one for Node.js with TypeScript and one for PHP with Laravel, two of the most widely used ways to build web backends. The chapters that do not depend on the language, such as HTTP, SQL, transactions, Redis, observability, performance and Docker, are the same in both, and their examples are shown in both languages side by side where code is needed. The other chapters build the same shop API in the language of your edition, with the same tables, the same endpoints and the same tests. You are reading the Node.js edition.You are reading the Laravel edition. If your team uses the other one, the ideas still apply, word for word: only the syntax changes.

Read the first two parts in order. After that, the chapters can be read in the order your work needs them, though each one assumes the parts before it, and the last chapter uses them all.

Every chapter

Each chapter follows the same pattern, so you always know where you are: what you will learn; explanations built on real, running examples; a quick check in the middle; boxes with professional habits and common traps; a table of common mistakes; a summary; three practice projects (easy, medium and challenge) with steps and hints; and exercises at three levels. Answers to the quick checks follow each summary, and answers to the exercises are at the end of the book.

The projects matter more than anything else in the book. Reading about a skill is not having it. Do at least one project per chapter, preferably the medium one, before moving on.

  • A dark tab above a listing gives the file’s name and path in the project.
  • A box with three coloured dots shows what appeared in the terminal. A line starting with $ is a command; the lines below it are the answer, and lines starting with # are comments that say what the next command is for.
  • Where an output was long, the book shows the lines that matter. Times that change on every run are written as ….

What you need

  • A computer with Windows, macOS or Linux, with at least 8 GB of memory.
  • Node.js 22 or later, Git, curl, jq, and an editor such as Visual Studio Code.
  • PHP 8.5 with Composer (or Laravel Herd, which installs both), Git, curl, jq, and an editor such as Visual Studio Code or PhpStorm.
  • Docker, which runs PostgreSQL and Redis for every chapter without installing them, and the whole system in the last chapters.
  • Every library and tool in the book is free and open source.

The code repository

Every example, every project and every exercise answer is in the book’s code repository, in a folder per chapter, together with the scripts that produced each output. Type the examples yourself first, then use the repository to compare, or to recover when you are stuck.

A word from the author

Most of what goes wrong in a backend goes wrong quietly: an order saved twice, a lock held too long, a token that never expires, an error that nobody logged. None of it shows in a demo, and all of it shows on a busy day. This book is about building services that keep their promises when the network fails, the traffic grows and the code changes, and about the habits that make that normal rather than heroic. Like every book of the series, it is written for each of its two languages rather than translated word for word. I hope it helps you become the engineer that others trust with the systems that matter.
