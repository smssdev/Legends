# Sprint 04: لوحة وتطبيق التاجر

| | |
|---|---|
| **الحالة** | ⏳ قادم |
| **المدة** | 7 أيام عمل |

**الهدف:** التاجر يستقبل الطلب بصوت لا يُفوَّت، يقبله ويجهّزه، ويدير متجره وحده.

| الرمز | المهمة | الملفات |
|---|---|---|
| B1 | API التاجر: طلباته الحية والسابقة، القبول بوقت تحضير، الرفض بسبب، «جاهز» | `routes/merchant.php` |
| B2 | تعديل الطلب قبل القبول: صنف غير متوفر يُحذف أو يُستبدل بموافقة العميل | `OrderAmendment` |
| B3 | إدارة الكتالوج من التاجر (بمراجعة الإدارة اختيارياً)، و«غير متوفر اليوم» | `MerchantCatalog` |
| B4 | حالة المتجر: فتح، إغلاق مؤقت، مشغول (يزيد وقت التحضير) | `StoreStatus` |
| B5 | تقارير التاجر: مبيعاته، الأصناف، التقييمات، نسبة القبول والرفض | `MerchantReports` |
| W1 | لوحة التاجر (ويب، تعمل على تابلت): لوحة الطلبات بأعمدة الحالات | `merchant/` |
| W2 | تنبيه الطلب الجديد: صوت متكرر حتى الرد، وإشعار المتصفح | `merchant/src/alert` |
| W3 | طباعة الطلب (حراري عبر المتصفح، وA4) | `merchant/src/print` |
| W4 | محرر الكتالوج وساعات العمل | `merchant/pages` |
| M1 | تطبيق التاجر (Flutter): الطلبات والتنبيه والقبول والحالة، للمتاجر الصغيرة بلا كمبيوتر | `apps/merchant` |

**تعريف الانتهاء:**
- [ ] طلب جديد يرنّ في اللوحة والتطبيق خلال ثانيتين، ويستمر حتى القبول أو الرفض.
- [ ] الرفض أو انتهاء المهلة يعيد المال للعميل ويبلّغه.
- [ ] موظف المتجر لا يرى كشف الحساب، وصاحبه يراه.
- [ ] تعديل سعر من التاجر لا يمس الطلبات الجارية.
- [ ] التطبيق يرنّ والشاشة مقفلة (إشعار بأولوية عالية).

**كيف يُختبر:** افتح لوحة التاجر على تابلت، واطلب من تطبيق العميل ثلاثة طلبات متتابعة: اقبل واحداً، ارفض واحداً، واترك الثالث حتى المهلة.
