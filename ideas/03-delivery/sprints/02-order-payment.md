# Sprint 02: السلة والطلب والدفع

| | |
|---|---|
| **الحالة** | ⏳ قادم |
| **المدة** | 7 أيام عمل |

**الهدف:** API كامل لدورة الطلب من السلة إلى التسليم، بحالات واضحة ومال مضبوط.

| الرمز | المهمة | الملفات |
|---|---|---|
| B1 | العميل: دخول بالجوال وOTP، وعناوين على الخريطة بتسمية وتفاصيل | `App\Customers` |
| B2 | السلة: من متجر واحد، بخيارات وملاحظات، وتُفحص الأسعار والإتاحة عند كل قراءة | `App\Cart` |
| B3 | التسعير: المجموع، رسوم التوصيل، رسوم الخدمة، الضريبة، الخصم، وعرض مفصّل قبل التأكيد | `Pricing\Quote` |
| B4 | الطلب: آلة حالات (جديد، قبله المتجر، يُحضَّر، جاهز، مع المندوب، سُلِّم، ألغي، رُفض) وسجل أحداث بمن ومتى | `App\Orders\StateMachine` |
| B5 | الدفع: نقدي عند الاستلام، وبطاقة (حجز ثم تحصيل عند القبول)، ومحفظة العميل | `App\Payments` |
| B6 | الإلغاء: قواعد من يلغي ومتى وكم يُرد، والاسترجاع للمحفظة أو البطاقة | `Cancellation` |
| B7 | مهلات تلقائية: متجر لم يرد خلال X دقيقة يُنبَّه ثم يُلغى | `OrderTimeouts` |
| B8 | أحداث حية لكل طرف على قناته الخاصة | `order.{id}`، `store.{id}` |
| B9 | إعادة الطلب، والطلب المجدول لوقت لاحق اليوم | `Reorder` |

**تعريف الانتهاء:**
- [ ] كل انتقال حالة غير مسموح يُرفض (اختبار جدول الانتقالات كاملاً).
- [ ] تأكيد الطلب مرتين بنفس `idempotency_key` ينشئ طلباً واحداً.
- [ ] سعر تغيّر بين السلة والتأكيد يُبلَّغ به العميل ولا يُحصَّل القديم.
- [ ] فشل الدفع لا يترك طلباً معلقاً، والاسترجاع حركة عكسية.
- [ ] العميل لا يرى إلا طلباته، والمتجر طلباته (اختبار على كل مسار).
- [ ] العقد كاملاً في `openapi.yaml` (تعتمد عليه التطبيقات الثلاثة).

**كيف يُختبر:** اختبارات Feature تمشي دورة كاملة: سلة، تأكيد، قبول، تجهيز، استلام، تسليم، ثم دورة إلغاء في كل مرحلة.
