# Sprint 05: المناديب والإسناد والتتبع الحي

| | |
|---|---|
| **الحالة** | ⏳ قادم |
| **المدة** | 8 أيام عمل |

**الهدف:** كل طلب جاهز يجد مندوباً مناسباً وحده، والجميع يرى أين هو.

| الرمز | المهمة | الملفات |
|---|---|---|
| B1 | المندوب: بياناته ومركبته ووثائقه، طلب انضمام ومراجعة، وحالة (متصل، مشغول، غير متصل) | `App\Drivers` |
| B2 | استقبال المواقع: آخر موقع في Redis (فهرس مكاني)، ومسار الطلب في PostgreSQL بتخفيف | `DriverLocation` |
| B3 | الإسناد التلقائي: الأقرب المتاح ضمن نطاق، عرض بمهلة (20 ثانية)، ثم التالي، ثم توسيع النطاق | `App\Dispatch\AutoAssign` |
| B4 | الإسناد اليدوي من لوحة العمليات، وإعادة الإسناد | `ManualAssign` |
| B5 | قواعد قابلة للضبط: حد الطلبات مع المندوب معاً، تجميع طلبين من متجر واحد، أولوية بالتقييم | `config/dispatch.php` |
| B6 | المسافة والوقت المتوقع عبر OSRM مستضاف ذاتياً، مع بديل بالخط المستقيم | `App\Geo\Routing` |
| B7 | بث موقع المندوب للعميل والمتجر والعمليات (للطلب الجاري فقط) | `order.{id}.track` |
| B8 | إثبات التسليم: رمز من العميل أو صورة | `ProofOfDelivery` |
| B9 | أجر المندوب للطلب: ثابت زائد بالمسافة، وحوافز | `DriverFare` |
| W1 | لوحة العمليات: خريطة حية بالمناديب والطلبات، وقائمة «بلا مندوب» بتنبيه | `admin/pages/live` |
| W2 | إدارة المناديب وطلبات انضمامهم ووثائقهم | `admin/pages/drivers` |

**تعريف الانتهاء:**
- [ ] حجز الطلب لمندوب بتحديث شرطي: مندوبان يقبلان معاً، واحد يفوز (اختبار تزامن).
- [ ] مندوب لم يرد في المهلة ينتقل العرض لغيره، وبلا مندوب يُنبَّه موظف العمليات.
- [ ] موقع المندوب لا يصل لأحد خارج طلبه الجاري (اختبار خصوصية).
- [ ] 500 مندوب يرسلون مواقعهم كل 5 ثوانٍ: الخادم مستقر (اختبار حمل).
- [ ] Unit لاختيار المندوب وحساب الأجر (أرقام صحيحة).

**كيف يُختبر:** محاكي مناديب (سكربت يحرّك 30 مندوباً)، وطلبات مولّدة، ومراقبة الخريطة الحية ونسبة الإسناد.
