# Sprint 07: العمولات والمحافظ والتسويات

| | |
|---|---|
| **الحالة** | ⏳ قادم |
| **المدة** | 7 أيام عمل |

**الهدف:** مالك المنصة يعرف بالقرش ما له وما عليه لكل تاجر ومندوب، ويسوّي بضغطة.

| الرمز | المهمة | الملفات |
|---|---|---|
| B1 | دفتر واحد: كل حركة مال قيد مزدوج لا يُعدَّل (عميل، تاجر، مندوب، منصة، بوابة) | `App\Ledger` |
| B2 | توزيع الطلب عند التسليم: قيمة الأصناف للتاجر ناقص العمولة، أجر المندوب، رسوم الخدمة للمنصة، الضريبة | `OrderSplit` |
| B3 | العمولة: نسبة لكل متجر أو نوع، وحد أدنى، وعمولة مختلفة للاستلام | `Commission` |
| B4 | النقد عند الاستلام: يصير ديناً على المندوب، وحد أقصى يوقفه عن الطلبات النقدية حتى يورّد | `CashOnHand` |
| B5 | المحافظ: عميل (استرجاع وشحن)، تاجر، مندوب. الرصيد مجموع القيود | `Wallet` |
| B6 | التسويات: كشف دوري لكل تاجر ومندوب، واعتماد، وتسجيل التحويل، وPDF | `Settlement` |
| B7 | أثر الإلغاء والاسترجاع والتعويض على كل طرف بقواعد واضحة | `RefundSplit` |
| B8 | مطابقة البوابة: مقارنة تحصيلاتها بقيودنا وتقرير الفروق | `GatewayReconcile` |
| W1 | مالية المنصة: الإيراد، المستحقات، النقد عند المناديب | `admin/pages/finance` |
| W2 | شاشة التسويات والاعتماد | `admin/pages/settlements` |
| W3 | كشف حساب التاجر في لوحته والمندوب في تطبيقه | `merchant/`، `apps/driver` |

**تعريف الانتهاء:**
- [ ] مجموع الدفتر صفر دائماً، ورصيد كل محفظة يساوي قيودها (اختبار بعد ألف طلب مولّد بكل الحالات).
- [ ] طلب نقدي وطلب بالبطاقة وطلب بكوبون تتحمله المنصة: كلٌّ يوزَّع صحيحاً (حالات ذهبية).
- [ ] لا float في أي مكان، والتقريب يذهب لطرف محدد مكتوب.
- [ ] تسوية معتمدة لا تُعدَّل، وتصحيحها بقيد جديد.
- [ ] مندوب تجاوز حد النقد لا تصله طلبات نقدية.

**كيف يُختبر:** شغّل يوماً مولّداً (200 طلب)، سوِّ كل الأطراف، وتأكد أن ما بقي للمنصة يساوي عمولاتها ورسومها.
