# Sprint 07: العملاء والتوصيل والفاتورة الإلكترونية

| | |
|---|---|
| **الحالة** | ⏳ قادم |
| **المدة** | 7 أيام عمل (والفاتورة الإلكترونية لبلد واحد) |

**الهدف:** المطعم يعرف زبائنه ويعيدهم، ويدير توصيله، وفاتورته مطابقة لقانون بلده.

| الرمز | المهمة | الملفات |
|---|---|---|
| B1 | العملاء: الجوال والاسم والعناوين، وسجل طلباتهم، والبحث بالجوال في الكاشير | `App\Customers` |
| B2 | الولاء: نقاط بكل مبلغ، واستبدال، وسجل حركات | `Loyalty` |
| B3 | الكوبونات والعروض: نسبة، مبلغ، اشترِ واحصل، بوقت وحد استعمال | `Promotions` |
| B4 | التوصيل الخاص: مناطق برسوم، وسائقو المطعم، وإسناد، وحالة الطلب، وتحصيل السائق وتسويته | `App\Delivery` |
| B5 | صفحة طلب أونلاين للمطعم (توصيل واستلام) بالدفع أونلاين أو عند الاستلام | `OnlineOrderController` |
| B6 | الفاتورة الإلكترونية: واجهة `EInvoiceProvider` ووحدة البلد الأول (السعودية: فاتورة مبسطة بـ QR وربط المرحلة الثانية؛ أو مصر: الإيصال الإلكتروني) | `App\EInvoice` |
| B7 | طابور إرسال للهيئة مع إعادة المحاولة وسجل الحالات | `EInvoiceQueue` |
| W1 | بطاقة العميل في الكاشير ونقاطه | `pos/` |
| W2 | شاشة التوصيل: الطلبات والسائقون والتسوية | `pages/delivery` |
| W3 | صفحة الطلب أونلاين بهوية المطعم | `order/` |
| W4 | إعدادات الفاتورة الإلكترونية وشهاداتها وسجلها | `pages/settings/EInvoice` |

**تعريف الانتهاء:**
- [ ] الفاتورة تُقبل في بيئة اختبار الهيئة للبلد الأول، ومرفوضها يظهر بسببه.
- [ ] انقطاع الهيئة لا يوقف البيع: تُرسل لاحقاً ضمن المهلة القانونية.
- [ ] رصيد نقاط العميل مجموع حركاته، والاستبدال لا يتكرر.
- [ ] تسوية السائق: المحصّل يساوي طلباته النقدية.
- [ ] الطلب أونلاين يدخل الكاشير والمطبخ كأي طلب.

**كيف يُختبر:** اطلب أونلاين بكوبون، أسنده لسائق، سلّمه وسوِّ حسابه، وتحقق من الفاتورة في بيئة الهيئة.

**تنبيه:** متطلبات الهيئات تتغير؛ تُقرأ الوثائق الرسمية الحالية قبل البناء، ولا يُعتمد على هذا الملف.
