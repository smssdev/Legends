# Sprint 03: الطباعة وشاشة المطبخ

| | |
|---|---|
| **الحالة** | ⏳ قادم |
| **المدة** | 6 أيام عمل |

**الهدف:** الفاتورة تخرج للزبون، وتذكرة كل قسم تصل لطابعته أو شاشته، والمطبخ يدير التحضير من الشاشة.

| الرمز | المهمة | الملفات |
|---|---|---|
| B1 | الطابعات: تعريف كل طابعة (شبكة، USB، بلوتوث) وعرض الورق، وربط كل فئة بقسم تحضير وطابعته | `App\Printing` |
| B2 | قوالب الإيصال وتذكرة المطبخ: شعار، بيانات ضريبية، QR، تذييل، يعدّلها المالك | `ReceiptTemplate` |
| B3 | حالات التحضير لكل بند: جديد، يُحضَّر، جاهز، سُلِّم، ووقت كل مرحلة | `KitchenTicket` |
| B4 | بث الطلبات لشاشات المطبخ حسب القسم | قناة `kitchen.{branch}.{station}` |
| P1 | جسر الطباعة: برنامج محلي صغير (Windows وأندرويد) يستقبل من الكاشير ويطبع ESC/POS ويفتح الدرج | `bridge/` |
| P2 | العربية على الحراري: رسم النص صورة نقطية (لا ترميز الطابعة) | `bridge/render` |
| P3 | طباعة مباشرة لطابعات الشبكة من الكاشير حين لا جسر | `pos/src/print` |
| W1 | شاشة المطبخ KDS: بطاقات بالأقدم أولاً، ألوان للتأخير، لمسة للتجهيز، صوت للجديد | `kds/` |
| W2 | شاشة الاستلام للزبائن: أرقام «يُحضَّر» و«جاهز» | `pages/pickup` |
| W3 | إعدادات الطابعات مع «اطبع تجربة» ومحرر القوالب بمعاينة | `pages/settings/Printers` |

**تعريف الانتهاء:**
- [ ] طلب فيه مشروب وطبق: تذكرة البار وتذكرة المطبخ كلٌّ في مكانه.
- [ ] الإيصال العربي مقروء على طابعتين مختلفتين (58mm و80mm).
- [ ] انقطاع طابعة يظهر تنبيهاً ويحفظ المهمة حتى تعود، ولا يوقف البيع.
- [ ] تعديل طلب بعد إرساله يطبع تذكرة «تعديل» أو «إلغاء» للمطبخ.
- [ ] شاشة المطبخ تستعيد حالتها بعد انقطاع الشبكة.

**كيف يُختبر:** بطابعة حقيقية: اطبع 10 طلبات متنوعة، افصل الطابعة في منتصفها ثم أعدها، وجهّز الطلبات من شاشة المطبخ.

**يحتاج:** طابعة حرارية ودرج نقود (قرار الشراء في README).
